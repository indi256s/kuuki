# Kuuki Design System 2.0

Kuuki is a personal flight journal with a restrained editorial character. Typography, whitespace, and the details of stamps, tickets and passports carry the design. It has one illustrative voice, isometric drawings of real objects where only the live part glows (see [Illustration](#illustration)), and one verbal voice, the dry, sarcastic narrator. This document is the single authoritative design reference for the Next experience and supersedes conflicting color, font, glass, grain, and motion guidance elsewhere. The [Redesign 2.0 UX brief](docs/plans/2026-10-04-redesign-2.0-ux-ui.md) explains the experience decisions.

**Status labels.** Unmarked claims describe the current source implementation, not deployment or visual acceptance. The [Overview Release 3 section](#overview-redesign) records the implemented production route and its components. Earlier implementation includes the Redesign 2.0 work from PR #42; its branch, checkout and local verification are recorded in the [auth handoff](docs/plans/2026-10-06-auth-one-form-handoff.md). **Planned (Wn/Tnn)** is documented intent not yet built; Wn/Tnn is the wave and task in the [implementation plan](docs/plans/2026-10-04-redesign-2.0-implementation.md). **Superseded** is older guidance that Redesign 2.0 replaced; the line says by what. **Built (auth redesign)** follows the Paper file [Kuuki — Auth redesign](https://app.paper.design/file/01M48F4SHK61AZS2FH5P5JPRY7) and its spec, [`.scratch/auth-one-form/spec.md`](.scratch/auth-one-form/spec.md). **Proposed** is design work in that file that has not been approved. The same Paper file now also holds Overview (9–10, 13), Journal (11–12), the sign-in fleet (14) and onboarding (15–19) boards; board names marked "(proposed)" carry this label here. **Built on `feat/onboarding-morph`** and **Built on `feat/chapter-cards`** are source on those branches, not yet merged to `main`. **In progress** is uncommitted work in the root checkout; the line names its spec. Where the brief and the code disagree, the code is recorded here and the brief's intent is noted.

## Color and surfaces

Use semantic CSS variables from [`apps/next/src/app/styles.css`](apps/next/src/app/styles.css); do not place palette literals in components. Light is a white sheet: page `#ffffff`, card `#fafafa`, inset `#f2f2f2`, charcoal text (`#302d2a`). Dark steps the other way: page `#2e2e2e`, card `#282828` (darker than the page), inset `#232323`, floating layer `#3d3d3c` (lighter), warm white text (`#f1efeb`). Shu 朱 (vermilion) is the default accent in both themes: light fill `#ec684d` with foreground `#202020`, text and focus `#ae4e3b`, tint `#fff0ec`. Text colors are separate from fills. Muted text must meet 4.5:1 contrast, control borders and focus must meet 3:1; do not fade text with opacity. `apps/next/src/app/tokens.test.ts` parses `styles.css` and covers the accent, data-color and brand pairs listed below; it measures `--control-border` only on the floating sheet, and not hairlines, status or rank text. Hairlines may outline cards; control borders outline inputs and controls. Internal content and page chrome have no divider hairlines: none between rows or figures, under headers, around Next, above the narrator or Hidden sections, on the tab bar, or between sheet headers, bodies and footers. Full card/control outlines, the 2px active-tab and drag indicators, and sheet pager segments remain. The globe’s 1px limb is an explicit exception. No side stripes: a card, row, lane or note never takes a thick coloured edge on one side (`border-inline-start`, `inset Npx 0 0`); status reads from text and an icon, the viewer from the «Вы» badge and the surface fill (`apps/next/src/app/side-stripes.test.ts`). In-flow cards use one subtle boundary and no shadow. Floating surfaces use a solid background and elevation. No glass, backdrop blur, gradient buttons, or decorative grain. No glow on UI: controls, cards, text, badges, focus and status marks stay flat. Glow belongs only to [illustration](#illustration): the built Overview iso figures and the **Proposed** sign-in procession light only their live part in the accent. Nothing interactive glows.

Map fills reuse the accent's heat ramp (`--map-bucket-N` is `--heat-N`) under a titled legend with fixed buckets 1, 2–3, 4–9, 10+. Flag colors may inform stamp ink, never map fill. Claims must have a text and shape cue. Retired accent names map to their successor, any other unknown value to shu, and an accent never overwrites status colors. Accents are set on `<html data-accent>` and stored by name; the picker is `SwatchPicker`. [Accent delivery](#accent-delivery) covers cookie, profile, public pages, favicon and PNG.

Five accents are built. Shu replaced Terracotta as the default on 2026-10-07. A stored `terracotta`, `kincha`, `sumi`, `yellow`, `red` or `orange` maps to `shu`, `blue` to `ai`, `cyan` and `teal` to `asagi`, `purple` and `coral` to `sakura` (`recognizeAccentKey` in the shared palette). `public/bootstrap.js` applies the same table to the cookie, and to the old `kuuki-accent-color` storage value when the cookie holds nothing usable, before paint, rewriting the cookie canonical. Values below match `styles.css`:

The catalog validator (`design-system/validate.mjs`) holds each accent to the status colors: at least 15° of OKLCH hue between the accent fill and every status fill, and status text at CIEDE2000 ≥ 10 from the accent text. Status is never conveyed by color alone; an icon or label accompanies it.

**Implemented (color system v1)**: the roles, scales, slot protocol and delivery below are in source and follow the [spec](.scratch/color-system-audit/spec.md); the shared values come from its [palette proposal](.scratch/color-system-audit/palette-proposal.json). The label records source, not a release.

Each accent has six roles per mode: **fill** (`--accent`: buttons, bars, the route line, swatch dots), **text** (`--accent-text`: links, active nav, "Ku" in the wordmark), **on-tint** (`--accent-on-tint`, same value as text, for labels on the tint), **tint** (`--accent-tint`, a pale wash for tags, the logo tile and unlit glass), **foreground** (`--accent-foreground`, the label on a fill) and **focus** (`--focus`: the fill, except light Shu, whose fill is under 3:1 on the inset and takes the text value; typed fields use neutral `--text` to stay distinct from errors). Hover adds `--accent-hover` (the primary hover fill, at CIEDE2000 ≥ 6 from the fill) and `--accent-hover-foreground` (the label on it). Text is its own value rather than the fill: the fill is the accent's color, the text role is the version tuned to read on every surface. The catalog roles in `styles.css` equal [`design-system/palette.json`](design-system/palette.json) (spec: [`design-system/README.md`](design-system/README.md)) in all ten mode × accent combinations, and `tokens.test.ts` fails on drift. `packages/shared/src/theme/palette.ts` mirrors the same values as plain data for consumers that cannot read CSS (PNG export, favicon, browser bar `theme-color`); `styles.css` stays canonical for the UI, and `tokens.test.ts` fails if the two drift. In OKLCH the warm end is crowded: shu 33°, Sakura 355°, danger fill 11–18°. The validator's 15° rule keeps every accent clear of the status hues, which holds danger inside the 10–18° window.

`tokens.test.ts` resolves all ten mode × accent token sets from `styles.css` and requires:

- **Catalog equality**: every role in `design-system/palette.json` resolves to the same value in `styles.css`.
- **Shared-table equality** for the accent roles, the comparison slots, heat steps and their labels, map buckets and `--mark-1…4`; for `--mark-rest` (the table's `markRest`); and for `--mark-peak`, which must equal `--accent-text` and the table's `markPeak`. Per mode: surfaces, text, makers, regions and neutrals.
- **4.5:1** for text, muted text and accent text on the background, surface and inset; text, muted text, accent text and on-tint on the tint; the foreground on the fill; each heat 1–4 label on its cell; the boarding-pass inks on their paper and the flap label on its flap.
- **3:1** on all three surfaces for the focus ring, the heat contour, comparison slots, makers, regions, `--missing`, the Unknown outline and `--brand-neutral`; `--mark-rest` on the surface; the boarding-pass flap on its paper. `--mark-peak` against `--mark-rest` holds 1.4:1.
- **Floating sheet**, where the chapter cards' marks and controls sit: `--text`, `--mark-rest`, `--mark-peak`, `--accent` and `--control-border` ≥3:1 on `--surface-floating`, and `--skeleton` ≥1.3:1 on `--surface` and `--surface-floating`, in both modes.
- **Heat ramp** monotonic in lightness (darker toward 4 in light, lighter in dark), `--heat-0` equal to `--surface-inset`, and the heat contour identical across accents.
- **Brand adaptation** over the whole airline catalog (see Token roles), the holder inks and the text under the UV shade, and that the non-CSS mirrors (`THEME_COLOR`, `SURFACE_COLOR`, `NEUTRAL_INK`) agree with the tokens.

Heat cells 0–2 against the surface, `--mark-ghost`, the status and rank colors, and `--control-border` on the other surfaces, are not part of it; the boards do not prove contrast either.

### Accent delivery

Precedence, from the first paint: the `kuuki_accent` cookie sets `data-accent` synchronously in `public/bootstrap.js` (no flash). When a signed-in member shell mounts, `AccentSync` reconciles once: an accent picked on the sign-in or activation corner in this tab, if the device still shows it, is saved over the profile; otherwise a recognized `profiles.theme_color` (canonical or retired name) wins and the device adopts it, rewriting a retired name canonical; a missing or unrecognized one receives the device accent, so a local preference is kept. The picker applies on the device at once and, when signed in, saves `theme_color` through `PATCH /api/profiles/me`, which accepts only the five canonical names, or `null` to clear it (anything else is `400 Invalid theme_color`). Profile accent saves are sent one after another, and the last one issued decides the cached accent, so an automatic save that finishes late never overrides a pick. If the save fails, the device returns to the last saved accent and Settings says so; it never claims a public setting that was not saved. Settings states that theme and language apply on this device while the accent also colors the public profile.

**Public profile.** A public `/fly/[username]` page shows its owner's accent (`OwnerAccent`): an inline script sets `data-accent` and `data-accent-scope="owner"` during parse, a layout effect does the same on soft navigation, and leaving the page restores the visitor's cookie accent. The visitor's light or dark mode stays; nothing is written to the cookie or the profile, the shell's `AccentSync` waits until the scope is left, and private profiles, not-found and the leaderboard have no owner scope. The public Overview payload is unchanged: color changes how a public page looks, never what it discloses, and that boundary stays with [ADR 0004](docs/adr/0004-public-record-sharing-boundary.md).

**Favicon.** `FaviconSync` (root layout) watches `data-accent` and `data-theme` and swaps every SVG tab icon link (Next also emits the static `icon.svg` one) for a data URI of the `app/icon.svg` geometry: accent text color on the mode's background. It follows an owner's accent too. File-based `icon.svg` stays the no-JS default (shu), and `favicon.ico`, `apple-icon.png` and the manifest icons (`app/manifest.ts`, `public/icons/`, rendered from `icon.svg` and `public/icons/maskable.svg`) stay static, so an installed OS or PWA icon does not follow the accent. That is a known limitation, not a claim.

**PNG export.** `GET /api/me/overview/share.png?mode=light|dark` draws the card from the shared table for the mode and the owner's saved accent (`profiles.theme_color`, resolved on the server). No request parameter can supply a color. A missing `mode` is `light`, the card's original background; any other value is `400 BAD_REQUEST`. Background, text, bars and chart SVG come from one snapshot, with the Clock's roles: the peak hour takes `markPeak` (the accent text), the others `markRest`, matching the live Clock in both modes, and an hour without flights draws nothing. The embedded chart text has no font in the PNG, as before.

### Data color

Color carries one role at a time, set by what the current view means rather than by its card. Values sit in `styles.css` (mirrored in the shared table) per mode and accent.

- **Accent** colors the interface, decorative SVG and the route line. It is never a data category.
- **Categories** are fixed whatever the accent. Makers: each manufacturer in the aircraft reference and Other are filled (`--cat-maker-*`), drawn as rounded squares. Regions: Africa, Americas, Antarctica, Asia, Europe and Oceania (`--cat-region-*`); a country takes its region's color, and treemap labels sit on a `--surface` plate because no single ink reads on every region fill. Alliances keep their own dated palette.
- **Unknown** is an outline in `--cat-maker-unknown` with a «?» (once the cell is 14px or more), never a fill, so it cannot pass for a maker or region. Makers use it for absent or unrecognized aircraft, regions for a country whose airports name none (shown, not dropped). **Other** is recognized aircraft whose manufacturer has no named slot: a filled neutral, not Unknown.
- **Comparison slots** `--cmp-1…5` compare series inside one analysis. `--kc-chart-1…5` and `--mark-1…4` alias them (no fixed literals), so a chart that sets two series against each other (Routes: flights and new routes; Continents' clock shift by year: forward and backward) is a comparison inside its analysis and follows the accent. Maker charts swap in their category palette.
- **Peak and rest** inside one metric is not a comparison. The peak keeps its emphasis token (`--mark-peak`) and the rest uses `--mark-rest`, an independent neutral (`#8d8c89` in both modes), no longer heat-3. `--mark-peak` is the selected reading and equals `--accent-text` in every mode × accent; the ramps and comparison slots stay at CIEDE2000 ≥ 8 from it (the validator checks this), and `tokens.test.ts` holds it at 1.4:1 against the rest. The peak-vs-rest pair appears in the Clock hours and the Records busiest-year months, and every stage chart below. Comparisons use `--cmp-*`; a single quantity never borrows a second categorical hue.
- **Stage charts** (the columns and rows of the Overview [chapter cards](#chapter-cards)) draw rest marks in `--mark-rest` and the picked reading in the peak token `--mark-peak`, with its value label at 13/18 600 `--text`. The accent colors controls and the figure's live part, never a mark. Hover, focus, pin and applied are contours (see States), and applied adds a ✓ before the label. A known zero is a `--zero` stub (2px on a column, 4px on a row) that reads "—". Aircraft rows keep the category fill in every state, picked or not (`--cat-maker-*`, the Fleet view takes the type's maker), and Unknown stays a 1px outline with «?». A category-coloured chart never uses `--mark-peak`: a stage row renders the peak overlay only when it has no category fill (`charts/stage.test.tsx`), and shows the pick with the selection contour. No opacity on data.
- **Quantity** uses the accent's heat ramp (`--heat-1…4`), always with a numeric legend.
- **Neutrals** have their own tokens even where hexes coincide: `--zero` (known zero), `--missing`, `--cat-maker-other`, `--cat-maker-unknown`, `--mark-ghost` (baseline) and `--brand-neutral`. Code picks the role, never a borrowed neighbour.

**Slot protocol** (`charts/comparison-slots.ts`). A key keeps its slot: stored assignments never move. A new key takes the first slot unused by every stored key, else the first unused by the keys on screen, else the least-used on-screen slot (lowest index on ties). While nothing is stored, the whole-journal (unfiltered) ranking order seeds slots 1…5, so server and first client render agree; stored assignments are read right after mount, so a returning member can see one swap then. Assignments live in `localStorage` under `kuuki:cmp:v1:<ownerId>:<analysis>`, device-local; a new palette version starts a new namespace, and blocked storage falls back to memory for the page. Slots are not hashed from the key. A slot also fixes a dash and a marker, so color is never the only cue: 1 solid line, circle; 2 `6 4`, square; 3 `2 3`, diamond; 4 `10 3 2 3`, triangle; 5 `1 4`, ring. An accent change re-reads `--cmp-N` for the same index. Rankings airport and route bumps use slots; airline series keep their brand color and take only the cues (analysis `airlines-cues`). The **baseline** ("Whole journal") is not a slot: `--mark-ghost`, a thin round-capped `1 6` dotted line, drawn only while a filter is active, and under 3:1 on the inset, which is acceptable for a context stroke.

**Heat scales.** One ramp, three meanings, each with its own legend:

| Scale                  | Levels                              | Reads as                                                                                                                         |
| ---------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Daily Activity         | 0, 1, 2, 3, 4+ completed flights    | Absolute counts, identical in every year and filter                                                                              |
| Monthly grid (Rhythm)  | 0, ≤25%, ≤50%, ≤75%, ≤100%          | Share of the whole-journal busiest month for the selected metric (flights, km or hours); the line above the grid names that base |
| Map and country visits | never (land tone), 1, 2–3, 4–9, 10+ | Visits per country; `--map-bucket-N` is `--heat-N`                                                                               |

A known zero is a filled `--heat-0` cell. **Missing** is a different thing and is never folded into 0: a transparent cell with a dashed `--missing` outline. On the daily grid a day is missing when it has no completed flight and falls outside the span from the journal's first dated, non-upcoming flight to today (or its last dated row, if later); a day with a flight is never missing. On the monthly grid future months, any value the base cannot place, and a month with flights but no distance or duration for the chosen metric are missing (the table says "No data"); a month without flights is a real 0. The legend adds a "No data" entry only when such cells are on screen. Cells in levels 1–3 can sit under 3:1 on the card surface (level 3 does for Matcha and Asagi on the white page), so they and their legend swatches carry a 1px `--heat-contour` (one value per mode, shared by every accent); level 4 clears 3:1 without it. A known zero is the quiet `--heat-0` fill with no contour, so it reads apart from the dashed missing outline and a sparse calendar is not drawn as a grid. Numerals in cells use `--heat-N-text` at 4.5:1. Map fills have no contour: buckets 1–2, and 3 against the light land tone, are under 3:1, and the legend, the "Visits per country" rows and tooltips carry the counts.

**States.** Hover, legend highlight, a pinned touch tooltip and an applied filter never recolor or dim data and never fade neighbours (the former 22% fade is gone). They add a 2px `--text` contour to the mark (lines 3.5px while highlighted or pinned and 3px when filtered; donut separators 4px, capped at the sector's own separator width so a tiny share is never covered); the Aircraft waffle retains category fills, uses a contour on the picked legend swatch, and applies the shared hover, pin and filter contours to its category marks. Chart contours use `--text`, the same value as `--selection-contour`. Keyboard focus is the 2px offset `--focus` ring, and only focus uses `outline`. Hiding a Rankings series is a button with `aria-pressed`, and "Show all" restores it. Visible values, legends, dashes, markers and table rows back every state. On a stage chart the picked reading is the exception that is a fill (`--mark-peak`); hover, pin and applied stay contours there too.

## Type and layout

Self-hosted Commissioner WOFF2 ([`apps/next/public/fonts`](apps/next/public/fonts), weights 400/500/600/700) is the Cyrillic-capable UI and display face; Paper Mono is for ticket codes, flight numbers, times, table dates, and handles. OFL licenses ship beside the font files. Changing and aligned numbers use tabular figures. Displayed durations and distances use plain figures, without approximation prefixes or captions explaining estimates. Missing-data and partial-coverage states retain their labels. Headings wrap with `balance`, paragraphs with `pretty`. Use locale-aware EN/RU dates, numbers, and real plural forms (one/few/many/other in Russian). Russian copy addresses the user as «вы».

## Interaction and states

Use the shared Arc-based primitives for import review and editing. Warnings use text and, where useful, a status icon; do not add colored side rails or tinted wrappers to cards or fields. Airport editors reuse the shared searchable Combobox, including its mobile search sheet.

Language changes apply in place through the device locale subscription (`useLocale` in `client/preferences.tsx`), including page copy, number/date formatting and accessible labels. `setLocale` persists the cookie and updates the document language without reloading or refreshing the route; unfinished forms, filters and open panels retain their state. Server-rendered copy uses live client presentation while private data reads and visibility gates stay on the server.

Navigation stays available while private data streams in. Every data surface distinguishes loading, empty, partial, error, and ready states; route `loading.tsx` files render the [loading screen](#loading-screen). Never present an unavailable read as a confirmed empty journal. Links and controls have visible 2px offset focus rings (`--focus`) and 44px touch targets. `outline` is keyboard focus only: selected, pressed, linked, current and drag-over states draw an inset `box-shadow` (or border) in `--selection-contour`, so focus stays visible on a selected item. Under forced colors the border becomes `Highlight`. Press feedback is 120ms scale to 0.96 except static rows and cards; hover styles apply only to fine pointers. Disabled actions explain why in visible text, not a `title`. Use Keyline icons with text labels; color alone does not signal active state. Capture, authentication, privacy, and destructive copy is calm and direct.

After a route change focus moves to `main h1` (`RouteFocus`); only the pathname (each `/welcome/*` onboarding step is its own path) or the mode key `/passport?view` triggers it, never filters or search text.

System theme is the default for new users. Preserve an explicit light/dark choice, map supported legacy settings, and keep EN/RU and theme consistent with the first usable page (`public/bootstrap.js` sets theme, locale and accent before paint). Client persistence uses same-origin cookies; private app data and authorization are never cached in shared shells.

## Typeface decision

Commissioner replaces Onest at the user's request. The UI and display face is self-hosted as WOFF2 with real upright 400/500/600/700 faces and Latin/Cyrillic coverage. The official static faces include the `tnum` feature that the variable release lacks. Tabular figures are enabled on the body and inherited by data values and form controls; Paper Mono (self-hosted variable WOFF2, 100–800, replacing JetBrains Mono at the user's request) is the ticket-data face. It has no Cyrillic, so Russian text set in it (month names in dates, for example) falls back glyph by glyph to Commissioner, the next face in `--font-mono`, rather than to a system monospace. Unicode-range shards retain the original glyph coverage and share combining marks for decomposed text. Both OFL licenses ship beside the fonts. The earlier [`font specimen`](docs/design/font-specimen.html) and screenshot record the previous Onest selection.

## Illustration

Kuuki's illustration language is the **iso figure**: a 30° isometric line drawing of one real, physical object that stands for a fact. The drawing stays quiet in the `--iso-*` faces and `--iso-line`; only its **live part** is accent and glows. Live paints read `--figure-live-fill` (the accent fill by default); a part that depicts a category takes that category's colour instead (a lit hangar its maker, a fleet plane its maker; an unknown maker stays on the accent), while the puzzle stays on the accent because it shows state, not category. Ink on a live fill is `--figure-live-ink` (default `--accent-foreground`); on hangars it is the background in light and the accent foreground in dark. The painted name is decorative because no single ink reaches 4.5:1 on every maker in light. The glow is a blurred accent copy at `--iso-glow` opacity behind that part, never a shadow, halo or animated gradient on the card. One live part per figure. The fact itself is always HTML text beside the figure (value, label, route), so the figure is `aria-hidden`, takes no pointer input of its own (the one exception is the sign-in Concorde, whose click lights reheat as a toy; see [Motion](#motion)), and never carries information that is not also written. Figures sit inside level 1 cards; the card stays flat.

- Summary figures are three labelled metrics using the adapted Arc SlotText. Count, distance and air time all use matching logged flights; awaiting flights remain in the confirmation action. ## Integrated journeys and evidence

The member import route uses [UnifiedImport](apps/next/src/client/import/unified-import.tsx) and [UnifiedSession](apps/next/src/client/import/unified-session.ts). Choosing, dropping or pasting supported PDF/PNG/JPEG files (10 MB per file) starts reading immediately; the native picker accepts multiple files, the camera (shown for touch input; desktop browsers ignore `capture`) accepts successive photos, and more files append to the current review. Online recognition is disclosed before selection. Local barcodes are read and persisted first; online recognition supplies printed years and all PDF pages, reconciling stored batches while preserving trusted barcode fields without assuming a year. Recognition runs serially to respect the existing one-processing-batch-per-owner admission guard; each source retains its operation ID and owning batches. Only batch IDs, operation IDs, labels, source fingerprints, pending-complement state, system-suppressed copy IDs and selection/recovery metadata are retained in owner-scoped session storage; source bytes and unsent edits stay in memory. Failed files retain retry unless the type or size check failed, where only removal helps; an empty file offers manual entry beside it. Successful rows remain actionable. Primary import entry resumes retained source groups. Empty extraction shows a localized no-flights result with file/manual recovery. Before selection, file and camera actions lead with text paste secondary. After a source is added, a compact Add more menu keeps all source methods available.
