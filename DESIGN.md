# Kuuki Design System 2.0

Kuuki is a personal flight journal with a restrained editorial character. Typography, whitespace, and the details of stamps, tickets and passports carry the design. It has one illustrative voice, isometric drawings of real objects where only the live part glows (see [Illustration](#illustration)), and one verbal voice, the dry, sarcastic narrator. This document is the single authoritative design reference for the Next experience and supersedes conflicting color, font, glass, grain, and motion guidance elsewhere. The [Redesign 2.0 UX brief](docs/plans/2026-10-04-redesign-2.0-ux-ui.md) explains the experience decisions.

**Status labels.** Unmarked claims describe the current source implementation, not deployment or visual acceptance. The [Overview Release 3 section](#overview-redesign) records the implemented production route and its components. Earlier implementation includes the Redesign 2.0 work from PR #42; its branch, checkout and local verification are recorded in the [auth handoff](docs/plans/2026-10-06-auth-one-form-handoff.md). **Planned (Wn/Tnn)** is documented intent not yet built; Wn/Tnn is the wave and task in the [implementation plan](docs/plans/2026-10-04-redesign-2.0-implementation.md). **Superseded** is older guidance that Redesign 2.0 replaced; the line says by what. **Built (auth redesign)** follows the Paper file [Kuuki — Auth redesign](https://app.paper.design/file/01M48F4SHK61AZS2FH5P5JPRY7) and its spec, [`.scratch/auth-one-form/spec.md`](.scratch/auth-one-form/spec.md). **Proposed** is design work in that file that has not been approved. The same Paper file now also holds Overview (9–10, 13), Journal (11–12), the sign-in fleet (14) and onboarding (15–19) boards; board names marked "(proposed)" carry this label here. **Built on `feat/onboarding-morph`** and **Built on `feat/chapter-cards`** are source on those branches, not yet merged to `main`. **In progress** is uncommitted work in the root checkout; the line names its spec. Where the brief and the code disagree, the code is recorded here and the brief's intent is noted.

## Color and surfaces

Use semantic CSS variables from [`apps/next/src/app/styles.css`](apps/next/src/app/styles.css); do not place palette literals in components. Light uses paper (`#fbfaf8`) and charcoal text (`#302d2a`); dark uses ink (`#292827`) and warm white text (`#f1efeb`). Shu 朱 (vermilion) is the default accent in both themes. Text colors are separate from fills. Muted text must meet 4.5:1 contrast, control borders and focus must meet 3:1; do not fade text with opacity. `apps/next/src/app/tokens.test.ts` parses `styles.css` and covers the accent, data-color and brand pairs listed under [Data color](#data-color); it measures `--control-border` only on the floating sheet, and not hairlines, status or rank text. Hairlines may outline cards; control borders outline inputs and controls. Internal content and page chrome have no divider hairlines: none between rows or figures, under headers, around Next, above the narrator or Hidden sections, on the tab bar, or between sheet headers, bodies and footers. Full card/control outlines, the 2px active-tab and drag indicators, and sheet pager segments remain. The globe’s 1px limb is an explicit exception. In-flow cards use one subtle boundary and no shadow. Floating surfaces use a solid background and elevation. No glass, backdrop blur, gradient buttons, or decorative grain. No glow on UI: controls, cards, text, badges, focus and status marks stay flat. Glow belongs only to [illustration](#illustration): the built Overview iso figures and the **Proposed** sign-in procession light only their live part in the accent. Nothing interactive glows.

Map fills reuse the accent's heat ramp (`--map-bucket-N` is `--heat-N`) under a titled legend with fixed buckets 1, 2–3, 4–9, 10+. Flag colors may inform stamp ink, never map fill. Claims must have a text and shape cue. Retired accent names map to their successor, any other unknown value to shu, and an accent never overwrites status colors. Accents are set on `<html data-accent>` and stored by name; the picker is `SwatchPicker`. [Accent delivery](#accent-delivery) covers cookie, profile, public pages, favicon and PNG.

Five accents are built. Shu replaced Terracotta as the default on 2026-10-07. A stored `terracotta`, `kincha`, `sumi`, `yellow`, `red` or `orange` maps to `shu`, `blue` to `ai`, `cyan` and `teal` to `asagi`, `purple` and `coral` to `sakura` (`recognizeAccentKey` in the shared palette). `public/bootstrap.js` applies the same table to the cookie, and to the old `kuuki-accent-color` storage value when the cookie holds nothing usable, before paint, rewriting the cookie canonical. **Implemented (color system v1)**: the roles, scales, slot protocol and delivery below are in source and follow the [spec](.scratch/color-system-audit/spec.md); the shared values come from its [palette proposal](.scratch/color-system-audit/palette-proposal.json). The label records source, not a release.

Each accent has six roles per mode: **fill** (`--accent`: buttons, bars, the route line, swatch dots), **text** (`--accent-text`: links, active nav, "Ku" in the wordmark), **on-tint** (`--accent-on-tint`, same value as text, for labels on the tint), **tint** (`--accent-tint`, a pale wash for tags, the logo tile and unlit glass), **foreground** (`--accent-foreground`, the label on a fill) and **focus** (`--focus`, same value as the fill). Text is its own value rather than the fill: the fill is the accent's color, the text role is the version tuned to read on every surface. `packages/shared/src/theme/palette.ts` holds the values as plain data for consumers that cannot read CSS (PNG export, favicon, browser bar); `styles.css` stays canonical for the UI, and `tokens.test.ts` fails if the two drift. In OKLCH the warm end is crowded: shu 33°, danger 12°, Sakura 355°, about 20° apart each, so there is no room for another warm accent unless danger moves.

`tokens.test.ts` resolves all ten mode × accent token sets from `styles.css` and requires:

- **Equality** with the shared table for the roles above, the comparison slots, heat steps, map buckets, `--mark-1…4` and `--mark-rest` (which must equal `--heat-3` and hold 3:1 on the surface), plus surfaces, makers, regions and neutrals per mode.
- **4.5:1** for text, muted text and accent text on the background, surface and inset; text, muted text, accent text and on-tint on the tint; the foreground on the fill; each heat 1–4 label on its cell.
- **3:1** on all three surfaces for the focus ring, the heat contour, comparison slots, makers, regions, `--missing`, the Unknown outline and `--brand-neutral`.
- **Floating sheet**, where the chapter cards' marks and controls sit: `--mark-rest`, `--mark-peak`, `--accent` and `--control-border` ≥3:1 on `--surface-floating`, and `--skeleton` ≥1.3:1 on `--surface` and `--surface-floating`, in both modes.
- **Heat ramp** monotonic in lightness (darker toward 4 in light, lighter in dark), and `--heat-0` equal to `--surface-inset`.
- **Brand adaptation** over the whole airline catalog (see Token roles), and that the non-CSS mirrors (`THEME_COLOR`, `SURFACE_COLOR`, `NEUTRAL_INK`) and `resolveAccent` agree with the tokens.

Heat cells 0–2 against the surface, `--mark-ghost`, the status and rank colors, and `--control-border` on the other surfaces, are not part of it; the boards do not prove contrast either.

### Accent delivery

Precedence, from the first paint: the `kuuki_accent` cookie sets `data-accent` synchronously in `public/bootstrap.js` (no flash). When a signed-in member shell mounts, `AccentSync` reconciles once: a recognized `profiles.theme_color` (canonical or retired name) wins and the device adopts it, rewriting a retired name canonical; a missing or unrecognized one receives the device accent, so a local preference is kept. The picker applies on the device at once and, when signed in, saves `theme_color` through `PATCH /api/profiles/me`, which accepts only the five canonical names, or `null` to clear it (anything else is `400 Invalid theme_color`). Profile accent saves are sent one after another, and the last one issued decides the cached accent, so an automatic save that finishes late never overrides a pick. If the save fails, the device returns to the last saved accent and Settings says so; it never claims a public setting that was not saved. Settings states that theme and language apply on this device while the accent also colors the public profile.

**Public profile.** A public `/fly/[username]` page shows its owner's accent (`OwnerAccent`): an inline script sets `data-accent` and `data-accent-scope="owner"` during parse, a layout effect does the same on soft navigation, and leaving the page restores the visitor's cookie accent. The visitor's light or dark mode stays; nothing is written to the cookie or the profile, the shell's `AccentSync` waits until the scope is left, and private profiles, not-found and the leaderboard have no owner scope. The public Overview payload is unchanged: color changes how a public page looks, never what it discloses, and that boundary stays with [ADR 0004](docs/adr/0004-public-record-sharing-boundary.md).

**Favicon.** `FaviconSync` (root layout) watches `data-accent` and `data-theme` and swaps every SVG tab icon link (Next also emits the static `icon.svg` one) for a data URI of the `app/icon.svg` geometry: accent text color on the mode's background. It follows an owner's accent too. File-based `icon.svg` stays the no-JS default (shu), and `favicon.ico` and `apple-icon.png` stay static, so an installed OS or PWA icon does not follow the accent. That is a known limitation, not a claim.

**PNG export.** `GET /api/me/overview/share.png?mode=light|dark` draws the card from the shared table for the mode and the owner's saved accent (`profiles.theme_color`, resolved on the server). No request parameter can supply a color. A missing `mode` is `light`, the card's original background; any other value is `400 BAD_REQUEST`. Background, text, bars and chart SVG come from one snapshot, with the Clock's roles: the peak hour takes comparison slot 1, the others `--mark-rest` (heat level 3, as in the live Clock), and an hour without flights draws nothing. The embedded chart text has no font in the PNG, as before.

### Data color

Color carries one role at a time, set by what the current view means rather than by its card. Values sit in `styles.css` (mirrored in the shared table) per mode and accent.

- **Accent** colors the interface, decorative SVG and the route line. It is never a data category.
- **Categories** are fixed whatever the accent. Makers: each manufacturer in the aircraft reference and Other are filled (`--cat-maker-*`), drawn as rounded squares. Regions: Africa, Americas, Antarctica, Asia, Europe and Oceania (`--cat-region-*`); a country takes its region's color, and treemap labels sit on a `--surface` plate because no single ink reads on every region fill. Alliances keep their own dated palette.
- **Unknown** is an outline in `--cat-maker-unknown` with a «?» (once the cell is 14px or more), never a fill, so it cannot pass for a maker or region. Makers use it for absent or unrecognized aircraft, regions for a country whose airports name none (shown, not dropped). **Other** is recognized aircraft whose manufacturer has no named slot: a filled neutral, not Unknown.
- **Comparison slots** `--cmp-1…5` compare series inside one analysis. `--kc-chart-1…5` and `--mark-1…4` alias them (no fixed literals), so a chart that sets two series against each other (Routes: flights and new routes; Continents' clock shift by year: forward and backward) is a comparison inside its analysis and follows the accent. Maker charts swap in their category palette.
- **Peak and rest** inside one metric is not a comparison. The peak keeps its emphasis token (`--mark-peak`) and the rest uses `--mark-rest`, an alias of `--heat-3` on the accent ramp. `--mark-peak` is comparison slot 1 in light; in dark, where slot 1 sits on heat-3's lightness, it is `--heat-4`, and `tokens.test.ts` holds it at 1.4:1 against the rest. The peak-vs-rest pair appears in the Clock hours and the Records busiest-year months, and every stage chart below. Comparisons use `--cmp-*`; a single quantity never borrows a second categorical hue.
- **Stage charts** (the columns and rows of the Overview [chapter cards](#chapter-cards)) draw rest marks in `--mark-rest` and the picked reading in the peak token `--mark-peak`, with its value label at 13/18 600 `--text`. The accent colors controls and the figure's live part, never a mark. Hover, focus, pin and applied are contours (see States), and applied adds a ✓ before the label. A known zero is a `--zero` stub (2px on a column, 4px on a row) that reads "—". Aircraft rows keep the category fill in every state, picked or not (`--cat-maker-*`, the Fleet view takes the type's maker), and Unknown stays a 1px outline with «?». No opacity on data.
- **Quantity** uses the accent's heat ramp (`--heat-1…4`), always with a numeric legend.
- **Neutrals** have their own tokens even where hexes coincide: `--zero` (known zero), `--missing`, `--cat-maker-other`, `--cat-maker-unknown`, `--mark-ghost` (baseline) and `--brand-neutral`. Code picks the role, never a borrowed neighbour.

**Slot protocol** (`charts/comparison-slots.ts`). A key keeps its slot: stored assignments never move. A new key takes the first slot unused by every stored key, else the first unused by the keys on screen, else the least-used on-screen slot (lowest index on ties). While nothing is stored, the whole-journal (unfiltered) ranking order seeds slots 1…5, so server and first client render agree; stored assignments are read right after mount, so a returning member can see one swap then. Assignments live in `localStorage` under `kuuki:cmp:v1:<ownerId>:<analysis>`, device-local; a new palette version starts a new namespace, and blocked storage falls back to memory for the page. Slots are not hashed from the key. A slot also fixes a dash and a marker, so color is never the only cue: 1 solid line, circle; 2 `6 4`, square; 3 `2 3`, diamond; 4 `10 3 2 3`, triangle; 5 `1 4`, ring. An accent change re-reads `--cmp-N` for the same index. Rankings airport and route bumps use slots; airline series keep their brand color and take only the cues (analysis `airlines-cues`). The **baseline** ("Whole journal") is not a slot: `--mark-ghost`, a thin round-capped `1 6` dotted line, drawn only while a filter is active, and under 3:1 on the inset, which is acceptable for a context stroke.

**Heat scales.** One ramp, three meanings, each with its own legend:

| Scale                  | Levels                              | Reads as                                                                                                                         |
| ---------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Daily Activity         | 0, 1, 2, 3, 4+ completed flights    | Absolute counts, identical in every year and filter                                                                              |
| Monthly grid (Rhythm)  | 0, ≤25%, ≤50%, ≤75%, ≤100%          | Share of the whole-journal busiest month for the selected metric (flights, km or hours); the line above the grid names that base |
| Map and country visits | never (land tone), 1, 2–3, 4–9, 10+ | Visits per country; `--map-bucket-N` is `--heat-N`                                                                               |

A known zero is a filled `--heat-0` cell. **Missing** is a different thing and is never folded into 0: a transparent cell with a dashed `--missing` outline. On the daily grid a day is missing when it has no completed flight and falls outside the span from the journal's first dated, non-upcoming flight to today (or its last dated row, if later); a day with a flight is never missing. On the monthly grid future months, any value the base cannot place, and a month with flights but no distance or duration for the chosen metric are missing (the table says "No data"); a month without flights is a real 0. The legend adds a "No data" entry only when such cells are on screen. Cells in levels 1–2 sit under 3:1 on the card surface in every theme and accent, so they and their legend swatches carry a 1px `--heat-contour` (one value per mode, shared by every accent); levels 3–4 clear 3:1 without it. A known zero is the quiet `--heat-0` fill with no contour, so it reads apart from the dashed missing outline and a sparse calendar is not drawn as a grid. Numerals in cells use `--heat-N-text` at 4.5:1. Map fills have no contour: buckets 1–2, and 3 against the light land tone, are under 3:1, and the legend, the "Visits per country" rows and tooltips carry the counts.

**States.** Hover, legend highlight, a pinned touch tooltip and an applied filter never recolor or dim data and never fade neighbours (the former 22% fade is gone). They add a 2px `--text` contour to the mark (lines 3.5px while highlighted or pinned and 3px when filtered; donut separators 4px, capped at the sector's own separator width so a tiny share is never covered); the chart kit's waffle (no Overview chart uses it now) outlines the whole group. Keyboard focus is the 2px offset `--focus` ring. Hiding a Rankings series is a button with `aria-pressed`, and "Show all" restores it. Visible values, legends, dashes, markers and table rows back every state. On a stage chart the picked reading is the exception that is a fill (`--mark-peak`); hover, pin and applied stay contours there too.

## Type and layout

Self-hosted Commissioner WOFF2 ([`apps/next/public/fonts`](apps/next/public/fonts), weights 400/500/600/700) is the Cyrillic-capable UI and display face; Paper Mono is for ticket codes, flight numbers, times, table dates, and handles. OFL licenses ship beside the font files. Changing and aligned numbers use tabular figures. Headings wrap with `balance`, paragraphs with `pretty`. Use locale-aware EN/RU dates, numbers, and real plural forms (one/few/many/other in Russian). Russian copy addresses the user as «вы».

## Interaction and states

Navigation stays available while private data streams in. Every data surface distinguishes loading, empty, partial, error, and ready states; route `loading.tsx` files render the [loading screen](#loading-screen). Never present an unavailable read as a confirmed empty journal. Links and controls have visible 2px offset focus rings (`--focus`) and 44px touch targets. Press feedback is 120ms scale to 0.96 except static rows and cards; hover styles apply only to fine pointers. Disabled actions explain why in visible text, not a `title`. Use Keyline icons with text labels; color alone does not signal active state. Capture, authentication, privacy, and destructive copy is calm and direct.

After a route change focus moves to `main h1` (`RouteFocus`); only the pathname (each `/welcome/*` onboarding step is its own path) or the mode key `/passport?view` triggers it, never filters or search text.

System theme is the default for new users. Preserve an explicit light/dark choice, map supported legacy settings, and keep EN/RU and theme consistent with the first usable page (`public/bootstrap.js` sets theme, locale and accent before paint). Client persistence uses same-origin cookies; private app data and authorization are never cached in shared shells.

## Typeface decision

Commissioner replaces Onest at the user's request. The UI and display face is self-hosted as WOFF2 with real upright 400/500/600/700 faces and Latin/Cyrillic coverage. The official static faces include the `tnum` feature that the variable release lacks. Tabular figures are enabled on the body and inherited by data values and form controls; Paper Mono (self-hosted variable WOFF2, 100–800, replacing JetBrains Mono at the user's request) is the ticket-data face. It has no Cyrillic, so Russian text set in it (month names in dates, for example) falls back glyph by glyph to Commissioner, the next face in `--font-mono`, rather than to a system monospace. Both OFL licenses ship beside the fonts. The earlier [`font specimen`](docs/design/font-specimen.html) and screenshot record the previous Onest selection.

## Illustration

Kuuki's illustration language is the **iso figure**: a 30° isometric line drawing of one real, physical object that stands for a fact. The drawing stays quiet in the `--iso-*` faces and `--iso-line`; only its **live part** is accent and glows. The glow is a blurred accent copy at `--iso-glow` opacity behind that part, never a shadow, halo or animated gradient on the card. One live part per figure. The fact itself is always HTML text beside the figure (value, label, route), so the figure is `aria-hidden`, takes no pointer input of its own, and never carries information that is not also written. Figures sit inside level 1 cards; the card stays flat.

### Welcome flow

**Built on `feat/onboarding-morph`** (boards 15.1–15.10; spec `.scratch/onboarding-morph/spec.md`). - **Dissolve.** The card exits over `--dur-moment` with `--ease-out`: opacity to 0, scale 1.04, blur 6px. Navigation starts half way, so the old page keeps painting until Overview's first paint. Reduced motion keeps only a `--dur-fast` crossfade.

**Break states (boards 16–19).** The break boards drew each step under stress and proposed states for the gaps; the branch builds most of them. Name: empty (Continue disabled with its reason), saving, save failure with Try again, offline (typed text kept, Continue unlocks on reconnect), and an invalid or taken address. Every state keeps the instruction in calm text, per [Copy and trust](#copy-and-trust). Not yet checked against the branch: the upcoming-only ready state (boards 19.4 and 19.10), and the line-break findings for long, Cyrillic and RTL names in the cover (16.1–16.17) and for orphans in narrator headlines (19.2, 19.5, 19.7).

**Pick model.** A click, Enter or a touch tap on a stage mark, or a press of the figure button, selects the reading. The hero and the figure follow it, and a pick never filters. Filtering is explicit. ### Travel patterns and record evidence

A segment or record pick inspects locally. Only an explicit Filter Overview action changes the common scope; Open flight opens the existing flight sheet. Logged flights add one fact, "4th recorded arrival in Tel Aviv", counted chronologically over logged flights in the journal and grouped by the reference city across its airports, so importing older flights can change it. ## Copy and trust

Capture, auth, privacy, settings, errors, validation and destructive flows are calm and direct, with no humor. Wit is allowed only as a secondary line in non-critical empty states, achievements and insights, never replacing the instruction. Russian copy uses «вы»; no «ты» forms. Every string is written in RU and EN together with real plural forms (inline `{en, ru}` pairs or `locale-en` / `locale-ru` spans, plurals through the shared formatter), and must be checked at 320px and 200% text size; this is a design requirement, not a claim of visual verification for Overview Release 3.

"Nothing is stamped without you" is a precise rule, not an absolute promise: the one documented exception (D11) is that an awaiting flight is confirmed automatically seven days after it becomes date-eligible. Say so wherever the promise appears, for example in queue helper text. Never write "never" or "always" about stamping.

## Integrated journeys and evidence

Import's file source uses a selection-only adaptation of [Arc FileDropzone](https://uiarc.dev/components/file-dropzone), with a thumbnail, file size and labelled removal action. Members can choose, drop or paste one PDF/PNG/JPEG document up to 10 MB; clipboard ingestion accepts images through Cmd/Ctrl+V while the file source is active, and ignores text fields and pending recognition. Removal returns focus to the picker; previews remain local and their object URLs are revoked on replacement or unmount. Selection alone never submits a document.

Quick Add decodes a selected boarding pass in a dedicated local worker using self-hosted WASM. Only allowlisted flight fields return to the UI; raw barcode text stays in the worker. Replacing or removing the selection terminates decoding and cancels active PDF loading/rendering. Overview keeps tile previews eager and loads full chapter components when they mount, including adjacent chapters in the mobile sheet, with the chapter card's own loading bands (a static Skeleton per band).

Import aircraft review distinguishes AI claims about operated aircraft from scheduled equipment. Each offered model needs a matching dated flight identity and a source from search metadata; retrieved links are not independent verification. Scheduled proposals start unchecked. Source date, registration and operator are review context; accepting a proposal saves the aircraft type through the existing import flow.

Profile, leaderboard, Settings and entry/onboarding use their scoped modules alongside these primitives. Guests see the one-form auth card; authenticated Capture reuses the normal manual/import save authorities. Reveal reads canonical saved Tickets, preserves fulfilled reads during batch continuation and only presses new published countries. Future-only saves show booked Tickets.

Settings guards owned links, browser history and document exits while edits are unsaved. Current transport and hosting guidance is in the [deploy procedure](docs/skills/deploy-kuuki/SKILL.md); the [candidate runbook](docs/runbooks/2026-10-04-next-release-candidate.md) retains historical release evidence.
