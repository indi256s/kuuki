# Airport models

Run from the workspace root:

- `pnpm airport-models:prepare` writes versioned models, flat plans, previews, provenance, exact asset allowlist and compression/topology report.
- `pnpm airport-models:check` recomputes every output in memory and rejects drift; it performs no writes or network requests.
- `pnpm test:airport-models` checks independent import/metric contracts.

All required inputs are in `sources/`. Builds and preparation need no scratch files or network. Add a source/config pair and include its IATA in prepare.ts to prepare another airport; the viewer requires no airport-specific branch.

The official OSM snapshots were collected for the October 2026 research. Exact retrieval/state timestamps are unavailable, so fetchedAt and osmTimestamp remain null. Element timestamps are preserved and are not interpreted as snapshot timestamps. Config records each original bbox URL, merged snapshot SHA-256, extraction timestamp, explicit OSM airport identity, projection zone and versioned estimate values. The BER original is a merge by type/id selecting the highest element version. `extract.ts <IATA> <snapshot.json>` verifies that hash, selects features intersecting the airport by vertices, recursively includes all node/member dependencies and reports omissions. This is a bounded airport extract, not a global clipping tool. Retain source snapshots independently when refreshing; existing content-addressed outputs cannot be overwritten.

Normalization uses WGS84→UTM metres, a common origin, 0.01 m coordinate rounding and closure tolerance; airports north of the equator below 84° and within 50 km of origin are supported. No geometry simplification is applied. Rings reject open, degenerate and intersecting outlines; courtyard holes retain their owning outer. Building relations support outline/part roles; absent relation outlines are the union of their recorded part footprints. polygon-clipping (MIT, offline dev dependency) subtracts intersecting parts from every overlapping non-part envelope, and subtracts fully contained separately mapped buildings from larger envelopes. One strict total order by area and then stable identity prevents cycles, including near-equal footprints. Parts are subtracted only where their vertical intervals intersect the envelope; elevated roofs cannot erase lower floors. Contained non-part buildings that cover the envelope base replace the complete semantic envelope there; elevated standalone volumes use interval subtraction. Partial overlaps between independent non-part buildings remain unchanged. Explicit part parent IDs remain intact; subtraction only reconciles the physical extrusion remainder. This retains uncovered geometry without terminal envelopes hiding detailed volumes. Control-tower classifications recognize the observed tower:type/control_tower and service/aircraft_control tags. Original polygons remain available for selection; volumeSlices holds optional extrusion polygons with minHeightM/heightM per vertical interval. Preview and Three consume the same buildingVolumes helper; flat plans omit these height slices. Explicit min_height uses metres, not elevation; estimates have their source attached.

Physical runway identity groups connected compatible references, then attaches unlabelled connected threshold segments. Area geometry takes priority only when the complete line is contained; a partially covered line remains visible to avoid inventing coverage. Runway OSM length and geometric length remain distinct. Secondary airport objects are selected by tag; thousands of navigation-aid nodes are intentionally omitted. report.generated.json records every selected object dropped at normalization, vertex/part counts and raw/gzip/Brotli sizes. The original extraction reports separately record raw omissions. Significant malformed buildings, runways and airport boundaries abort preparation.

The canonical revision preimage contains source/config hashes, generator source hash/version, schema, precision/tolerance, projection/origin, estimates, normalized geometry and camera poses. Its revision field is omitted; no generated path enters the preimage. Previews use transparent SVG backgrounds and the neutral light/dark surface roles from apps/next/src/app/styles.css; theme colour changes require an explicit new preparation. Preview and viewer share projectPoint: plan coordinates east/north, world east/height/negative-north; azimuth zero views from south, positive azimuth moves west, angles in radians, verticalSpanM is the full orthographic height.

Geographic data and source extracts are an ODbL derivative database, separately attributed to OpenStreetMap contributors, with licence/source links alongside every model. No personal data is included. The generator and normalizer are independently written; no reference renderer code is imported, executed or extracted.
