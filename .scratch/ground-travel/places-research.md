# Источник городов: исследование

13 октября 2026. Исследование для GT-03/06/13; реализация, загрузка в D1 и
продуктовые правила счётчиков не выполнялись. Геодезическое расстояние для
обоих видов путешествия уже принято; здесь выбирается справочник координат.

## Исходная рекомендация исследования

Взять **GeoNames `cities500` глобально**, дополнить действующими населёнными
пунктами из `GE.zip`, `AM.zip`, `TR.zip`, объединяя по `geonameid`.
Это недорогой автономный каталог без платного геокодера и API во время ввода.
Для Европы и остальных стран базовый порог остаётся: небольшие места ниже
порога и места с неизвестным населением могут отсутствовать. Ручной ввод
без координат должен оставаться доступным. Полноту покрытия не обещаем.

Для дополнений предлагается явный список кодов `PPL`, `PPLA`, `PPLA2`,
`PPLA3`, `PPLA4`, `PPLC`, `PPLG`: населённые пункты и административные центры.
Не импортировать все записи класса P автоматически: туда входят также
исторические/заброшенные места и части населённых пунктов. Понятие «город»
в продукте в таком случае включает выбранный владельцем населённый пункт,
включая маленький посёлок. Это продуктовая политика, а не классификация закона.

## Факты источника и размер

[Описание выгрузок](https://download.geonames.org/export/dump/readme.txt):
`cities500` — население >500 либо административный центр до PPLA4;
`cities1000` — >1000 либо центр до PPLA3. В документации ориентиры
185 тыс. и 130 тыс. записей; это не измеренные текущие количества.
Страновые файлы содержат все типы географических объектов.
Основная строка даёт ID, название, ASCII-название, нетипизированные языком
алиасы, WGS84 координаты, ISO country, admin-коды, население, IANA timezone
и дату изменения. Для языковой маркировки алиасов нужен отдельный файл
alternateNamesV2; кириллица сама по себе не доказывает русский язык.
Лицензия CC BY 4.0; гарантий точности и полноты нет.

[Индекс загрузок](https://download.geonames.org/export/dump/) на дату проверки:
`cities500.zip` 13M, `cities1000.zip` 11M; AM 1.1M, GE 438K, TR 3.4M.
Индекс использует округлённые размеры. `cities500` не скачивали: его размер
превышал установленный для исследования предел около 12 MB.
`cities1000` экономит мало относительно потери небольших мест.
Общий alternateNamesV2 — 195M; allCountries и этот файл не скачивали.

[GeoNames публикует ежедневный экспорт](https://www.geonames.org/about.html).
Предложение: фиксированный снимок при выпуске, затем редкие проверяемые
обновления; хранить дату, SHA-256 и правила фильтрации в manifest. Ежедневная
синхронизация этому журналу не нужна. GeoNames admin-коды не следует
считать ISO subdivision-кодами; отображаемые регионы брать из
admin1CodesASCII/admin2Codes, ключ — country + admin-коды.

## Предлагаемый контракт идентичности и ввода

[GeoNames подтверждает постоянство ID](https://forum.geonames.org/gforum/posts/list/36274.page),
[удалённые ID не используются повторно](https://forum.geonames.org/gforum/posts/list/389.page).
Но объект может исчезнуть из следующих выгрузок. Поэтому хранить
`geonames:<id>` и снимок выбранных названия, страны, региона, координат,
timezone и версии каталога в записи. Обновление справочника не должно
молча менять историческое расстояние, название или идентичность поездки.

Результат поиска показывает название, страну и регион; одинаковые строки
не объединяются по названию. Основное имя/ASCII и все алиасы подходят
для поиска. Для RU/EN отображения — языковые алиасы, подготовленные при
импорте из alternateNamesV2: `ru`/`en` и preferred/short flags, проверенные
overrides по ID, затем имя источника. Не выдавать произвольный кириллический
алиас за RU. Размер сборки с языковыми алиасами и benchmark поиска —
приёмка реализации, а не доказанный результат этой выборки.

Ручное место: название + явно выбранная страна, собственный ID в namespace
`manual`, координаты и timezone необязательны. Повторный выбор уже созданного
места сохраняет его ID; одинаковое введённое название само по себе не
объединяет города. Нет результата, нет координат или ошибка поиска не
блокируют сохранение. Без координат хотя бы одной точки полная оценка
расстояния неизвестна; ноль и сумма только известных отрезков её не заменяют.
Timezone относится к локальным датам и времени, не нужен для расстояния;
отсутствующий пояс нельзя заменять часовым поясом устройства.

## Поиск и существующий код

Рекомендуется ограниченный серверный поиск по отдельному справочнику D1;
глобальный каталог не отправлять в браузер целиком. Индексированные
нормализованные имена/алиасы с ограничением количества результатов,
приоритетом точного совпадения и различимыми странами/регионами.
Выбор B-tree prefix или FTS5 оставить реализации: D1
[поддерживает FTS5](https://developers.cloudflare.com/d1/sql-api/sql-statements/).
Проверить план запросов и rows_read; избегать полного сканирования через
`LIKE '%term%'`. См. [D1 indexes](https://developers.cloudflare.com/d1/best-practices/use-indexes/).
Альтернатива без БД — заранее индексированные статические shards;
полная линейная фильтрация каталога при каждом вводе не рекомендуется.
Бюджет хранения/индекса и задержку поиска проверить на итоговой сборке;
исследование не является нагрузочным тестом.

Локальные источники: `db/seed/airports_reference.sql` содержит 557 аэропортов;
`db/migrations/0001_init.sql` и API `functions/api/reference/airports.ts`
возвращают IATA, имя, строку города, страну и координаты аэропорта без timezone.
`packages/data/src/airports.json` — отдельный источник; тип `Airport` в shared
содержит timezone, но SQL/API этого поля не предоставляют.
Это не идентичность и не координаты города: несколько аэропортов могут
обслуживать один город, маленькие пункты часто не имеют аэропорта.
`packages/shared/src/airportSearch.ts` содержит пять офлайн алиасов аэропортов
и линейный substring-поиск. Можно переиспользовать Unicode folding, но
не IATA-идентичность, набор алиасов и способ поиска большого каталога.

[Публичный Nominatim](https://operations.osmfoundation.org/policies/nominatim/)
не подходит для такого autocomplete: политика явно запрещает клиентское
автодополнение, ограничивает приложение одним запросом в секунду,
требует идентификации и attribution. Самостоятельный сервер/иной провайдер —
другая область работ и здесь не нужен.

## Итог triage

Технический выбор — глобальный GeoNames `cities500` с языковыми RU/EN-алиасами
при импорте. Страновые дополнения остаются возможным улучшением покрытия,
а не обязательной зависимостью первой версии.

Владелец принял ручное название/страну без обязательных координат, уникальные
города роуд-трипа включая старт и сумму времени на поездах без пересадок.
Текущий [контракт](./places-contract.md) определяет идентичность/повторный выбор
и метрики; исходные рекомендации выше не заменяют этот итог. Полная глобальная
сборка и индекс ещё не созданы и не проверены.

Дополнительно проверен [каталог geo-mcp-servers](./geo-mcp-servers-review.md):
он не заменяет выбранный источник; Overture/PlaceRoot оставлен как возможный
кандидат при обнаружении реального пробела покрытия.
