Status: архив обсуждения Q1–Q25. Исторические открытые формулировки ниже заменены финальной спецификацией [spec.md](spec.md). Пользователь принял уточнённую палитру v1 и поручил публикацию спецификации и запуск отдельного треда реализации 2026-10-12.

Основание: [аудит текущего кода](audit.md), [основы и UI](foundations.md), [графики и SVG](charts-svg.md), [проверки](verification.md). Дата первого раунда: 2026-10-12.

## Принятые решения

### Q1. Граница пользовательского акцента

Акцент перекрашивает интерфейс, декоративные SVG-подсветки и количественные шкалы. Производители, альянсы, бренды и статусы сохраняют смысловые цвета. Пользователь выбрал: «Да, разделяем акцент и смысловые цвета».

Следствие: окна Concorde — акцентная подсветка; maker-шторки ULD — идентичность данных. Конкретные новые значения палитр ещё не выбраны; количественные шкалы и состояния уточнены ниже.

### Q2. Палитра по смыслу анализа

Палитра определяется типом текущего анализа внутри карточки: категории, интенсивность или сравнение. Пользователь выбрал: «Да, палитра зависит от анализа».

Aircraft Makers и Fleet могут иметь разные представления данных; Rhythm Calendar и Over time также требуют разных шкал. Решение не предписывает конкретные цвета или типы графиков.

### Q3. Область контракта

Статические изображения и PNG-экспорт входят в общий цветовой контракт. Пользователь выбрал: «Да, включаем экспорт».

Источник акцента для публичного представления и экспорта принят в Q8.

### Q5. Стабильные цвета регионов

Шесть регионов коллекции имеют постоянные смысловые цвета в категорийных сравнениях. Пользователь выбрал: «Да, регионы имеют стабильные цвета». Цвета конкретных регионов ещё не выбраны. Наследование странами принято в Q9; карта посещаемости остаётся количественной шкалой по Q1.

### Q6. Сопоставимость дневной heat-шкалы

Одинаковый оттенок соответствует одному абсолютному диапазону числа перелётов при смене года. Пользователь выбрал: «Да, фиксируем диапазоны между годами». Пороги приняты в Q10.

### Q7. Состояния сохраняют цвет данных

Hover, keyboard focus, закреплённая подсказка и активный фильтр выделяются отдельными признаками с сохранением смыслового цвета данных. Пользователь выбрал: «Да, сохраняем цвет данных». Распределение признаков принято в Q12.

### Q8. Акцент владельца в публичных данных

Публичные визуализации и PNG-экспорт используют акцент владельца журнала. Светлый/тёмный режим живой страницы следует настройке посетителя. Пользователь выбрал: «Да, акцент владельца». Режим PNG принят в Q13, весь публичный контекст — в Q24. Акцент владельца требует профильного источника; существующие канонические предпочтения сохраняются, неизвестные старые значения получают Shu.

### Q4. Цвет производителя в Fleet

Пользователь принял рекомендацию после повторной проверки кода: «Да, принимаем цвет по производителю».

Один семантический цвет на maker, одинаковый у всех его семейств. A320/A350 различаются подписью и строкой, сохраняя цвет Airbus. Индивидуальные оттенки семейства не вводятся: они создали бы дополнительный код без однозначного значения и осложнили бы согласованность Makers/Fleet.

Основание в текущем коде:

- `sections/fleet/section.tsx:75–89`: ridge строится по family key, цвет берётся из `--cat-maker-${row.maker}`.
- `charts/arc-ridgeline.tsx:110–206`: семьи занимают подписанные строки; форма представляет распределение длительности, а цвет — maker.
- `sections/fleet/section.tsx:243–280`: табличная альтернатива и отдельная maker legend уже существуют.

Оговорка для будущего представления: если несколько family traces помещаются на одной оси, различать их прямыми подписями и штрихами линий, сохраняя maker hue. Это рекомендация для такого представления, а не запрос создавать новый график.

Внешний критерий: [W3C Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) требует видимого дополнительного способа различать информацию, переданную цветом. Он не предписывает цвет по производителю; выбор производителя — вывод из структуры текущего Fleet и принятой связи с Makers.

### Q9. Страны в категорийных графиках

Страны наследуют цвет своего региона в категорийных графиках. Пользователь выбрал: «Да, страны наследуют цвет региона». Passport stamp ink остаётся на основе флага, карта посещаемости использует количественную шкалу. Региональный цвет показывает принадлежность; страны внутри региона различаются подписью и положением.

### Q10. Постоянные уровни дневной активности

Приняты пять уровней числа перелётов: 0 / 1 / 2 / 3 / 4+. Пользователь выбрал: «Да, 0 / 1 / 2 / 3 / 4+». Шкала имеет видимую легенду, точное число доступно в подсказке и таблице. Ноль обозначает известное отсутствие перелётов; отсутствие данных требует отдельного состояния.

### Q11. Общая база месячной шкалы

Для перелётов, километров и часов месячная шкала остаётся относительной: доля от максимального месяца всего журнала для соответствующей метрики, с явной легендой. Пользователь выбрал: «Да, относительная шкала с общей базой». База не пересчитывается по выбранному году или фильтру. Это существующая база `baseline.max[metric]`, а не применение дневных порогов к месяцам.

### Q12. Признаки состояний

Hover — усиленный контур; keyboard focus — отдельный focus-ring; закреплённая подсказка — устойчивое выделение; применённый фильтр — check-маркер и выбранный chip. Пользователь выбрал: «Да, разделяем эти состояния». Цвет данных сохраняется. Поведение остальных серий принято в Q18.

### Q13. Режим PNG в момент экспорта

Пользователь изменил рекомендацию фиксированного светлого фона: «Фон следует режиму при экспорте». Изображение фиксирует эффективный светлый/тёмный режим в момент экспорта и акцент владельца по Q8. При настройке system фиксируется разрешённый режим, а не инструкция получателю выбрать фон. Палитры, подписи и фон изображения должны соответствовать одному зафиксированному режиму.

### Q15. Сравнения аэропортов и маршрутов

Используется небольшая сравнительная палитра со стабильным цветом сущности внутри одного анализа. Пользователь выбрал: «Да, цвет закреплён внутри анализа». Пересортировка не меняет цвет. Глобальные цвета каждому аэропорту или маршруту не назначаются. Постоянство при смене фильтра и года принято в Q17.

### Q14. Похожие цвета авиакомпаний

Пользователь принял рекомендацию после анализа: «Да, бренд плюс дополнительные признаки».

Сохранять фирменный оттенок как признак принадлежности, адаптировать светлоту/насыщенность к фону и обеспечивать различимость структурой графика. Не назначать авиакомпаниям вымышленные уникальные цвета только ради различимости.

- Для линий Bump/Slope: различные штрихи и формы маркеров в пределах отображаемого сравнения; подписи/легенда показывают название или код. Назначение признаков привязано к ключу авиакомпании, а не её текущему месту. Для одиночной линии дополнительные признаки не обязательны.
- Для donut: видимые границы секторов, связанная легенда с названием, количеством и долей, доступное выделение сектора. Штрихи линий эту задачу не решают. Разделители не должны скрывать маленькие доли или менять геометрию данных; если сектор меньше читаемого размера, точное значение остаётся в легенде/таблице.
- Неизвестный фирменный цвет остаётся нейтральным с подписью; цвет не угадывается. В каталоге отдельно сохраняется исходное значение, в графике используется его адаптация для конкретного фона.

Основание в текущем коде и каталоге:

- `apps/next/src/lib/airline.ts:14–20` уже сохраняет hue и ограничивает lightness/chroma. Комментарий о 3:1 не заменяет измерение фактического контраста.
- `sections/rankings/section.tsx:58` задаёт пять штрихов, из которых три сплошные; этого недостаточно для пяти совпадающих оттенков. Bump использует одинаковые круглые маркеры.
- `charts/arc-donut.tsx:59` рисует смежные заливки без разделителей; одинаковые цвета могут сливаться.
- В текущем каталоге 321 авиакомпания: 264 с цветом, 57 без цвета; среди заполненных значений 212 различных литералов. Совпадения реальны для каталога, но не доказывают актуальное официальное совпадение брендов. [Исследование источников](../../docs/research/2026-10-09-airline-colors.md) различает подтверждённые наблюдения, legacy_unverified и unknown.

Это принятое направление дизайна на основании текущих графиков. [W3C Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) обосновывает дополнительные признаки; [W3C Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) описывает контраст значимых линий и границ секторов. Ни один источник не предписывает конкретную фирменную палитру Kuuki и не доказывает доступность ещё не созданного решения.

### Q16. Остаток, неизвестность, baseline и отсутствие данных

Пользователь выбрал: «Да, отдельные роли и обозначения». Other — известные категории вне основных слотов; Unknown — неизвестная категория со знаком «?»; baseline — нейтральная линия со штрихом. Известный ноль и отсутствие данных имеют разные обозначения. Other и Unknown остаются разными смысловыми ролями даже при близких нейтральных оттенках. Для площадного baseline нужен подходящий к геометрии дополнительный признак, а не буквальный штрих линии.

### Q17. Постоянство сравнительных цветов

Пользователь выбрал: «Да, сохраняем между годами и фильтрами». Назначение цвета аэропорту/маршруту сохраняется при пересортировке, смене года и фильтра внутри текущего анализа. Новые сущности не перекрашивают ранее назначенные. Поведение после перезагрузки и переполнение принято в Q20.

### Q18. Читаемость остальных серий

Пользователь выбрал: «Да, остальные серии остаются читаемыми». Hover, focus и закрепление подсказки выделяют текущую серию, сохраняя читаемость остальных. Сильное затухание до opacity .22 не является общим правилом. Скрытие других серий допускается только через явную изоляцию в легенде; возврат всех серий должен быть доступен.

### Q19. Favicon следует акценту

Пользователь изменил рекомендацию брендового исключения: «Favicon тоже следует выбранному акценту». Favicon Kuuki входит в акцентный контракт. Это не ограничение согласованного поведения, а часть будущей реализации.

## Дополнение Impeccable: стратегия цвета

По запросу пользователя применён локально установленный [Impeccable](/Users/indi256/.agents/skills/impeccable/SKILL.md); подробные рекомендации прочитаны в [colorize reference](/Users/indi256/.agents/skills/impeccable/reference/colorize.md). Эти ссылки указывают на установленный skill вне репозитория.

Рекомендации для конкретных будущих палитр, ещё не визуально принятые:

- Сохранить спокойные тёплые поверхности Kuuki. Цвет данных объясняет анализ; акцент выделяет действие и декоративную живую часть модели. Не задавать произвольное процентное соотношение цветов.
- Строить значения в OKLCH, а выдавать токены в согласованном с существующим проектом формате. Сохранять узнаваемый hue категории между режимами, отдельно подбирая lightness/chroma; dark не является механической инверсией light.
- Количественная шкала имеет упорядоченную светлоту и явную легенду; категорийная палитра не изображает порядок или интенсивность. У крайних светлых/тёмных ступеней chroma уменьшается по необходимости.
- Разделить роли текста, заливки, текста на заливке, контура и focus. Не использовать один литерал для всех этих задач только потому, что он сегодня похож.
- Проверять реальные пары с учётом фона, opacity и состояний; дополнительные подписи/формы обязательны там, где цвет передаёт различие. Математический контраст сам по себе не доказывает различимость категорий.
- Проверить категорийные сравнения с похожими бренд-цветами и при нарушениях цветового зрения. Глобальный запрет повторять hue несовместим с реальными брендами и шестью регионами; смысл ограничивается объявленной ролью анализа.

Контекст Impeccable загружен один раз для `apps/next/src/app/styles.css`. Изменений web UI не было, поэтому detector и craft-floor для UI-редактирования пока неприменимы.

### Дополнительные факты доставки

- `setAccent` в `apps/next/src/client/appearance.tsx:76–82` записывает только cookie `kuuki_accent`, меняет `data-accent` и вызывает событие; профиль не сохраняет. В API уже есть отдельное `theme_color`: `functions/api/profiles/me.ts:22–45,109–114,134–141`, public DTO `functions/api/_lib/profiles.ts:42–54`. Наличие поля ещё не означает синхронизации текущего picker с профилем. Реализация Q8 требует профильного источника акцента владельца и согласованного fallback для старых значений; remote writes в рамках аудита не выполнялись.
- Значки подключены file-based metadata: `app/favicon.ico`, `app/icon.svg`, `app/apple-icon.png`. SVG выбирает режим по ОС, растровые значки фиксированы. Q19 требует согласовать браузерный favicon с акцентом; возможность обновления обычной вкладки и устанавливаемой иконки приложения — разные поверхности, поддержку нужно проверять отдельно.
- Канонические акценты: `shu, ai, matcha, asagi, sakura`, default Shu. Bootstrap уже содержит legacy mappings; isolated activation расходится по имени default. Будущая миграция должна сохранить существующие распознанные пользовательские предпочтения и использовать Shu при неизвестном значении.
