# Claude web search для обогащения перелётов Kuuki

Status: Исследование документации, 08.10.2026. Конфигурация и экономия
проверены [первым платным baseline](2026-10-08-claude-flight-experiment.md).
Dynamic filtering ещё не измерен платно. Продуктовые правила не меняются.

## Вывод

Предлагаемая последовательность: общий сохранённый результат → известная
датированная страница → узкий поиск недостающего свидетельства → чтение
и фильтрация конкретных строк → сохранение доказательств → разбор полей.
Главная экономия — пропустить ненужный поиск и не передавать полные архивы
модели. Более высокий effort не исправляет отсутствующую строку или
неустановленное происхождение данных.

## Проверенные возможности

- Haiku 5.5 явно поддерживает
  [programmatic tool calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling#compatibility).
  Правило поддержки dynamic filtering на моделях 4.6 и новее применимо
  к нему. Ограничение Haiku 4.5 переносить нельзя.
- [Tool reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-reference#tool-versioning):
  `web_search_20260209` добавляет фильтрацию; `_20260318` — управление
  включением результатов в ответ. Для fetch `_20260209` добавляет фильтрацию,
  `_20260309` — управление кэшем, `_20260318` — включением результатов.
  Для этих версий не нужен beta header.
- [Web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool):
  фильтрация выполняется кодом перед попаданием результатов в контекст.
  Search стоит $0.01 за поиск плюс токены; один поиск может вернуть несколько
  источников. `max_uses` ограничивает поиски, не число источников. Search
  citations включены всегда. Продолжение требует неизменного
  `encrypted_content`. `page_age` описывает страницу, не дату перелёта.
- [Web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool):
  отдельной платы нет, содержание оплачивается токенами. `max_content_tokens`
  приблизителен и не ограничивает PDF. По умолчанию число fetch не ограничено,
  citations выключены, кэш разрешён. JS-страницы не исполняются. URL должен
  ранее появиться во входном сообщении, клиентском результате или результатах
  search/fetch; одного URL в system prompt недостаточно.
- [Server tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools):
  новые web tools автоматически предоставляют code execution. Отдельный tool
  не нужен; `allowed_callers: ["direct"]` отключает фильтрацию. Search допускает
  фильтр по пути, fetch — только по домену. Нельзя одновременно задать
  allowed/blocked; организационные ограничения тоже учитываются.
- [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#feature-compatibility):
  включённые citations несовместимы с `output_config.format` и дают 400.
  Поэтому исследовательский ответ с цитатами и строгий JSON разбирать отдельно.
  Схема гарантирует форму, а не истинность значения или связи с источником.

## Начальная конфигурация эксперимента

Фрагмент Messages request; не исполняемый запрос. Перед вызовом добавить
вход конкретного перелёта, постоянные инструкции и проверенные фильтры доменов
для этой стратегии. Численные лимиты ниже — начальные гипотезы для измерения.

```json
{
  "model": "claude-haiku-5-5",
  "max_tokens": 8192,
  "thinking": { "type": "adaptive" },
  "output_config": { "effort": "xhigh" },
  "tools": [
    {
      "type": "web_search_20260318",
      "name": "web_search",
      "max_uses": 2,
      "response_inclusion": "full"
    },
    {
      "type": "web_fetch_20260318",
      "name": "web_fetch",
      "max_uses": 3,
      "max_content_tokens": 4000,
      "use_cache": true,
      "citations": { "enabled": true },
      "response_inclusion": "full"
    }
  ]
}
```

`allowed_callers` опущен: документированный default включает фильтрацию.
Три чтения оставляют возможность открыть две независимые записи и одну
страницу для уточнения идентичности; это не обещание найти нужные данные.
Для известных URL убрать search из отдельного запроса чтения.

Сначала оставить `response_inclusion: "full"`, чтобы проверить полученные
свидетельства. Позже измерить `excluded`: он удаляет только nested results,
использованные завершившимся code execution, не direct/paused results.
Не исключать результат, если это лишает нас проверяемой строки и происхождения.

## Порядок поиска — проектная рекомендация

1. Проверить общий ключ выполнения рейса и версию стратегии, отдельные
   исходы самолёта и времён. Переиспользовать допустимое свидетельство;
   терминальный неуспех той же стратегии пропустить. Это собственная история
   Kuuki, не кратковременный prompt cache.
2. Если есть разрешённая конкретная ссылка, читать её напрямую. Архивные
   источники прошлого аудита — кандидаты для перепроверки, не допущенная пара.
3. Если ссылки нет или нужна вторая независимая запись, искать номер + дату
   выполнения + направление. Например: `EK132 2020-02-25 DME DXB aircraft`.
   Вариант номера оператора использовать только при установленном кодшере.
   Разрешённые альтернативы запроса входят в версию стратегии заранее.
4. Сузить поиск допущенными доменами/архивными путями. Домены первого и
   второго свидетельства выбирать по происхождению; две страницы одного
   upstream не дают два подтверждения. Порядок источников фиксируется после
   проверки данных и не зависит от порядка выдачи.
5. В фильтрации извлечь точную строку: дата, номер и оператор, направление,
   тип/регистрация, времена с событиями и actual/scheduled, зона/дата прилёта,
   отмена либо выполнение. Не удалять соседние поля, необходимые для
   различения рейсов и перехода через полночь. Остановиться, когда выполнены
   согласованные условия, не продолжать обзор интернета ради полноты.
6. Сохранить доступное свидетельство отдельно от ответа модели: URL,
   источник конкретного поля, цитата/строка, дата получения и связь с выполнением.
   Применить Q12–Q21 из [спецификации](../../.scratch/claude-flight-enrichment/spec.md).
7. Для машинного результата сначала разобрать доступные поля детерминированно
   существующими валидаторами. Если нужен отдельный Claude extraction,
   передавать сохранённые свидетельства без web tools, со строгой схемой и
   проверкой ссылок на исходные строки. Не оплачивать второй поиск.

## Ограничения результата и продолжения

HTTP 200 с ошибкой инструмента, `pause_turn`, `max_tokens`, ошибка
`max_uses_exceeded` или обрезанная страница не являются полноценным отрицательным
поиском. Успешное исполнение всех этапов ограниченной стратегии без находки
может дать терминальный неуспех; само достижение запланированных двух поисков
не требует повторного поиска. Недостаточная независимость — отдельный
терминальный исход для той же стратегии, не «данных нет».
Восстановление `pause_turn` возвращает исходные блоки без изменений;
продолжения ограничивать общим лимитом работы, а не сбрасывать бюджет.
Не повторять неоднозначный timeout автоматически.

Не обещать чтение истории Plane Finder с JS-пагинацией через fetch.
Доступная статическая страница или отдельно допущенный API проверяются
предметно; добавление browser automation не входит в минимальный эксперимент.
Техническое отсутствие строки и отсутствие рейса — разные результаты.

## Кэш, effort и Batch

[Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching):
минимум Haiku 5.5 — 512 токенов. Статические tools/instructions перед
переменным идентификатором; 5 минут по умолчанию, 1 час при необходимости.
Не увеличивать инструкции искусственно ради порога. Между суточными запусками
кэш не живёт; менять effort нужно с учётом инвалидирования messages cache.

При хотя бы одном `cache_control` результаты server tools автоматически
кэшируются перед следующей итерацией на 5 минут, независимо от собственного
TTL. Это отдельная полезная экономия внутри поиска.
[Tool use with prompt caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching).

`xhigh` оставляем исходным вариантом пользователя. По
[effort docs](https://platform.claude.com/docs/en/build-with-claude/effort)
default Haiku 5.5 — `medium`; сравнить его с `xhigh` на одинаковых входах,
если останется бюджет. Не занижать `max_tokens` до усечения и затем считать
исход отрицательным. Измерить качество до выбора рабочего effort.

[Batch](https://platform.claude.com/docs/en/build-with-claude/batch-processing)
даёт 50% скидку на токены, но плата search не уменьшается. Выполнение может
занять до 24 часов, cache hits best effort, параллельная обработка может
превысить workspace spend limit. Для первого $5 эксперимента последовательные
Messages предпочтительны; для ежедневной очереди Batch оценить после замеров.

## Что измеряем

На разных выполнениях отдельно учитывать вызовы search/fetch, input/output
и cache tokens, задержку, прочитанные датированные строки, допущенные независимые
пары, полезные верные поля и ложные совпадения. Считать цену полного результата
со всеми этапами и продолжениями; не только число поисков или видимый текст.

Конфигурация не доказывает жёсткий общий денежный потолок. Происхождение
пары источников и права хранения также не гарантируются наличием citations.
Бесплатные API-проверки подтвердили доступ к Haiku 5.5 и единственному Default
Workspace. Для данного ключа необходим `anthropic-workspace-id`.
[Authentication](https://platform.claude.com/docs/en/manage-claude/authentication).
Count Tokens с указанными search/fetch фактически вернул 8408 входных токенов;
будущие результаты server tools он не предсказывает. Обычный server loop имеет
лимит десять итераций на запрос; консервативный резерв и ограничения первого
прогона описаны в [эксперименте](../../.scratch/claude-flight-enrichment/experiment.md).
Первый платный baseline использует basic/direct search/fetch. В разделах
`response_inclusion` современные docs упоминают output token costs nested
results; связь этой стоимости с `max_tokens` не определена достаточно явно
для исходного денежного резерва. Поэтому dynamic filtering измерять отдельно
после baseline, не считать заранее гарантированной экономией.
Исследованы официальные docs через Context7 и первичные страницы.

В [последующей проверке](2026-10-08-claude-seeded-flight-experiment.md) basic web_fetch успешно прочитал точные архивные ссылки; короткие сохранённые фрагменты разбирались отдельными Messages без web tools. Отключённый thinking устранил усечение JSON на контрольном пакете, однако не устранил ошибки кодшера и классификации времён. Dynamic filtering по-прежнему не измерен платно.
