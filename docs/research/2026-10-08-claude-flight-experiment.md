# Первый платный эксперимент Claude для исторических перелётов

8 октября 2026. Выполнено 8 запросов по 7 кандидатам; один незавершённый
случай сравнили на двух effort. Продовые данные не менялись.

## Результат

Ни одного типа самолёта или времени нельзя автоматически добавить по
согласованным правилам. В прочитанных страницах не установлено нужное
выполнение рейса на нужную дату; двух независимых первичных потоков также нет.
Это результат данной стратегии и выборки, не доказательство отсутствия данных
в архивах. Положительные контрольные сведения из прошлого ручного аудита
не передавались модели и сейчас не считаются заново проверенным эталоном.

Итого: **$0.2283818 по возвращённому usage и опубликованному стандартному
тарифу**, 16 поисков, 18 fetch, из них 10 успешных и 8 ошибок. Input 491628,
output 38438, cache tokens 0. Все ответы сообщают standard/global. Сверка
с итоговым биллингом Console и наличие подписочных кредитов не проверены.
[Тариф Anthropic](https://platform.claude.com/docs/en/about-claude/pricing).

Все отдельные запросы имеют суммарный input ниже 100k: ни одна внутренняя
итерация не могла превысить этот порог, поэтому применяется короткий тариф
$0.10/$0.50 за миллион input/output. Поиск добавляет $0.01 за использование.
Для неизвестного будущего usage резерв до отправки всё ещё использует старшие
тарифы и предельный контекст. Девятый запрос не проходит проверку: оставшиеся
$4.7716182 меньше резерва $4.78. Поэтому максимум 20 кандидатов не достигнут.
Расходовать оставшиеся деньги без принятого резерва этот эксперимент не разрешает.

## Что показала проверка

`xhigh` в обоих запросах исчерпал 8192 до итогового ответа; около 97% output
составил thinking. Aggregate output оказался 11019 и 9582: денежный контроль
не должен считать `max_tokens` пределом всего возвращённого usage server loop.
Незавершённый ответ нельзя сохранять как отрицательный результат поиска.

На одном и том же входе medium завершился за 14.91 секунды вместо 53.77;
его стоимость составила $0.026701 вместо $0.030891. Однако итог тоже не дал
подтверждённых полей. Один такой повтор не доказывает превосходство качества
medium; запросы имеют недетерминированную выдачу. У остальных пяти medium
также есть end_turn, но это не подтверждение найденного выполнения рейса.

Основная проблема — доступ к датированным архивам. Поиск возвращает текущие
расписания, соседние даты или другой маршрут того же номера. Больше thinking
не превращает эти страницы в свидетельство нужного выполнения.

Модель ошиблась в журнале собственных действий: для EK132 medium указала три
чтения при одном фактическом; для B2972 описала два сбоя и неисполненное третье
чтение при трёх фактических ошибках. Учёт расходов, ошибок и повторов должен
строиться по tool result blocks и usage, не по прозе модели.

После первых случаев стратегия v2 добавила обязательную дату в оба запроса,
приоритет поиска исторических записей и запрет конструировать fetch URL.
Это уменьшает известный класс ошибок; три случая v2 не доказали улучшения
покрытия. Ранние результаты не пересчитывались как результаты новой стратегии.

## Источники и времена

Фактические времена у гейта и на полосе действительно доступны: открытая
[страница FlightStats QR858](https://www.flightstats.com/v2/flight-details/QR/858)
за другую дату отдельно содержала actual gate departure/arrival и runway
departure/arrival. Вариант расписания тоже встречается. Времена относятся
к разным событиям; их нельзя смешивать без отдельных меток, переносить между
датами или считать первой/последней ADS-B позицией.

| Источник-кандидат | Наблюдение | Следствие для Kuuki |
|---|---|---|
| Flightera | Старый ручной аудит находил датированные записи; сейчас прочитанный UT787 относится к другому маршруту/дате | Нужен точный архивный путь; доступ и права продуктового использования остаются неподтверждёнными |
| Plane Finder | Получена общая история с другими датами | Нужен конкретный historical record; происхождение полей проверяется отдельно |
| FlightStats | В прочитанной записи есть борт, gate и runway clocks | Проверить историческую глубину, первичный поток и лицензию до допуска |
| Trip.com | Страница явно указывает VariFlight; получен снимок другой даты | VariFlight считается одним upstream, сколько бы сайтов его ни показывали |
| FlightAware | Два открытия не удались | Нельзя считать такой исход успешной проверкой отсутствия архивной записи |
| Flightradar24 / общие timetable sites | Прочитаны другие даты и расписания | Подходят для обнаружения ссылок; не подтверждают наш исторический перелёт |

Источник с неверной датой не является противоречащим свидетельством о нужном
самолёте. Например, Airbus/Boeing разных дней не запускают правило конфликта
производителей для одного выполнения. Сначала проверяется выполнение рейса.

Фиксированный порядок **допущенных** источников пока определить нельзя:
ни одной пары с доказанными разными первичными потоками для наших примеров нет.
Наличие URL, двух сайтов или citations не заменяет это условие.

## Решение после эксперимента

Ежедневный Worker пока не включать. Для следующей версии стратегии сначала
подтвердить доступ к точным датированным архивным страницам, права хранения
и независимость пары. Затем читать точные записи напрямую и проверять
идентичность, события времени и происхождение полей до общего кеша.
При повторном сравнении effort оставить достаточно output для итогового ответа;
текущий xhigh/8192 не завершил даже один из двух запросов.

Политика отрицательных результатов остаётся согласованной: полноценный
завершённый поиск без свидетельств запоминается по данным и версии стратегии;
технический сбой и усечение не превращаются в «не найдено». Проза модели
не определяет этот статус. Результаты этого прогона не записывались в продовую
историю и не объявлялись готовым общим отрицательным кешем.

Месячный бюджет, запуск cron, привязка кредитов и удалённые записи остаются
отдельными решениями. Фактический источник самолёта будущего рейса по-прежнему
не подтверждается заранее.
