## Current service decision evidence

1. **Keep the one-call import and review UI while measuring it.** Google lists `gemini-3.5-flash-lite` as a stable model supporting text, images, PDFs, structured output, and Search grounding ([model card](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)). The installed SDK's `httpOptions.timeout` is milliseconds and its generation config has `responseSchema`/`responseMimeType` ([SDK API](https://googleapis.github.io/js-genai/release_docs/interfaces/types.HttpOptions.html), [generation config](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html)). Google says structured output is syntactic, not semantic validation ([structured output guide](https://ai.google.dev/gemini-api/docs/structured-output)); current post-validation and user review are therefore essential. No real-ticket accuracy, latency distribution, or per-import cost is established in repo evidence. Each parse request makes a provider call ([`parse.ts`](../../functions/api/import/parse.ts#L293)); the source shows no import-result cache or in-flight deduplication, so a user's manual retry may pay again. A privacy-safe short-lived deduplication scheme would need explicit user scope and retention rules; broad shared caching is inappropriate for private tickets. Capture model ID, response `usageMetadata`, provider duration, outcome/timeout, input type and size buckets before choosing a replacement; Google documents token counts in response usage metadata ([token guide](https://ai.google.dev/gemini-api/docs/generate-content/tokens)). Do not log the ticket, PNR, name, or model output. Google's [billing terms](https://ai.google.dev/gemini-api/docs/billing/) distinguish free-tier content use from paid-tier protections; verify the actual project tier before real ticket processing.

2. **Fix the aircraft experience before buying flight feeds.** Inference from current timeouts: a request between 30 and 45 seconds can show failure in the browser while Gemini continues. Align client/provider deadlines and cancellation behavior; measure p50/p95 first. Search-grounded enrichment may issue multiple billable search queries per prompt; Google documents per-query charging for Gemini 3 and supports the selected model ([grounding guide](https://ai.google.dev/gemini-api/docs/google-search), [pricing](https://ai.google.dev/gemini-api/docs/pricing)). Google also labels structured output combined with built-in tools a preview capability ([structured output guide](https://ai.google.dev/gemini-api/docs/structured-output)); test this exact schema/tool combination against the installed SDK and safe synthetic flights. The bigger semantic problem is the prompt's present-day answer for historical trips. Keep the result optional and user-confirmed; consider a historical-data provider only if field-level evidence shows enough demand and a suitable licensed source.

3. **No immediate background jobs or durable ticket storage.** Current import is one synchronous call followed by human review, with no server-stored uploaded ticket and no background state machine. R2 would make sense for ticket storage only if resumable/large uploads or async parsing require temporary durable document storage; its lifecycle rules can delete objects after a defined period ([R2 lifecycle](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)). Cloudflare recommends Queues for decoupled single-step jobs with at-least-once delivery, and Workflows for dependent durable steps whose results survive retries ([Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/), [Workflows guide](https://developers.cloudflare.com/workflows/get-started/guide/)). Neither removes Gemini latency from today's synchronous UX without a new job/status/review flow. Durable Objects serve shared state coordination rather than stateless API calls ([DO guidance](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)); D1 already stores Kuuki's flight and session state. OpenNext's R2/cache-metadata/revalidation resources are a separate framework-cache requirement evaluated in the [architecture audit](../audits/2026-10-04-architecture-and-services.md).

4. **AI Gateway is optional observability, not a proven cache saving.** Cloudflare AI Gateway supports provider usage/cost/error analytics and caching, but cache keys default to an exact full request body match, and caching is disabled by default ([features](https://developers.cloudflare.com/ai-gateway/features/), [caching](https://developers.cloudflare.com/ai-gateway/features/caching/)). Unique personal ticket bodies make hit rates uncertain and caching private results introduces retention review. Logs can include prompt and response and are enabled by default for a new gateway ([logging](https://developers.cloudflare.com/ai-gateway/observability/logging/)); any trial should disable/scrub content logs first. Gateway fallbacks could retry paid calls and produce a different schema unless explicitly bounded. Start with app-level aggregate metrics and Google usage metadata; trial Gateway only if those cannot answer cost/availability questions.

5. **Keep Cloudflare email.** Current REST sender is already integrated and returns a generic response while delivery proceeds. Cloudflare now documents a native `send_email` Workers binding, plus REST, for its Email Service ([Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/), [send guide](https://developers.cloudflare.com/email-service/get-started/send-emails/)). Switching transport may remove a REST hop/token but has no measured UX benefit here; it must preserve recipient acknowledgement, error handling and environment isolation. A new vendor would increase setup and operational surface without evidence of a deliverability problem.

6. **Bundle small public browser assets if the map/font path is slow or unreliable.** The same jsDelivr atlas is used by two map views and prefetch. Shipping a pinned copy with the existing Pages build can reduce an external DNS/TLS and CDN dependency, but compare compressed build size/cache behavior first. Self-hosting the two fonts and tiny noise SVG is similarly a bounded option; unlike backend replacement it changes browser requests only. No claim of a measured speedup is made.

7. **A future Next.js-on-Workers rebuild does not itself justify service replacement.** The Gemini calls, D1 reference/flight data, Cloudflare email, and static airport/airline data can retain their contracts behind Next server routes or actions. Keep private ticket handling on the server, keep import confirmation before any D1 write, and preserve the current explicit production/preview data boundaries. Next's navigation/cache design is a separate frontend/hosting decision; do not assume its cache should hold personal flight responses or ticket output. For the atlas, fonts and decorative SVG, serving pinned static files from the app build remains a small option regardless of framework. Operational equivalence of any proposed Next adapter, bindings, request limits, and deployment pipeline needs a separate current-version proof; this audit makes no compatibility claim.
