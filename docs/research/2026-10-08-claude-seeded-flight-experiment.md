# Claude: проверка точных архивных источников и отдельного извлечения

Проверка 8 октября 2026 года на основе [исследования источников](2026-10-08-flight-sources-deep-research.md). Haiku 5.5, `medium`, последовательные Messages; без подписок поставщиков, записи в Kuuki и изменения billing. Это контрольная выборка с известными URL, не поиск с нуля и не оценка точности относительно фактически выполненных рейсов.

## Результат

Точные ссылки изменили результат: Claude прочитал шесть датированных страниц Flightera и одну страницу истории Plane Finder. Девять чтений инструментом успешны, поисков — ноль. На страницах есть самолёты, регистрации и отображённые часы; нельзя приравнивать эти находки к разрешению автоматически заполнить журнал. Независимость первичного происхождения и права продуктового переиспользования не установлены.

Отдельное извлечение из коротких сохранённых фрагментов, без web tools и с отключённым thinking, завершилось для всех шести кандидатов. Типы, регистрации, локальные часы и даты совпали с полученными фрагментами. Все 36 непустых подтверждающих фрагментов дословные. Это проверка верности извлечения из источника, а не истины самого источника. Семантическая проверка выявила ошибочное сопоставление кодшера и завышенную классификацию фактических/плановых времён; JSON-форма их не предотвращает.

## Ошибки, которые должен закрыть сервис

- При fetch cap 4 000 текст обрывался в истории рейсов до блока кодшеров. Отсутствие LX4590 в таком фрагменте не доказывает отсутствие связи на всей странице. Cap 10 000 позволил прочитать блок; полнота всей страницы этим тоже не гарантируется.
- В длинном ответе Claude видит датированное «operated by TP933 / tickets also sold as LX4590», но ошибочно считает, что для маркетингового номера нужен другой физический рейс. В JSON после явного правила он извлекает оба номера, однако всё равно выдумывает конфликт TAP/TP933. Сопоставление требует собственной проверки операторского и маркетингового номеров.
- В JSON **18 из 23 показанных часов** получили `status_basis=explicit`, хотя supplied-фрагменты не содержат буквальной метки actual/scheduled для этих часов. Остальные пять классифицированы как inferred; один отсутствующий плановый arrival QR858 оставлен null. Наличие Landed не превращает метку часов в явно указанную actual. Все 24 слота правильно сохранили `event_kind=unknown`.
- В схеме v2 нет отдельных UTC-полей. Локальные даты верны, но явно показанный UTC-вылет QR858 предыдущим днём не перенесён в машинный результат. Дата/зона и исходный фрагмент сохранены; будущий контракт должен сохранять обе формы или детерминированно нормализовать их с учётом зоны.
- Adaptive JSON-разбор не завершился даже с `medium`. Отключение thinking устранило усечение на этой выборке, но не семантические ошибки. [Документация Haiku 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-haiku-5-5) разрешает disabled при low/medium/high. Сравнение выполнено на одном повторном пакете; это не общий вывод о качестве режимов.

Расширенный вариант схемы v3 с UTC-полями и literal_status_label был отклонён HTTP 400 и не дал результатов; точная причина не установлена. Исходный runner не сохранил body этой ошибки — исправлено, будущие HTTP-ошибки сохраняются перед остановкой. Схемы v3 не считать прошедшими API-проверку. [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) ограничивают сложность схем и гарантируют форму, а не достоверность данных.

## Отдельная загрузка вместо web tools Haiku

Предпочтительная следующая архитектура: общий разрешённый кэш → самостоятельный загрузчик конкретного источника → выбор точной датированной строки и нужных секций → обычный Claude Messages без tools для неструктурированного фрагмента → проверка кодом → заполнение только пустых полей. Уже структурированную API-запись разумно разбирать без LLM. Поиск ссылок нужен только при отсутствии подходящего URL и является отдельной ограниченной операцией; поиск и загрузка — разные задачи.

Извлечение проверено на настоящих сохранённых результатах web_fetch, а не на пересказе исследования: 8 872 символа неизменённых секций шести документов, с хешами и диапазонами исходного текста. Стоимость двух разборов — **$0.0035075 за шесть кандидатов**, включая ошибочные семантические метки. Это стоимость extraction, не полной загрузки/поиска и не допустимого автозаполнения. У [web_fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool) нет отдельной платы: экономия внешнего загрузчика возникает за счёт короткого контекста и отсутствия повторного server loop. Токены текста и ответа всё равно оплачиваются.

Работоспособность внешнего загрузчика ещё не доказана. Обычный отдельный HTTP-запрос к точной странице EK132 получил 403; T3 browser snapshot/evaluate неоднократно истекали по timeout. Обход защиты не выполнялся. Нельзя переносить успех Anthropic web_fetch на Cloudflare Worker: нужно отдельно проверить разрешённый статический/API-доступ и стоимость выбранного загрузчика. Подписочные Claude API credits не оплачивают стороннего поставщика или браузерный сервис.

Ни найденные страницы, ни корректный JSON не разрешают фоновую запись: допустимых независимых пар — ноль; временные события неизвестны. Согласованные правила отрицательного кэша не менялись, неоднозначные/обрезанные результаты в production не сохранялись.

## Проверка и артефакты

Независимый review подтвердил пересчёт расходов, 9 fetch / 0 search, совпадение хешей и всех диапазонов шести пакетов с оригинальными tool results, 68 диапазонов API citations и сохранение пакетов в extraction-запросах. Проверены 42 поля коротких подтверждений: 36 непустых совпадают дословно и укладываются в 120 символов. Семантические ошибки выше сохранены как отрицательные результаты проверки, а не исправлены задним числом.

Сохраняются [пакеты исходных фрагментов](../../.scratch/claude-flight-enrichment/followup-source-packets.json), [машинные ответы и проверка цитат](../../.scratch/claude-flight-enrichment/followup-extraction-results.json), компактные результаты и общий ledger. Восемь полных response-файлов удалены после независимого review; общая база сервиса и связи с пользователями не создавались. API поставщиков, месячный production-бюджет, происхождение каждого поля и права общего переиспользования не проверены этим экспериментом.
