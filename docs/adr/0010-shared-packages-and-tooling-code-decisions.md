# ADR 0010: Shared packages and tooling code decisions

- **Status:** Accepted, 21 November 2026.
- **Source:** decisions that lived as code comments until the comment ban (`scripts/comments.mjs`); each entry names the symbol it governs.

## Context

Code comments are banned, so a decision that the code cannot express (a limit, a source choice, a boundary kept for privacy or safety, a workaround for a tool bug) has to live somewhere else. This ADR collects those decisions for `packages/` (shared, data, client) and `scripts/`. Decisions already recorded in ADRs 0001 to 0008 are linked, not restated.

## Decision

### Client API and local receipts

- **`apiClient`** ([packages/client/src/apiClient.ts](../../packages/client/src/apiClient.ts)) — requests are same-origin with `credentials: 'include'`; state-changing requests echo the readable `kuuki_csrf` cookie in `X-CSRF-Token` (double submit, see `functions/api/_lib/auth.ts`). On a 401 the client tries one shared session refresh and retries the original request once; if refresh fails it calls the registered unauthorized handler and surfaces the error, so there is no loop. `/api/auth/` paths are exempt because their 401s (bad password, expired refresh) are meaningful and must propagate. After taking the refresh lock the request re-checks the identity generation and CSRF cookie, because a peer tab may release its lock before this tab receives the identity broadcast.
- **`refreshInFlight`** ([packages/client/src/apiClient.ts](../../packages/client/src/apiClient.ts)) — cleared only while it is still the same promise, so a previous identity's refresh cannot clear a newer identity's in-flight refresh.
- **`generateCSV`** ([packages/client/src/export.ts](../../packages/client/src/export.ts)) — prepends a UTF-8 BOM so Excel detects the encoding of non-ASCII airport and country names.
- **`flightCreateOperations`** ([packages/client/src/flightCreateOperations.ts](../../packages/client/src/flightCreateOperations.ts)) — `localStorage` is the source of truth for create receipts. The tab's in-memory copy answers only when storage is unreadable or an entry is damaged: a missing entry means another tab settled or abandoned the receipt, and replaying it would double-create.
- **`getFlightCreateOperation`** ([packages/client/src/flightCreateOperations.ts](../../packages/client/src/flightCreateOperations.ts)) — keeps the payload and idempotency key together; an explicit retry reuses its captured key and never mints a new one, which would duplicate the flight.
- **`pendingFlightCreateOperations`** ([packages/client/src/flightCreateOperations.ts](../../packages/client/src/flightCreateOperations.ts)) — lists every stored create receipt of the user whatever wrote it and whatever shape its operation id has (plain UUID, run and row number, prefixed id), so an unresolved save is found again after a reload. A damaged receipt is listed as expired with an empty body and no key.
- **`currentFlightOperationId`** ([packages/client/src/flightCreateOperations.ts](../../packages/client/src/flightCreateOperations.ts)) — lives in `sessionStorage`, which survives a refresh while independent tabs keep separate manual attempts.

### Reference data

- **`AIRCRAFT_MAKERS`** ([packages/data/src/aircraft-makers.ts](../../packages/data/src/aircraft-makers.ts)) — maps `BCS1` and `BCS3` to Airbus: the A220 is the current type designation and supersedes the reference's Bombardier label. Overview folds no "Other" families, so every manufacturer in the aircraft reference needs its own slot and colour; `aircraft-makers.test.ts` fails when one is missing.
- **`airport-lookup`** ([packages/data/src/airport-lookup.ts](../../packages/data/src/airport-lookup.ts)) — a separate subpath, imported only by workflows that need the full offline airport corpus, so other bundles do not pay for it.
- **`COUNTRY_NEIGHBORS`** ([packages/data/src/country-neighbors.ts](../../packages/data/src/country-neighbors.ts)) — built from Natural Earth 1:110m Admin 0 countries (public domain, [terms](https://www.naturalearthdata.com/about/terms-of-use/)) as packaged in [world-atlas 2.0.2](https://github.com/topojson/world-atlas/tree/v2.0.2) (ISC) and pinned in `apps/next/public/maps/countries-110m-2.0.2-r2.geojson` (see `docs/research/2026-10-04-map-implementation.md`). Two catalog countries are neighbours when their low-detail outlines share a land boundary edge. A code has no entry when the atlas has no outline for it (microstates, many small islands and territories, Kosovo) or its outline shares no land edge at this resolution (Australia, Iceland, Japan); suggestions then fall back to recent countries and search always covers the whole catalog. Used only for "add a country" suggestions, never as evidence.
- **`build-country-neighbors`** ([scripts/build-country-neighbors.mjs](../../scripts/build-country-neighbors.mjs)) — relies on world-atlas being TopoJSON, where neighbouring countries share identical arcs, so decoded countries share identical consecutive vertices. Two countries are neighbours when at least one boundary edge (two consecutive vertices) is shared; a single shared point (a tripoint touch) is not enough. Only catalog codes are kept.
- **`airportAliases`** ([packages/shared/src/airportSearch.ts](../../packages/shared/src/airportSearch.ts)) — five aliases curated offline because the catalog has English names only. Russian names come from Russian Wikipedia airport articles «Шереметьево», «Домодедово», «Внуково», «Тбилиси (аэропорт)», «Стамбул (аэропорт)»; native names from Tbilisi Airport (tbilisiairport.com) and İstanbul Airport (istairport.com).
- **`resolveAirportCodes`** ([packages/shared/src/airportSearch.ts](../../packages/shared/src/airportSearch.ts)) — a word shorter than two characters resolves to nothing: it would match most of the catalog and the plain text match already covers it. Default limit is 400.
- **`decodeAirportScope`** ([packages/shared/src/airportHistory.ts](../../packages/shared/src/airportHistory.ts)) — re-encodes the parsed filter and rejects a mismatch, so alternate encodings and malformed base64 trailing bits are not accepted as the same scope.

### Dates, calendar and time zones

- **`calendar.ts`** ([packages/shared/src/calendar.ts](../../packages/shared/src/calendar.ts)) — a flight `date` is a `YYYY-MM-DD` label, never an instant: it is never passed to `new Date(date)` for presentation and days are added as labels, not 24-hour spans (ADR 0001 §1, calendar rule).
- **`startOfLocalDay`** ([packages/shared/src/calendar.ts](../../packages/shared/src/calendar.ts)) — in a DST gap returns the first existing instant after local midnight; when midnight occurs twice, the earlier instant.
- **`calendarDay`** ([packages/shared/src/overview/next.ts](../../packages/shared/src/overview/next.ts)) — validates through an ISO round-trip so normalized invalid dates are rejected and years 0000 to 0099 are preserved.
- **`dayToEpoch`** ([packages/shared/src/overview/range.ts](../../packages/shared/src/overview/range.ts)) — uses UTC and `setUTCFullYear` because `Date.UTC` maps years 0 to 99 to 1900 and later.
- **`todayIso`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — computes today in the browser's zone with a UTC fallback; the server uses the value the client supplies, so grouping matches what the owner sees.

### Flighty parsing and import

ADR 0008 owns the importer design (parse and map rules, run and row tables, limits). Entries below add only the reasons that lived in code.

- **`flighty.ts` layers** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — see [ADR 0008](0008-flighty-history-import.md). Parsing interprets no value; structural damage (bad quoting, uneven rows, duplicate or missing headers, size limits) rejects the whole file with a location and no cell content; every record keeps every cell, including unknown columns. Mapping turns anything it cannot establish into an issue, grouped when the same source token recurs, never a guess. Both layers are pure and shared by browser, API and offline evaluator. The profile name describes headers observed in independent parsers, not a format Flighty has published.
- **`FLIGHTY_MAPPER_VERSION`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — bumped when parsing or mapping rules change and stored with each import, so old runs stay explainable.
- **`FLIGHTY_MAX_RECORD_BYTES`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — one record's serialized cells; a longer record rejects the file instead of cutting its notes.
- **`FLIGHTY_MAX_TOKEN_LENGTH`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — 64, the longest source token an issue repeats, because staged issues are capped at 8192 characters by migration 0020.
- **`FLIGHTY_MAX_CHUNKS`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — 200: 10 000 records with long notes split by bytes into more chunks than the 100 a record count needs.
- **`FLIGHTY_CHUNK_PAYLOAD_BYTES`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — 240 KiB, leaving room under the 256 KiB request cap for the body wrapper; one record never exceeds it because `FLIGHTY_MAX_RECORD_BYTES` is smaller. Ordinals stay global so a chunk can be checked alone.
- **`flightyChunkPayload`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — the canonical chunk serialization; the server recomputes it over what it received to verify the digest.
- **BOM stripping in `parseFlightyCsv`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — one UTF-8 BOM at the very start only; a BOM elsewhere is content.
- **`FLIGHTY_COLUMN_ROLES`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — every cell of an accepted record is preserved as written; only `canonical` and `clock` columns are also interpreted into journal fields, `reference` columns are opaque Flighty IDs and `private` columns are owner-only. Unknown columns are preserved and never interpreted.
- **`FlightyParseError`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — its location names lines, records and header names, never cell content, so private data does not leak into errors.
- **`FlightyRefs`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — catalog lookups are supplied by the caller, keeping the mapper independent of `packages/data` and D1.
- **`FlightyIssue` grouping** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — rows sharing a group key share one question and take one answer (`answers.groups[group]`): unknown airline code, unknown airport code, unreadable cancellation token; null for a question about one record. `candidates` are catalog values the owner can pick from and are never pre-selected.
- **`groupKey`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — groups only short tokens (32 characters or fewer); a long free-text value stays a question about its own row.
- **`boundToken`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — cuts an overlong token to `FLIGHTY_MAX_TOKEN_LENGTH` with "…" only after grouping, so a grouped token (at most 32 characters) never changes. Short tokens are not split because a string's UTF-16 length never undercounts its code points.
- **`FLIGHTY_MAX_DURATION_MINUTES`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — the [ADR 0002](0002-flight-metrics-provenance.md) clamp on a duration stored as measured; a longer exact value needs an owner decision.
- **Cancellation mapping in `mapFlightyRecord`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — a cancellation gets action `preserve_only`: kept with the owner's records, never a flight, and no other question blocks it. The identity hints (`flightyFlightId`, `matchKey`) are not a proven stable ID ([ADR 0008](0008-flighty-history-import.md)).
- **Field mapping in `mapFlightyRecord`** ([packages/shared/src/flighty.ts](../../packages/shared/src/flighty.ts)) — a flight-number designator prefix is removed only when it repeats this row's own airline. Only an unambiguous catalog aircraft name becomes a type code; the name stays in the source. Each time event keeps its own phase and airport and none substitutes for another. Clock times come from one consistent gate pair, actual first then scheduled; runway events stay source-only.
- **`resolveLocalTimestamp`** ([packages/shared/src/flighty-time.ts](../../packages/shared/src/flighty-time.ts)) — the export writes `YYYY-MM-DDTHH:MM` with no offset (`docs/research/2026-11-10-flighty-csv-format-research.md`), so a wall-clock time names zero (DST gap), one or two (DST fold) instants in the airport's historical IANA zone. The resolver reports which and never picks an offset for the caller. A naive time is tried against every offset the zone used within two days; each candidate instant must map back to the same wall clock. Explicit offsets are checked, not trusted.
- **`HistoryFindingKind` `previous_deleted`** ([packages/shared/src/flightyHistory.ts](../../packages/shared/src/flightyHistory.ts)) — an identical or same-ID record whose flight the owner deleted is never re-created silently.
- **`HistoryFindingKind` `new_since_import`** ([packages/shared/src/flightyHistory.ts](../../packages/shared/src/flightyHistory.ts)) — a record unmatched while an earlier Flighty import exists is added only on an explicit owner decision.
- **`HistoryRowAnswers`** ([packages/shared/src/flightyHistory.ts](../../packages/shared/src/flightyHistory.ts)) — row-level answers only; group answers are set through `POST /api/import/history` groups, so a shared decision is never overwritten by a row write.
- **`HistoryRow.fields`** ([packages/shared/src/flightyHistory.ts](../../packages/shared/src/flightyHistory.ts)) — non-empty source cells by header, owner-only, null once the run's rows are erased.
- **`evaluate-flighty`** ([scripts/evaluate-flighty.ts](../../scripts/evaluate-flighty.ts)) — uses local files only (no model, no network, no D1); its report and console carry counts, categories, ordinals and header names, never cell values, so it is safe on a private export. The labels are the ground truth and the mapper under test never writes them. `--synthetic N` generates N records with the labels implied by how they were generated, to check scale and how many owner decisions a large clean history needs.

### Flights, passport and ground travel

- **`passport_visit_id`** ([packages/shared/src/flightValidation.ts](../../packages/shared/src/flightValidation.ts)) — the manual Passport air visit this create enriches; never editable on an existing flight.
- **`AVATAR_FACES`** ([packages/shared/src/avatar.ts](../../packages/shared/src/avatar.ts)) — in Facehash's FACES order (round, cross, line, curved). A null choice derives a face from the member id, so a rename never changes it.
- **`OwnFlight`** ([packages/shared/src/types.ts](../../packages/shared/src/types.ts)) — the own-flight API projection; ownership and D1-only bookkeeping columns stay on the server.
- **`EntryMethod`** ([packages/shared/src/types.ts](../../packages/shared/src/types.ts)) — applies to manual visits; an `air` entry is evidence and does not create a flight.
- **`GroundVisitMode`** ([packages/shared/src/types.ts](../../packages/shared/src/types.ts)) — set only for a land visit (`rail` or `road`); sea and air visits carry null.
- **Ground journeys** — boundaries are in [ADR 0005](0005-ground-travel-journey-boundaries.md). Code-level reasons follow.
- **`GROUND_LIMITS`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — `receiptDays` counts from the first successful commit and replays never extend it (37 days). `searchMinChars` is 3 because catalog prefix buckets hold three folded characters, so a shorter query has no bucket to read.
- **`GroundPlaceSnapshot`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — stores identity plus the names and coordinates chosen at selection, never rewritten later, so journeys stay stable when the catalog changes.
- **`placeLabel`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — language name first, then the source name; an ASCII transliteration is deliberately not treated as a translation.
- **Place text limits and `parsePlaceSnapshot`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — lengths count code points, not UTF-16 units, because SQLite `length()` counts characters. `parsePlaceSnapshot` validates structure only; ownership of manual place ids is checked by the server against its own rows.
- **`RailLegInput` and journey dates** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — `durationMinutes` is owner-entered minutes only; null lets the server derive a schedule duration when it can, keeping the two sources distinguishable. The start date decides year attribution; an unknown date stays null, never guessed.
- **`GroundCommand`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — create is `POST /api/ground-journeys`; everything else is `PATCH|DELETE /api/ground-journeys/:id`. `countries` is the complete owner-confirmed list, required (possibly empty) whenever the result is completed (create as completed, complete, update of a completed journey) and forbidden otherwise.
- **`GroundMutationResult`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — `savedVersion` is what the operation committed; `current` is the journey now (null when deleted or gone), so a replay never presents current content as the original snapshot. `accountRevision` is the revision recorded at commit; derived publication is sufficient once `published_revision >= accountRevision`.
- **`GroundOperationStatus` `unknown`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — `GET /api/ground-journeys/operations/:key` answers `unknown` for any missing receipt (never written, other owner, expired), so receipt existence does not leak across owners.
- **`RailLegDto.durationMinutes`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — the stored effective duration; an editor sends it back only when `durationSource` is `'manual'`, because echoing a `'schedule'` value would turn it into a manual one.
- **`JourneyMetrics.distanceKm`, `segmentKm`, `journeyDistance`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — a straight-line sum between consecutive cities, null unless every segment has coordinates. `segmentKm` returns null, never 0, for an end without coordinates; `journeyDistance` rounds once at the end and one unknown endpoint makes the whole distance unknown.
- **`journeyYear`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — uses the known start date only, so a New Year trip counts once, in its start year.
- **`modeTotals`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — completed journeys only; plans, cancelled journeys and local drafts never count.
- **`compareJourneys`** ([packages/shared/src/groundTravel.ts](../../packages/shared/src/groundTravel.ts)) — order: plans first (upcoming by nearest date, then past-dated plans newest first, then undated), then history newest first with undated last, then cancelled newest first with undated last; ties by `created_at` DESC then id ASC. Ids compare by code unit, not `localeCompare` (which puts `a` before `B`), so the order is identical across runtimes.

### Overview contracts and rules

Country evidence and publication rules are in [ADR 0001 §4 and §10](0001-flight-lifecycle-and-import-drafts.md); the entries below add the contract details.

- **Overview read contract** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — compact and owner-only (C6): top lists hold 5 items, months 12, `countryIds` and `map.countries` at most 512 reference codes. Flight totals and `countryIds` use completed flights in the selected period, including `all`. Undated claims and ground visits, and legacy visit evidence without a flight, stay Passport evidence and are not assigned to a flight period. The one exception is the unfiltered all-time country figure, which reads the published country evidence and so includes legacy-only countries, as Passport does (ADR 0001 §4).
- **`OverviewMapCountry.pending`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — the account-wide published C3 status, not a statement about the period's flights: a country counts as waiting only when awaiting evidence is the only support anywhere in the account, never as a pressed stamp. A country whose only flight this year is awaiting is still pressed if a logged flight, claim, ground evidence or archived visit supports it in another period. Membership and `visits` are period-specific.
- **Country figures** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — `totals.countries`, `totals.continents`, `countryIds` and `topLists.countries` come from published country evidence only and are `updating` (null or empty, never a mixed figure) while a repair is pending or the evidence stamp is stale (ADR 0001 §4, §10).
- **`OverviewSummary.archivedEvidence`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — true when the unfiltered all-time country figure includes at least one contributing archived (legacy) visit record (ADR 0001 §4, open item 8); always false for year periods, filtered reads and flight-only accounts. It is account provenance, so it is reported even while `countryState` is `updating`; clients state it only for a ready all-time figure.
- **`OverviewSummary.comparison`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — year periods only (null for `all`): the previous calendar year under the same completed-flight rules. `firstYear` is true when the account has no completed flight before the selected year, so a zero baseline reads as "first year" instead of growth from nothing. `countries` is null while country evidence is updating.
- **`dataAvailability`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — `durationKnown` and `distanceKnown` count completed period flights with a stored value, `missingAircraft` those without an aircraft, so unknown is never shown as a genuine zero.
- **`favoriteAirline`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — the top airline of the period, only when it flew at least two flights; count ties break by IATA; null otherwise.
- **`newCountries`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — year periods only (null for `all`, where every country would be new): countries whose earliest non-transit evidence across all time falls inside the period, so a repeat visit is never new again. `items` holds at most 12, ordered by first visit then code; `count` is exact. Null while country evidence is updating.
- **`OverviewSummary.months`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — January to December for a year period, the last 12 calendar months (UTC) for `all`.
- **`MissingAircraftPage`** ([packages/shared/src/overview.ts](../../packages/shared/src/overview.ts)) — one keyset page of the set `dataAvailability.missingAircraft` counts (same owner and completed-period predicate), newest first (date, then id, descending). `total` is the size of the whole set; `nextCursor` is passed as `after` and is null on the last page; a page never exceeds `limit` (at most 100).
- **`route-projection` contract** ([packages/shared/src/routeProjection.ts](../../packages/shared/src/routeProjection.ts)) — `GET /api/flights/route-projection?period=all|YYYY` (C6, opened map) shares the Overview summary's owner scope, completed-period predicate, country policy and publication metadata, so a client can compare `revision` / `publishedRevision` with the summary it shows and say "updating" on a mismatch.
- **`RouteProjection`** ([packages/shared/src/routeProjection.ts](../../packages/shared/src/routeProjection.ts)) — `countryState` is `updating` while published country evidence is stale and `countries` is then null, never a mixed figure. `routeCount` is the exact number of distinct undirected airport pairs in the period even when `routes` and `pairs` are truncated, and equals the summary's `map.routeCount`.
- **Aggregate row key** ([packages/shared/src/overview/aggregate.ts](../../packages/shared/src/overview/aggregate.ts)) — keeps filters, paired metrics and zone coverage identical across merged rows; invalid dates cannot add to valid calendar evidence.
- **`continentOf`** ([packages/shared/src/overview/continents.ts](../../packages/shared/src/overview/continents.ts)) — splits transcontinental countries by airport coordinates; null when the reference data cannot place the airport.
- **`crossingTime`** ([packages/shared/src/overview/crossings.ts](../../packages/shared/src/overview/crossings.ts)) — undefined for legacy weighted rows, whose representative dates carry no actual instants.
- **Duration samples** ([packages/shared/src/overview/figures.ts](../../packages/shared/src/overview/figures.ts)) — weighted or legacy aggregate rows hold no exact constituent evidence, so precise duration samples come only from raw single-flight rows.
- **`SourceRecordRef`** ([packages/shared/src/overview/model.ts](../../packages/shared/src/overview/model.ts)) — source identities stay numeric until the cabinet is projected, including legacy carried extrema.
- **`replayItems`** ([packages/shared/src/overview/next.ts](../../packages/shared/src/overview/next.ts)) — aggregate groups keep their distinct minimum source ids, including groups on the same monthly route.
- **`hasAviationFacet`, `groundMatches`** ([packages/shared/src/overview/filter.ts](../../packages/shared/src/overview/filter.ts)) — any facet beyond countries and regions excludes ground journeys, which carry no aviation evidence to match. Ground journeys match by `startDate ?? endDate` with the flight date's period rules.
- **`effectiveScope`, `effectiveScopeFromPresence`** ([packages/shared/src/overview/filter.ts](../../packages/shared/src/overview/filter.ts)) — a stored travel scope is ignored while the payload has no ground journeys, so a leftover scope cannot blank the Overview; the presence check is global (any non-cancelled ground journey in the account), not limited to the filtered view.
- **`LEGACY_SECTIONS`** ([packages/shared/src/overview/prefs.ts](../../packages/shared/src/overview/prefs.ts)) — maps section ids retired by Overview cards v2 (`fleet`, `manufacturers` to `aircraft`; `timeline` to `rhythm`) so stored layouts keep working. In a pre-v2 layout a merged card is hidden only when every card it replaced was hidden.
- **Saved maker filter in `prefs.ts`** ([packages/shared/src/overview/prefs.ts](../../packages/shared/src/overview/prefs.ts)) — a saved `other` maker filter is dropped on load: every reference manufacturer has its own slot now, so it would match no flight.
- **`latestDeparture`, `recordFlights`** ([packages/shared/src/overview/records.ts](../../packages/shared/src/overview/records.ts)) — `latestDeparture` is null unless every row is a raw flight, because route-group rows carry no witness for it. One route-group witness suffices for either endpoint; a flight is never reconstructed from sums or hour floors.
- **Route newness** ([packages/shared/src/overview/routes.ts](../../packages/shared/src/overview/routes.ts)) — a route is new in the year of its first counted flight (date, then id), and only if that flight is in scope.

### Geography and map generation

- **`greatCirclePoints`** ([packages/shared/src/geo.ts](../../packages/shared/src/geo.ts)) — the shortest spherical arc including endpoints; antipodal points use a deterministic perpendicular because the shortest arc is otherwise ambiguous.
- **`greatCircleCrossings`** ([packages/shared/src/geo.ts](../../packages/shared/src/geo.ts)) — reports only internal side changes on the same arc as `greatCirclePoints`; boundary contact is excluded. A `1e-12` epsilon suppresses floating-point boundary noise, including the indeterminate longitude at a pole.
- **`generate-atlas-points`** ([scripts/generate-atlas-points.mjs](../../scripts/generate-atlas-points.mjs)) — the Natural Earth label-points source (`ne_10m_admin_0_label_points.geojson`) is pinned and supplied by path, so the script never fetches silently. The file is keyed by ISO 3166-1 alpha-3 (`sr_su_a3`, `sr_adm0_a3`), so catalog alpha-2 codes are translated through the ISO3 column of the stamp index. Where a country has several points (archipelagos), the lowest `scalerank` wins (Natural Earth's own "most important label first"), then file order. `NE_CODE` maps the catalog's SJ and XK to Natural Earth's own subunit codes (`NSV`, `KOS`). A label must sit on the main landmass: the file also lists subunit points (Corsica, Alaska, Svalbard), all tied at `scalerank` 0, so only points inside the largest outer ring are kept and the one nearest its centre wins. Drawn countries the source does not cover, or whose point falls outside that ring, are left out and the atlas falls back to the ring's bounding-box centre.
- **`generate-continent-pieces`** ([scripts/generate-continent-pieces.ts](../../scripts/generate-continent-pieces.ts)) — builds `apps/next/src/client/overview/iso/continents.generated.ts` from the 110m country polygons. Airport-level rules assign countries to seven continents: Russia and Kazakhstan split at the Urals, Turkey's Thrace is Europe, Sinai is Asia, the Americas split by subregion from `packages/data/src/countries.json`. Straddling countries are clipped, outlines are merged per landmass by cancelling shared borders, and the result is simplified (Douglas-Peucker at 1.5 degrees, rings under 10 deg2 dropped, coordinates to 0.1 degrees).
- **`continentOf` (generator)** ([scripts/generate-continent-pieces.ts](../../scripts/generate-continent-pieces.ts)) — overseas pieces of European countries (French Guiana, the Caribbean) belong to the continent where they lie, not their sovereign's. The east cut of Turkey is split at Thrace's corner so its shared southern edge cancels in the union step.
- **`union`** ([scripts/generate-continent-pieces.ts](../../scripts/generate-continent-pieces.ts)) — edges shared by two neighbouring countries cancel, so a continent is the outline of its land: the rings left after stitching what remains.
- **`generate-country-regions`** ([scripts/generate-country-regions.ts](../../scripts/generate-country-regions.ts)) — writes `packages/shared/src/countryRegions.generated.ts` from the catalog's `continent` field. `functions/` cannot import `@kuuki/data`, so the six-region map is checked in and `functions/test/regions.test.ts` fails when catalog and map diverge. Run with `pnpm generate:regions`.
- **`generate-ring-endonyms`** ([scripts/generate-ring-endonyms.ts](../../scripts/generate-ring-endonyms.ts)) — resolves the ring text of every country (own-script name on top, English name below) into `apps/next/src/lib/stamp-art/ring-endonyms.json`, derived from Intl (language by likely subtags, name by `Intl.DisplayNames`) and corrected by `ring-endonyms.overrides.json`. The resolved table is committed so stamp output never depends on the ICU build that runs the generator. Run with `pnpm generate:ring-endonyms`.

### Figure and lane generators

- **Decorative SVGs** ([scripts/generate-passport-bench.mjs](../../scripts/generate-passport-bench.mjs), [scripts/generate-windsock.mjs](../../scripts/generate-windsock.mjs)) — the generated drawings are marked `aria-hidden` and not focusable, because the facts are in the HTML captions (bench) or the status line (windsock) beside them.

- **Concorde nose details** ([scripts/generate-concorde.mjs](../../scripts/generate-concorde.mjs)) — surface details share the nose's turning part, so the far-side glazing fades with its facing.
- **`verifiedAnatomyKit`** ([scripts/concorde/verify-kit.mjs](../../scripts/concorde/verify-kit.mjs)) — shared by figure generators; validates the complete locked dependency set against the hashes in `anatomy.lock.json` before executing kit code or writing anything.
- **Airliner estimates** ([scripts/leaderboard-lanes/airliner/airliner.ts](../../scripts/leaderboard-lanes/airliner/airliner.ts)) — belly height, nose shape between measured stations, airfoil thickness, wheel track and tyre sizes (published values, rounded, by family), gear stations, door, exit, cargo-door and window stations, inlet internals, flap-track fairing stations and antenna positions are estimated in the drawing code, not held in the measured aircraft-geometry data.
- **`AIR_UNIT`, `MASS`** ([scripts/leaderboard-lanes/airliner/build.ts](../../scripts/leaderboard-lanes/airliner/build.ts)) — `AIR_UNIT` (112) is the reference airliner's drawn length (nose to tail end on screen) in viewBox units, equal to CSS px at `--lane-unit` 112, so it must stay in step with the lane CSS. Lengths blend true scale and equal weight: drawn length is proportional to length^`MASS` (0.55), so small and large types stay readable in one lane.
- **`surface.ts`** ([scripts/leaderboard-lanes/airliner/surface.ts](../../scripts/leaderboard-lanes/airliner/surface.ts)) — a custom parametric-surface renderer, because the anatomy kit's lathe turns circles about a straight axis and airliners need bodies that are not turned (drooped nose, upswept tail cone, airfoil wings and tails, pylons, winglets). It samples S(u, v) on a grid, takes vertex normals from the grid, marches each cell against visibility n·V (clipped at 0 with linear interpolation, so the silhouette is the true limb rather than a facet edge) and against n·L at the kit's band thresholds, then unions each band's pieces. A surface may be open (an inlet's hole, a wing root standing on the fuselage): what is not front-facing is not drawn, so the hole reads through.
- **Grid snapping and `union2`** ([scripts/leaderboard-lanes/airliner/surface.ts](../../scripts/leaderboard-lanes/airliner/surface.ts)) — geometry is snapped to a grid before union because polygon-clipping's sweep line fails on nearly coincident vertices. `union2` retries on coarser grids (`0`, `1e-3`, `1e-2`, `5e-2`) when the sweep line throws and fails the build only if none works.
- **`unionAll`** ([scripts/leaderboard-lanes/airliner/surface.ts](../../scripts/leaderboard-lanes/airliner/surface.ts)) — unions polygons in balanced batches, because polygon-clipping is fastest on similar-sized inputs.
- **`solidHoles`** ([scripts/leaderboard-lanes/airliner/surface.ts](../../scripts/leaderboard-lanes/airliner/surface.ts)) — removes union slivers left where a rounded cut point misses its neighbour's edge: any hole thinner than half a build unit on average (twice its area over its perimeter). Real openings such as inlets are far wider and stay.
- **Lane SVG paints and `EPS`** ([scripts/leaderboard-lanes/airliner/svg.ts](../../scripts/leaderboard-lanes/airliner/svg.ts)) — every paint is an inline `var()` so the art follows the theme and the member's livery through the `<use>` clone (selectors do not reach into it, custom properties inherit). `EPS` is the Douglas-Peucker tolerance, 0.04 in final viewBox units (1 unit = 1 CSS px on a desktop lane); coordinates are written to a tenth, as the ground vehicles' are: under half a pixel of error even in a 4x close-up, at half the gzip size of hundredths.
- **`scene-art.ts` paints** ([scripts/leaderboard-lanes/scene-art.ts](../../scripts/leaderboard-lanes/scene-art.ts)) — paints are the theme's iso roles written as CSS variables so the art follows the theme through the `<use>` boundary; the accent ramp is the member's livery.
- **`scene-art.ts` frames and root size** ([scripts/leaderboard-lanes/scene-art.ts](../../scripts/leaderboard-lanes/scene-art.ts)) — each atlas-only vehicle (yacht, balloon) gets its own family frame, so a tall balloon never resizes the ground lanes. Each art file's root `<svg>` carries the symbol's width and height because Next reads image dimensions from every imported SVG.
- **`buildBalloon`** ([scripts/leaderboard-lanes/balloon/balloon.ts](../../scripts/leaderboard-lanes/balloon/balloon.ts)) — the envelope's cloth and the basket's wicker use their own `BALLOON_CSS` ramps so both stay bright in the dark theme; the serializer writes the aircraft ramps, which are renamed per item.
- **`buildCar`** ([scripts/leaderboard-lanes/car/car.ts](../../scripts/leaderboard-lanes/car/car.ts)) — derives the kit camera from the road's actual projection through `laneCamera`. `LaneScene`'s rotated iso basis differs from the air camera, and inheriting it keeps tyre contacts, road skew and the car's scale aligned with the lane.

Parts are drawn far to near: far bogies, underframe, near bogies, the tail end (behind the shell), the shell and everything drawn on it, the nose end (in front), the roof; reordering breaks occlusion.
- **Locomotive model** ([scripts/leaderboard-lanes/locomotive/model.ts](../../scripts/leaderboard-lanes/locomotive/model.ts)) — a modern four-axle electric locomotive (Bo'Bo') in metres with a Vectron's proportions. `a` is the distance from the rear buffer face, so the nose buffer face stands at `a = LENGTH` and world x is `a - LENGTH`: the nose is the lane anchor (x = 0), as for the car. Envelope, bogie centres and wheel size are the type's published dimensions; cab glazing, doors, grilles and roof equipment are drawn for a generic type, not one railway's.
- **`LENGTH`, `RAIL`, `WHEEL_Y`** ([scripts/leaderboard-lanes/locomotive/model.ts](../../scripts/leaderboard-lanes/locomotive/model.ts)) — `LENGTH` (18.98 m over buffers) is a lane contract: `scene-art.ts` reads it as `LOCO_LENGTH` from the app's lane draw, so changing it moves the lane layout. `RAIL` (0.7175) is half the standard gauge and must equal the lane's `RAIL` offset from the track centre line. `WHEEL_Y` (`RAIL + 0.03`) is the tread centre from the centre line; the wheel's outer face stands at `RAIL + 0.08`, the lane's `gear`.

## Consequences

- Changing any behaviour, limit, source or contract listed here means updating this ADR in the same change; the symbol name is the lookup key.
- A new non-obvious decision in `packages/` or `scripts/` gets an entry here, or in a topic ADR when it belongs to one, because comments can no longer carry it.
- Entries that point to ADRs 0001, 0002, 0005 and 0008 defer to them; edit the owning ADR first when the decision itself moves.
