# ADR 0013: Overview, Journal and maps client decisions

- **Status:** Accepted, 21 November 2026.
- **Source:** decisions that lived as code comments until the comment ban (`scripts/comments.mjs`); each entry names the symbol it governs.

## Context

Code comments are now banned by lint. The comments that recorded a non-obvious decision (a reason the code cannot express: a browser bug, a contrast measurement, a race, a licence) were moved here so the reason survives next to a stable link to the code. This ADR covers the Overview (charts, figures, globe, chapters, narrator), the Journal, the Leaderboard and the MapLibre map layer under `apps/next/src/client/`, plus the Overview server read.

## Decision

### Owner sync and request lifecycle

- **`useFlightEdits`** ([detail-sheet.tsx](../../apps/next/src/client/journal/detail-sheet.tsx)) — one save per flight at a time; a save or Undo answered after a sign-out or owner switch is dropped, never applied, so one member's answer cannot land in another member's session.
- **`writeFlightFields`** ([flight-edits.ts](../../apps/next/src/client/journal/flight-edits.ts)) — sends one PATCH with every changed field so related changes land together or not at all. The answer is applied only while the asking session is current and the returned row matches the sent values; otherwise the outcome is unknown. A sign-out or owner switch aborts the request through `trackPrivateOperation`.
- **`failureOutcome`, `unknownMessage`, `EditOutcome`** ([flight-edits.ts](../../apps/next/src/client/journal/flight-edits.ts)) — a 4xx means the server refused and nothing changed (`rejected`: drafts stay, the form shows why). A 5xx, a dropped connection or an abort is `unknown`: the compare-and-set update may have landed before the answer was lost, so drafts stay, no outcome is claimed and the copy says it may or may not be saved.
- **`EditForm`** ([flight-detail.tsx](../../apps/next/src/client/journal/flight-detail.tsx)) — changes are measured against the flight as it was when Edit started, so a refresh that lands meanwhile is never reverted; an `unknown` save counts as done when the refetched flight already holds every sent value.
- **`undoWrite`, `canUndo`** ([flight-edits.ts](../../apps/next/src/client/journal/flight-edits.ts)) — Undo restores the signed server snapshot only while the flight's complete post-edit state still matches and no later edit was recorded; otherwise it is unsafe and refused.
- **`confirmFlights`** ([confirm-flights.ts](../../apps/next/src/client/journal/confirm-flights.ts)) — contract:
  1. Upcoming and logged flights are skipped and reported, never sent.
  2. Candidate tokens come from the first 100 awaiting flights (`GET /api/me/awaiting`); the queue is re-read when tokens run out, after each committed batch and after a 409.
  3. `POST /api/flights/confirm` takes at most 100 items and is all or nothing, so flights go in sequential batches of up to 100, each with its own `operationId`.
  4. A 409 (`STATE_CONFLICT` or `CANDIDATES_CHANGED`) committed nothing: the queue is re-read and the batch rebuilt at most twice in a row. Leftover flights without a token are `skipped.notAwaiting` only when the queue was read complete after the last change (`awaitingFlights.length >= awaitingFlightCount`), otherwise `skipped.noToken`.
  5. A lost answer (network, 408, 5xx) may have committed: the same request is replayed once and the server answers a known `operationId` from its receipt. Still lost: outcome `unknown`. Any other 4xx: `rejected`.
  6. A response arriving after sign-out, an owner switch or an abort is dropped (`stale`); the request is registered with `trackPrivateOperation`.
     It never waits for publication; the caller refreshes its reads. "Did not fly" is not a server call but the Journal's deferred delete (spec D1).
- **`useJournalReview`** ([review-mode.tsx](../../apps/next/src/client/journal/review-mode.tsx)) — the review set is every awaiting flight in the payload ignoring filters (D6), minus rows a pending delete hides and flights confirmed this session, oldest first (date, `departure_utc`, id). I flew confirms one flight with the queue's candidate token and the transit choice; a confirmation whose publication is pending waits for it (`awaitPublication`) and then re-reads the operation receipt for new stamps. Did not fly uses the shared deferred delete. Both actions are blocked offline. An `unknown` outcome (and `partial`, which one flight cannot reach) may have committed, so it reports the uncertainty and refreshes.
- **`receiptTransport`** ([review-mode.tsx](../../apps/next/src/client/journal/review-mode.tsx)) — keeps the last confirm request and answer so a pending publication can read the receipt again for newly stamped countries.
- **`scheduleDelete`** ([journal-delete.tsx](../../apps/next/src/client/journal/journal-delete.tsx)) — the Journal has one deferred delete owner: bulk Delete, bulk Did not fly, review-mode Did not fly and mobile swipe Delete share one pending operation with a 6 s Undo (paused while the tab is hidden). A new schedule commits the pending one first and drops ids already in it, so only the newest is undoable and the one Undo is never ambiguous. Only a 4xx `ApiError` is a definite rejection (rows come back); a transport failure, timeout, 5xx or missing flight cannot prove the DELETE did not commit, so the list is reconciled by a read before unhiding, and a failed reconciliation keeps rows hidden with a read-only refresh. Unmounting while pending sends nothing (except after sign-out or owner switch). Reloads keep the countdown in owner-scoped `sessionStorage`; interrupted requests are reconciled by read, never replayed. Stored receipts are read before deferring restoration so a new action does not restore its own fresh receipt, and restoration is deferred to a microtask so React Strict Mode's setup/cleanup rehearsal cannot cancel a restored operation.
- **`clearDeleteReceipts`** ([delete-receipts.ts](../../apps/next/src/client/journal/delete-receipts.ts)) — receipts live in `sessionStorage` per owner and hold only ids, never flight or account details; an identity change clears them even while the Journal is unmounted so a previous owner's deferred delete is never replayed.
- **Journal refresh read** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — refresh uses its own owner-bound read because TanStack Query cancellation may resolve with reverted cached data; reconciliation needs the actual read. On `OWNER_CHANGED` the read keeps this owner's cached rows until the identity check navigates away, while required reads still reject.
- **`isNewer`** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — a newer server payload (revision, `publishedRevision`) replaces the cache; an older one (a late or cached render) never does.
- **Overview prefs saver** ([overview-context.tsx](../../apps/next/src/client/overview/store/overview-context.tsx)) — aborting keeps the write slot until settlement, because abort does not undo an accepted UPDATE and an overlapping write must not be authorized. After mount the store revalidates again when the etag differs, because a refresh already in flight may predate the server publication.
- **`canPublish`** ([data-store.ts](../../apps/next/src/client/overview/data-store.ts)) — admission and publication share one synchronous continuation after the final await, so a superseded response cannot publish.
- **Overview owner reads** ([overview.ts](../../apps/next/src/server/overview.ts)) — request-scoped like the identity they read, started beside the onboarding gate rather than after it so the page reuses reads in flight. Each read checks the session first (a guest reads nothing); a member redirected to onboarding has the result dropped.
- **`MissingAircraftReview`** ([missing-aircraft.tsx](../../apps/next/src/client/overview/missing-aircraft.tsx)) — page refresh keeps the reviewed boundary because the refreshed page may contain older targets not yet reviewed; the consumed prefix is computed from retained reviewed ids, because saved rows no longer consume the server cursor's missing-only prefix and continuing would otherwise skip unseen flights.
- **`PayloadAircraftReview`** ([aircraft-review.tsx](../../apps/next/src/client/overview/sections/manufacturers/aircraft-review.tsx)) — reads the raw missing count, not `useAircraftReviewCount`'s null-at-zero, so an open dialog keeps rendering while its last flights are saved.

### Journal list, URL and detail sheet

- **`useJournalHref`** ([journal-sections.tsx](../../apps/next/src/client/journal-sections.tsx)) — renders `/journal` on the server and during hydration; the section stored in `sessionStorage` applies only after hydration, and storage is re-read every render so leaving the Journal picks up what its page stored (avoids a hydration mismatch).
- **Journal store** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — one in-memory store per page, not shared with the Overview; payload seeded by the server page. View state is mirrored to the URL with `history.replaceState`, never pushing and never moving focus. `openFlight` pushes one history entry from closed and replaces while open; `closeSheet` steps Back over its own entry; selection survives filter changes; hidden rows are deferred-delete rows. `applyFlight` patches the cache at once and callers still `refresh()` so firsts, connections and refs are recomputed by the server.
- **`SHEET_ENTRY`, `ENTRY_KEY`** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — the pushed sheet entry stores the id of the entry it was pushed from, and every entry the store writes is tagged, so closing can step Back instead of adding history and only a return to that exact entry keeps the current filters. Back from the sheet to its parent only closes it; filters changed while open stay. Any other traversal (Forward, Back past another entry) adopts that entry's own URL. `writeUrl` names the parent entry lazily so a plain visit never rewrites its URL.
- **`ownHistoryState`** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — writes only the app's own keys, because Next's patched history copies its internals back in and syncs `useSearchParams` only when the passed state does not already carry them.
- **`writeUrl` failures and hash** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — history write failures are swallowed because browsers throttle history writes (Safari: 100 per 30 s); the view state stays right and the next write catches the URL up. Legacy aliases and `#arrival-<id>` are canonicalised on mount because the server never sees the hash; a later server render (a shell link to legacy `/journal?queue=awaiting`) only rewrites the URL to the current view; the view is set from the location after hydration since the hash cannot be read during server render.
- **Facet key** ([store.tsx](../../apps/next/src/client/journal/store.tsx)) — facets are keyed by value without `q`, so a keystroke does not rerun the selection with the old search before the deferred search text lands.
- **`parseJournalUrl`** ([url.ts](../../apps/next/src/client/journal/url.ts)) — legacy status `completed` (and `isUpcoming=false`) meant flown flights, which are now the default contents, so it maps to an empty status facet.
- **`JournalDetail`, `useDockedDetail`** ([detail-sheet.tsx](../../apps/next/src/client/journal/detail-sheet.tsx)) — stays mounted for the page lifetime so a toast Undo works after the sheet closes. At 1280 px and above (after mount) it renders a non-modal 460 px `<aside>`; otherwise a modal `Sheet`, opened only after mount so a `?flight=` deep link renders identical server and client markup. `useDockedDetail` is false on the server and during hydration so the first render never depends on `window`. The modal overlay offers Undo in an in-sheet status line because a toast would sit behind the focus trap. While Edit is open, Escape first leaves Edit; Escape or a close request with unsaved changes asks before discarding.
- **`.journal-detail`** ([detail-sheet.css](../../apps/next/src/client/journal/detail-sheet.css)) — the pane has no overflow clip: calendar popovers portal out, and a combobox list near the bottom scrolls the body instead.
- **`FlightEditor`, `flight-edits`** ([flight-detail.tsx](../../apps/next/src/client/journal/flight-detail.tsx)) — typed from the lazily loaded `flight-edits.ts`; only types are imported so the airport, airline and aircraft catalogues stay out of the page bundle and load only when a member starts an edit.
- **`validateDrafts`** ([flight-edits.ts](../../apps/next/src/client/journal/flight-edits.ts)) — checks only changed fields; unchanged fields are not sent, so a legacy value the catalogue no longer knows never blocks another edit.
- **`mergeSavedFlight`** ([flight-edits.ts](../../apps/next/src/client/journal/flight-edits.ts)) — endpoint countries are not in the PATCH DTO: an unchanged airport keeps the payload's country, a changed one takes the catalogue's until the refetch brings the server's.
- **`arrivalOrdinal`** ([arrivals.ts](../../apps/next/src/client/journal/arrivals.ts)) — counts recorded arrivals over logged flights in this journal only, not claimed visits, so importing older flights can raise an existing ordinal.
- **`BulkActions`** ([bulk-actions.tsx](../../apps/next/src/client/journal/bulk-actions.tsx)) — acts only on ticked flights that pass the filters (`selectedVisible`), never on ticks the filters hide. Delete and Did not fly use no confirm dialog but the page's deferred delete. Set aircraft fills only flights without an aircraft unless "Replace all" is ticked, through `aircraft-batch` in sequential chunks of 20. I flew skips upcoming and logged flights and counts them. Export builds the OpenFlights CSV in the browser. Offline, every write is blocked and points at the page's offline note; Export still works.
- **Portal event bubbling** ([bulk-actions.tsx](../../apps/next/src/client/journal/bulk-actions.tsx), [ledger.tsx](../../apps/next/src/client/journal/ledger.tsx)) — the `BulkActions` key handler and the `Ledger` row click handler check `event.currentTarget.contains(target)`: the aircraft dialog and menu items render in a portal, React bubbles their events to the bar or row, the DOM does not contain them.
- **`Ledger`** ([ledger.tsx](../../apps/next/src/client/journal/ledger.tsx)) — a real `<table>` with explicit ARIA roles, because the CSS turns rows into grids (cards on phones) and would otherwise strip table semantics. `FlightRow` is memoised on flight identity and booleans (callers pass stable callbacks); "any row selected" reaches the checkboxes through `data-selecting` on the table, so a selection or sort change re-renders only touched rows.
- **`useProgressiveCount`** ([progressive.ts](../../apps/next/src/client/journal/progressive.ts)) — the server and hydrating render show the first 60 rows; the rest mount after hydration in interruptible transitions of 150, so a 1,000-flight Journal is interactive after 60 rows (spec D3). A large growth (clearing a filter) continues from what is mounted; a sort or small change renders at once.
- **`openFlightsCsv`** ([export-csv.ts](../../apps/next/src/client/journal/export-csv.ts)) — follows OpenFlights CSV spec 0.41/0.42, checked 2026-10-09 against <https://openflights.org/help/csv.php> and the importer/exporter source (<https://github.com/jpatokal/openflights/blob/master/php/import.php>, `php/flights.php`). RFC 4180: UTF-8, comma, CRLF rows, double-quote delimiter; the docs say the file starts with a UTF-8 BOM and OpenFlights' own export prints one, so we emit it. The first line is a header the importer skips, exactly 19 columns: `Date,From,To,Flight_Number,Airline,Distance,Duration,Seat,Seat_Type,Class,Reason,Plane,Registration,Trip,Note,From_OID,To_OID,Airline_OID,Plane_OID`. Date is `YYYY-MM-DD` with an optional departure time `HH:MM[:SS]`. From/To are IATA or ICAO codes; the OID columns are OpenFlights internal ids and must not be supplied for foreign data, so they stay empty. A `Flight_Number` whose first two characters are an alphanumeric, not all-digit airline code overrides Airline, and an unrecognised code fails the import. Airline is the full name from `refs.airlines[iata].name`, never the code ("airline codes are not recognized"). Distance is miles with no conversion by the importer, so km is converted and rounded to whole miles. Duration is `HH:MM`, estimated by OpenFlights when blank. Seat_Type, Class, Reason, Seat, Registration and Trip are left empty (Kuuki has none). Plane matches by exact `planes.name` (unmatched names become new planes): `refs.aircraft[icao].name`, falling back to the ICAO code. An `awaiting` flight gets the note "Awaiting confirmation" (English only, interchange file); `upcoming` flights export as ordinary rows; confirmation source is dropped.
- **`countryNicknames`** ([search.ts](../../apps/next/src/client/journal/search.ts)) — adds older names and abbreviations (Turkey, USA, UK, ...) because `Intl.DisplayNames` now says Türkiye while people still type the old ones.
- **Journal search** ([search.ts](../../apps/next/src/client/journal/search.ts)) — everything depending on `refs` is built once per refs object (`indexFor`), so a keystroke costs a few lookups and each flight a handful of set checks; the server keeps the same semantics for its fallback (`buildFlightWhere`): every word must be found, folded and literal. A number under a known airline code is a flight number only, so `TK381` reads like `TK 381`. Two words that each name an airport with no airport in common are origin and destination in either order; overlap ("Istanbul IST", "New York") is not a pair.
- **`NextUp`** ([next-up.tsx](../../apps/next/src/client/journal/next-up.tsx)) — "today" comes from the client only (server snapshot null), so the hydrating render shows dates alone and the count follows; the subscription wakes at the next local midnight and on tab return, so an open page counts down a real day change. The first-render day decides motion: `null` (hydration) flips the split-flap count in instead of popping; a later day means the page crossed midnight and a Today/Tomorrow word arrives the same way; client navigation paints settled; reduced motion swaps instantly; rows have no press scale. The stub is reserved through hydration so the arriving count does not move the ticket. The lead button stretches over the whole ticket and carries the spoken name and keyboard access; the stub is `aria-hidden` and a pointer-only shortcut to the same flight.
- **`.journal-next-item:focus-visible`** ([next-up.css](../../apps/next/src/client/journal/next-up.css)) — the ring takes the flap's accent (`--pass-flap`) because on the jade paper the page focus colour can fall under 3:1 (light Shu).
- **`ReviewNote`** ([review-mode.tsx](../../apps/next/src/client/journal/review-mode.tsx)) and **`DeleteNotice`** ([journal-delete.tsx](../../apps/next/src/client/journal/journal-delete.tsx)) — live regions stay mounted with their block so a message after advancing is still announced; `DeleteNotice` is always mounted so its polite region is registered before the first message, and its sentence is constant while the countdown runs so it is announced once (the seconds are decoration).
- **`Crossfade`** ([crossfade.tsx](../../apps/next/src/client/journal/crossfade.tsx), [states.css](../../apps/next/src/client/journal/states.css)) — fades over `--dur-fast` when the result-set signature changes, never on first render; opacity only. It restarts by alternating `data-fade` between two identical keyframes with different names, so no timers or remount are needed. Reduced motion is instant.
- **Edit footer in the detail sheet** ([flight-detail.tsx](../../apps/next/src/client/journal/flight-detail.tsx), [detail-sheet.tsx](../../apps/next/src/client/journal/detail-sheet.tsx)) — Edit portals Save, Cancel and what blocks them into the panel footer so they stay in view however long the form is; an empty footer takes no room. Because Save sits outside the form, Enter in a field submits through the form's own handler, not a default button. The docked pane is sticky but starts mid-screen, which would put that footer below the fold, so starting Edit scrolls the pane up to where it sticks.

### Overview data, filters and page layout

- **`journalLinkFor`** ([journal-link.ts](../../apps/next/src/client/overview/page/journal-link.ts)) — a facet carries to the Journal only where the Journal matches it the same way: period, airline, alliance, and airports, countries, aircraft or families on their own. The Journal ORs airports with countries and aircraft with families and counts suppressed transit countries, so those pairs keep the narrower facet and report the other as dropped. A flight whose endpoint country Overview suppresses would still match in the Journal, so the country facet is dropped then. Both lists cover logged and awaiting flights; ground scope has no flight count to link.
- **`OverviewPage` gates** ([overview-page.tsx](../../apps/next/src/client/overview/page/overview-page.tsx)) — a section below its gate with no filter leaves the grid and tiles but stays in the saved order and hidden lists. The gate reads the unfiltered scope, so a filter that drops a chapter below it leaves the chapter in place and the chapter says so itself.
- **Chapter code wait** ([overview-page.tsx](../../apps/next/src/client/overview/page/overview-page.tsx)) — desktop chapters wait up to 250 ms for their code, then mount drawn rather than as loading bands; released once so a later chapter does not hold back those already on screen. Focus handoff waits a timeout because Radix `FocusScope` restores the retiring trigger in a zero-delay passive cleanup, which would otherwise override it.
- **`chapter`, `ChapterPreloads`** ([registry.ts](../../apps/next/src/client/overview/sections/registry.ts)) — a preload is optional: a chunk that fails to load leaves the chapter to fetch its own code on mount. The loaded or lazy view is chosen once per mount, since swapping later would remount it and drop state. `ChapterPreloads` has its own Suspense boundary so hydrating the page does not wait for chapter code.
- **Docked country list** ([overview-page.tsx](../../apps/next/src/client/overview/page/overview-page.tsx), [page.css](../../apps/next/src/client/overview/page/page.css)) — both the docked list and its disclosure render and CSS picks between them. Very wide screens use a media query at 2176 px (where the band reaches about 2080 px under the shell's 2560 px cap with a gutter reaching 48 px), not measurement, so the server's first paint already has the final layout. Globe row height grows up to the viewport less the header, since height, not width, limits the round globe.
- **`.ov3-page`** ([page.css](../../apps/next/src/client/overview/page/page.css)) — must not re-apply `--content-width` and `--page-gutter` (the shell already does; adding them doubled the gutter) or top padding (`.page-shell` already pads it; a second 40 px left an empty band under the header).
- **`FilterBar`** ([filter-bar.tsx](../../apps/next/src/client/overview/filters/filter-bar.tsx)) — the scope segment exists only with ground data (compute already ignores a stored scope without it). Chips use at most two rows; the rest collapse to +N beside Clear all on the last row. Nothing laid out (a hidden ancestor) measures nothing, so nothing collapses.
- **`ChapterCard`** ([chapter-card.tsx](../../apps/next/src/client/overview/layout/chapter-card.tsx), [chapter-card.css](../../apps/next/src/client/overview/layout/chapter-card.css)) — every band (figure stage, hero, chart stage, details) has a fixed box, so swiping lines two chapters up and loading, empty and ready never move what is below. Applying "Only ..." removes its own button, which would drop focus to `<body>`, so focus goes to the picked mark (or the figure button). The hero value rolls only on a pick; a non-pick change (filter, reset) bumps the epoch to start a fresh `SlotText` that renders its first value still.
- **`WIDE_STEPS`** ([figure-box.ts](../../apps/next/src/client/overview/layout/figure-box.ts)) — a few fixed figure boxes (520, 440, 320 wide), not the measured width, so a window drag redraws the figure only at a step crossing and each step's builds stay cached.
- **`useLanes`** ([use-lanes.ts](../../apps/next/src/client/overview/layout/use-lanes.ts)) — measures with a callback ref, not a container query, because a container query puts layout containment on the root and re-anchors the fixed-position menus inside the cards.
- **Card reorder** ([drag-motion.ts](../../apps/next/src/client/overview/layout/drag-motion.ts), [layout.css](../../apps/next/src/client/overview/layout/layout.css), [use-reorder.ts](../../apps/next/src/client/overview/layout/use-reorder.ts)) — `layoutRect` subtracts any in-flight FLIP translate from `getBoundingClientRect` so drop targets do not jitter while cards slide. `placeCards` reorders with CSS `order` and never moves DOM nodes, so pointer capture and focus survive; running slides are read live, cancelled and restarted from their on-screen offset so a quick second change never snaps. `createGhost` drags a visual-only copy in a fixed layer while the original stays in the grid as the hidden-content placeholder, so lane spans, `ResizeObserver` and open tooltips keep working. `MIN_TRAVEL` requires 12 px of pointer travel after a preview change, because masonry repacking can move cards under a still pointer and a boundary would flicker. `touchmove` is `preventDefault`ed only once a drag is active, since before activation a touch move is a scroll that cancels the long-press. Section headers keep interactive children `touch-action: auto` because native touch dragging requires the handle to be reserved before `pointerdown`.
- **`SectionTile`** ([section-tile.tsx](../../apps/next/src/client/overview/mobile/section-tile.tsx)) — the title is a span: a button's content is phrasing and a heading inside it is not exposed as one. The page `h1` and the sheet heading carry structure.
- **Mobile sheet** ([mobile.css](../../apps/next/src/client/overview/mobile/mobile.css)) — the options button is a sibling of the heading (`titleAction`), so it stays out of the heading's accessible name and keeps its own corner. The pager accent bar is bound to the track with scroll-driven animations where supported, otherwise moved by an inline transform from `chapter-motion.ts` (an animation outranks inline style). `.ov3-sheet-track` uses `scroll-snap-stop: always` so a hard flick stays one chapter, and no sideways overscroll so an over-swipe does not become the browser back gesture (Chrome on Android).
- **`useChapterTrack`** ([chapter-motion.ts](../../apps/next/src/client/overview/mobile/chapter-motion.ts)) — chapters are slides in a scroll-snap track; the browser owns the gesture (finger tracking, momentum, bounce, axis lock). The script only follows the track position to drive heading and footer text and switches `openId` once the track settles. It waits for the track node via state because Radix mounts the sheet portal a commit after it opens. A keyboard Previous/Next shows its destination at once (pinned) so the focused button's name is right, and the scroll position must not undo it. It calls `flushSync` when switching the shown chapter so the new text is in the DOM in the frame its fade starts; otherwise the old text flashes back for a frame.
- **`DETENT_TICK`** ([chapter-motion.ts](../../apps/next/src/client/overview/mobile/chapter-motion.ts)) — a short vibration tick when a swipe passes the point where it will change chapter. Android only (iOS Safari has no Vibration API) and it relies on Scroll Snap Events (Chromium 129+); other browsers get no tick.
- **Overview URL year** ([open-flight.tsx](../../apps/next/src/client/overview/store/open-flight.tsx)) — year navigation updates `window.history` natively, because the server page reads only `year` and native history syncs `useSearchParams` without refetching it.
- **Overview scope control** ([filters.css](../../apps/next/src/client/overview/filters/filters.css)) — Всё / Перелёты / По земле is one row in both languages: three equal cells as wide as the longest label. The primitive's wrapping put "Ground" on a second line at 320px and in Fullscreen's narrow corner.
- **Ground scope and the next strip** ([next-strip.tsx](../../apps/next/src/client/overview/hero/next-strip.tsx), [hero-panel.tsx](../../apps/next/src/client/overview/hero/hero-panel.tsx)) — По земле describes ground trips only: the next flight and the review queue show under Всё and Перелёты, and the Journal's ground link carries no Overview filters because the ground list has none.

### Overview charts

- **Heatmap and rhythm known/missing rule** ([arc-activity-heatmap.tsx](../../apps/next/src/client/overview/charts/arc-activity-heatmap.tsx), [grids.tsx](../../apps/next/src/client/overview/sections/rhythm/grids.tsx), [helpers.ts](../../apps/next/src/client/overview/sections/rhythm/helpers.ts)) — a value the journal cannot place is never a zero. `activityPoints`: a day inside `known` (first dated flight of the whole journal, not the filter, through today inclusive) with no completed flight is a known zero; a day outside it is `missing`; a completed flight is never missing; `known: null` treats every empty day as missing. `HEAT_MISSING` is never folded into bucket 0. `measuredMonths` exists because `totals()` reads a missing distance or duration as 0, so a month with flights outside the measured set is unknown (`YearByMonth`), not zero. Missing days render as a dashed outline with transparent (not `none`) fill so the cell keeps its hit area; known zeros are filled.
- **`dailyLevel`, `heatIsWeak`** ([arc-activity-heatmap.tsx](../../apps/next/src/client/overview/charts/arc-activity-heatmap.tsx)) — an absolute scale (0, 1, 2, 3, 4 or more flights) whatever the year or filter. Levels 1-3 can fall under 3:1 on the card surface (level 3 for Matcha and Asagi in light), so they carry `--heat-contour`; a known zero is the quiet `--heat-0` fill and a missing day the dashed outline, neither contoured. Levels are Kuuki's own, not Arc's.
- **`ArcBrush`** ([arc-brush.tsx](../../apps/next/src/client/overview/charts/arc-brush.tsx)) — a completed interaction consumes its draft, so a blur after key or pointer release cannot commit twice. Both range inputs span the plot area, so each thumb sits on its own edge; when the pair rests in the far half the start input is lifted so it stays grabbable. It keeps Arc's time-scaled overview/selected window; native range handles own keyboard and touch.

### Figures and motion

- **`Scene`** ([scene.ts](../../apps/next/src/client/overview/iso/scene.ts)) — projects every point itself so the SVG holds absolute screen coordinates with no nested transforms, keeping 1 px strokes 1 px at any scale. Builders return a node tree, not markup, so named parts stay addressable for motion; paints are theme roles resolved by CSS variables. A `shadow` polygon with no stroke is drawn feathered (`SHADOW_BLUR`) and excluded from the fit box; `shade` is never feathered, for crisp inner walls and apertures. `MIN_LABEL_PX` is 6: below about 6 px glyph counters close up and mono digits blur, so `labelSize` enlarges text to it even if it outgrows its plate. While `fitK` probes a build, `Scene.measure()` makes Scene skip SVG string generation (probe markup is thrown away); bounds come from projected points alone, so a probe measures exactly what the real build draws. `Scene.area()` winds every polygon the same way so overlaps fill once under the nonzero rule (a translucent fill does not darken where they meet). `Scene.done()` pads the viewport for glow at 3 sigma, while cast shadows spill via `overflow: visible` into a separate filter region with 2 sigma of feather (the tail beyond is under 3% opacity).

The gap to beat sits on the lane to beat; when that lane is outside the list (a tie spanning the neighbourhood) it moves to the viewer's own lane so it is never lost.
- **`useRankUp`** ([leaderboard.tsx](../../apps/next/src/client/leaderboard/leaderboard.tsx)) — `recordRank` runs once per publication for every all-time place. A tile that climbed first paints its old rank (layout effect, before paint), then flips when scrolled into view; several tiles flip 60 ms apart. Results are memoised by viewer and publication because Strict Mode runs the effect twice and the second `recordRank` would report nothing new.
- **Rank memory** ([leaderboard.tsx](../../apps/next/src/client/leaderboard/leaderboard.tsx)) — storage is merged with the tab baseline (newest period wins, seen sets unioned) because a failed write can leave readable storage behind this tab and another tab can publish a newer baseline. A replayed older snapshot (history, older tabs) must not rewind the next comparison.
- **`NarratorState`** ([narrator.ts](../../apps/next/src/client/leaderboard/narrator.ts)) — one line about the viewer in the selected category and period (`glados-copy`): witty where it observes a standing, calm and direct where it concerns privacy, publication or settings. Numbers arrive pre-formatted with their unit so RU plurals already agree; names are Latin-script @handles, which do not decline.
- **`CategoryStrip` scrolling** ([category-strip.tsx](../../apps/next/src/client/leaderboard/category-strip.tsx)) — the selected tile is brought into view by scrolling only the strip, never the page, and only when it is hidden or under an edge fade; a tile that opens its group snaps to the group label.
- **Lane fade mask** ([leaderboard.css](../../apps/next/src/client/leaderboard/leaderboard.css)) — the edge fade is horizontal only: the mask repeats vertically and paints past the box, or it cuts a tall wing or fin flat.
