# ADR 0011: App shell and UI code decisions

- **Status:** Accepted, 21 November 2026.
- **Source:** decisions that lived as code comments until the comment ban (`scripts/comments.mjs`); each entry names the symbol it governs.

## Context

The comment lint rule bans comments in source. Comments that only restated code were deleted. The ones below recorded a non-obvious decision, a browser or library workaround, a measured number or a privacy or security boundary that the code alone cannot express, so they are kept here, one entry per governing symbol. This ADR covers the Next app's shell, Worker runtime, routing, UI primitives, auth card, appearance, route transitions, capture, stamp art and airport viewer, plus the top-level files of `apps/next`.

## Decision

### Worker runtime, build and activation

- **`activationAsset`** ([apps/next/activation-asset.ts](../../apps/next/activation-asset.ts)) — the restricted activation host cannot serve sign-in, resend or the card, so its HTMLRewriter rewrites only `a[data-primary-path]` links to explicit static targets on the primary origin. Nothing else leaves the activation host.
- **`token`** ([apps/next/activation/activate.js](../../apps/next/activation/activate.js)) — `activate.js` is the only script the activation CSP allows. It must stay parser-blocking: it captures and erases the one-use token fragment (`history.replaceState`) before any DOM setup or async work, and applies theme, accent and language before first paint.
- **`window.location.replace($('saved').href)`** ([apps/next/activation/activate.js](../../apps/next/activation/activate.js)) — after a password reset on the activation host there is deliberately no automatic sign-in. The main-origin card shows the password-saved notice, so no secret or session travels across origins.
- **`captureHandler`** ([apps/next/api-capture.ts](../../apps/next/api-capture.ts)) — the password-reset request and complete routes are pre-auth recovery paths. The shared middleware skips session handling for them, so they are dispatched without the session wrapper.
- **`serverExternalPackages`** ([apps/next/next.config.ts](../../apps/next/next.config.ts)) — `harfbuzzjs` and the `@expo-google-fonts` packages stay external because ring baking needs native Node font-file resolution and HarfBuzz's adjacent WASM file, which bundling would break.
- **`typescript.ignoreBuildErrors`** ([apps/next/next.config.ts](../../apps/next/next.config.ts)) — true because `pnpm typecheck` already runs `next typegen` plus `tsc` over the same files, so the build skips its own type pass.
- **`worker-bundles.d.ts`** ([apps/next/worker-bundles.d.ts](../../apps/next/worker-bundles.d.ts)) — the two build outputs `worker.ts` dispatches to are typed by hand. Without that, `tsc` infers types from the bundles themselves (the Pages Functions bundle alone is about 150k lines); their sources are type-checked separately.
- **`api`** ([apps/next/worker.ts](../../apps/next/worker.ts)) — the `apiEnv` handed to the compiled Pages handler replaces `ASSETS` with a 404 JSON error. Pages' generated handler may call `ASSETS` on a miss, and an API URL must never return HTML, even if its internal route table changes.
- **`built`** ([apps/next/worker.ts](../../apps/next/worker.ts)) — `/_next/static/` output is served with long-lived cache headers: every chunk, stylesheet and media file is content-hashed and every manifest sits under its build ID, so a returning visit runs them from cache instead of revalidating each one before first paint.
- **`getRequestEnv`** ([apps/next/src/server/identity.ts](../../apps/next/src/server/identity.ts)) — never retain the Cloudflare binding or the identity at module scope. `cache()` is per request; module state leaks across requests.
- **`getOptionalPublicViewer`** ([apps/next/src/server/identity.ts](../../apps/next/src/server/identity.ts)) — public pages stay available during maintenance (`MAINTENANCE_MODE`), but real session-read errors still surface.
- **`registerSW.js`** ([apps/next/transition/registerSW.js](../../apps/next/transition/registerSW.js)) — keeps the old Vite PWA registration script URL alive during migration. It updates an existing root registration only; fresh Next visitors get no service worker. It returns early when storage is unavailable, to avoid a reload loop.
- **`sw.js`** ([apps/next/transition/sw.js](../../apps/next/transition/sw.js)) — deployed at the old root `/sw.js` URL only with the Next candidate. It has no fetch handler, so it cannot cache or answer Next, RSC or API requests. Workbox keys precaches by scope, so it matches this origin's root registration exactly to leave other applications' caches and storage alone.
- **`manifest`** ([apps/next/src/app/manifest.ts](../../apps/next/src/app/manifest.ts)) — the app is installable without a service worker (Chrome 108+ on Android); `/sw.js` remains only as the retired Vite worker's cleanup. A manifest takes one colour, so the installed app opens on the light background and the `theme-color` meta that `AppearanceProvider` keeps current recolours the bar. Icons are rendered from `app/icon.svg` and `public/icons/maskable.svg` with `rsvg-convert -w <size> -h <size> <svg> -o public/icons/<name>-<size>.png`.
- **`THEME_COLOR`** ([apps/next/src/lib/theme-colors.ts](../../apps/next/src/lib/theme-colors.ts)) — browser-chrome colours (`<meta name="theme-color">`) cannot read CSS variables, so the values are hardcoded and mirror `--background` in `src/app/styles.css` (light `:root`, `:root[data-theme=dark]`). The canvas stamp-ink colours in the same file mirror `--surface` and `--text-muted` per theme for the same reason. `src/app/tokens.test.ts` fails if either drifts.
- **`HAIRLINE`** ([apps/next/src/client/favicon-sync.tsx](../../apps/next/src/client/favicon-sync.tsx)) — the favicon hairline colours are hardcoded under a disabled `kuuki/design-tokens` lint, because `app/icon.svg` is a standalone image that cannot read CSS variables and the shared palette has no entry for them.
- **`FaviconSync`** ([apps/next/src/client/favicon-sync.tsx](../../apps/next/src/client/favicon-sync.tsx)) — sets every SVG icon link, because Next emits its static `icon.svg` link next to ours and some browsers use the first one. It writes an `href` only when it differs, so the `document.head` MutationObserver cannot loop on its own edits. It observes `childList` because Next re-renders its icon links on navigation and the tab icon must be taken back.
- **`windsock-geom.ts`** ([apps/next/src/client/loading/windsock-geom.ts](../../apps/next/src/client/loading/windsock-geom.ts)) — Node runs this file directly with type stripping from `scripts/generate-windsock.mjs`, so it uses erasable TypeScript only and imports nothing.
- **`airports`** ([apps/next/src/client/capture/reference-choices.ts](../../apps/next/src/client/capture/reference-choices.ts)) — the airline and aircraft JSON are imported with `with { type: 'json' }` attributes to match the lookups and avoid separate ESM and CommonJS copies of the same data.
- **`artwork` cache rule** ([apps/next/worker.ts](../../apps/next/worker.ts)) — `/stamps`, `/airlines` and `/icons` SVG and PNG files carry no content hash and get redrawn in place, so they are reused for a day with revalidation, unlike content-hashed `/_next/static` output.

### Server pages and layouts

- **`AdminLayout`** ([apps/next/src/app/(admin)/admin/layout.tsx](<../../apps/next/src/app/(admin)/admin/layout.tsx>)) — awaits `requireUserAnalyticsAdmin` before rendering any shell or streaming fallback, so a non-admin never receives admin markup.
- **`MemberLayout`** ([apps/next/src/app/(member)/layout.tsx](<../../apps/next/src/app/(member)/layout.tsx>)) — awaits `requireOnboardedMember` before any shell byte so hard loads get a real redirect. Pages still gate again on soft navigation.
- **`Welcome`** ([apps/next/src/app/(card)/welcome/[step]/page.tsx](<../../apps/next/src/app/(card)/welcome/[step]/page.tsx>)) — on a document load the onboarding step lands where progress allows: the name first; a running or finished import batch wins over the prompt; review needs drafts and the reveal needs saved flights. In-card moves between steps are history pushes and never reach this page.
- **`GroundTravel`** ([apps/next/src/app/(member)/ground-travel/page.tsx](<../../apps/next/src/app/(member)/ground-travel/page.tsx>)) — the list is read in the browser, because its groups depend on the visitor's own "today", which the server cannot know.
- **`Overview`** ([apps/next/src/app/(member)/overview/page.tsx](<../../apps/next/src/app/(member)/overview/page.tsx>)) — guesses `phone` from `sec-ch-ua-mobile` or the user agent only to decide whether to start the early chapter-code fetch. A phone draws tiles, so only a larger screen fetches the chapter code while the data is still being read. A wrong guess only costs or skips that early fetch, so UA sniffing is acceptable here.
- **`OwnerPassport`** ([apps/next/src/app/(member)/passport/page.tsx](<../../apps/next/src/app/(member)/passport/page.tsx>)) and **`ProfileData`** ([apps/next/src/app/(public)/fly/[username]/page.tsx](<../../apps/next/src/app/(public)/fly/[username]/page.tsx>)) — only the allowlisted identity fields of the profile (`id`, `username`, `display_name`, …) enter the client island, so no private profile column reaches the browser. On the public visitor page this is a privacy boundary.
- **`Settings`** ([apps/next/src/app/(member)/settings/page.tsx](<../../apps/next/src/app/(member)/settings/page.tsx>)) — the counts query swallows errors so Settings stays usable, and unavailable counts must never become an empty account. The publication previews read also swallows errors and leaves `previews` null; without previews Settings cannot widen publication, so it must never widen blind.
- **`POST`** ([apps/next/src/app/dev/stamps/review/route.ts](../../apps/next/src/app/dev/stamps/review/route.ts)) — the dev stamp-review write queue lives on `globalThis`, so file writes are serialised across route reloads and tabs served by the same development process. Only requests whose `Host` is a loopback alias (`localhost`, `127.0.0.1`, `[::1]`) on the dev server's port are accepted, because Next dev reports its listen address in `request.url` while browsers use loopback aliases on the same port.
- **`StampSheet`** ([apps/next/src/app/dev/stamps/stamps.tsx](../../apps/next/src/app/dev/stamps/stamps.tsx)) — the stamp impression id is created in the click handler, never during render, so SSR markup does not carry it. It includes a timestamp so a replay after a reload does not hit the session's pressed memory.
- **`ImportRuns`** ([apps/next/src/client/shell.tsx](../../apps/next/src/client/shell.tsx)) — `MemberShell` takes `jobs`: background reading needs the import job worker binding; without it imports are read inside the request on `/import`.

### Routing and URL state

- **`normalize*`** ([apps/next/src/lib/url-state.ts](../../apps/next/src/lib/url-state.ts)) — the pure URL-state normalizers validate the keys their route owns, drop invalid values, omit defaults and keep unrelated keys untouched. Output is a fixed point (normalising a normalised query returns the same query), so canonical-URL redirects never loop.
- **`period`** ([apps/next/src/lib/url-state.ts](../../apps/next/src/lib/url-state.ts)) — `year` is the canonical Journal key; the legacy `period` key from earlier builds is accepted once and rewritten.
- **`normalizePassport`** ([apps/next/src/lib/url-state.ts](../../apps/next/src/lib/url-state.ts)) — `isCountry` (`isCatalogCountry` in `client/passport/model`) is passed in to keep the country catalog out of every page that shares the module. A country deep link opens a sheet with write actions, so a well-formed code outside the catalog is dropped rather than shown. Legacy `view=stamps`, `layer`, `year` and `period` are dropped (the page redirects to the canonical URL); `sort=visits` became `records`.
- **`addOrigin`** ([apps/next/src/client/capture/add-origin.tsx](../../apps/next/src/client/capture/add-origin.tsx)) — accepts only local paths (starting with `/`, not `//`) from `sessionStorage` and otherwise falls back to Journal, as a direct visit to `/add` does. This prevents an open redirect through stored state.
- **`NavigationLink`** ([apps/next/src/client/navigation-link.tsx](../../apps/next/src/client/navigation-link.tsx)) — calls `onNavigate` only for a plain, local click that nobody cancelled, just before navigating; a mounted Journal treats a link to `/journal` like Reset or Back (see `JournalView`). It disables full-route viewport prefetch and warms only an intended destination (pointer enter, focus), because viewport prefetches compete with the page being read.
- **`useAirportHistory`** ([apps/next/src/client/airport-models/use-airport-history.ts](../../apps/next/src/client/airport-models/use-airport-history.ts)) — one owner and scope generation owns every page; stale cursors restart instead of mixing snapshots.
- **`updateOverviewReturn`** ([apps/next/src/client/airport-models/return-session.ts](../../apps/next/src/client/airport-models/return-session.ts)) — user changes update the exact history source entry, so Forward then Back cannot replay an older choice.
- **`guardTraversals`** ([apps/next/src/client/history-gate.ts](../../apps/next/src/client/history-gate.ts)) — lets an owner hold a Back or Forward traversal before Next sees it: on the bootstrap's cancelable gate when it exists, else on `popstate` in capture. `ask` gets each traversal to another entry with the URL it left; true holds it (it is undone at once and `rerun` replays it), false lets it through. Without a history index a traversal counts as one step Back. The bootstrap's gate event must be cancelled (`preventDefault`), not only stopped, because that cancellation is what keeps Next's own `popstate` handler from running.
- **`airport-screen`** ([apps/next/src/client/airport-models/airport-screen.tsx](../../apps/next/src/client/airport-models/airport-screen.tsx)) — the compare URL update deletes Next's `__NA` and `_N` fields from `history.state` before `pushState` or `replaceState`, because Next copies its own fields and publishes the URL for external History calls.
- **`CompareSettled`** ([apps/next/src/client/airport-models/compare-flow.ts](../../apps/next/src/client/airport-models/compare-flow.ts)) — holds settled outcomes only. The requested code is never stored there, so a stale failure cannot outlive it.

### Shell layout, layers and CSS

- **`edge-top` and `edge-bottom`** ([apps/next/src/app/layout.tsx](../../apps/next/src/app/layout.tsx), [apps/next/src/app/shell.css](../../apps/next/src/app/shell.css)) — the status-bar and bottom-control strips repaint the page's edge colours over scrolled content, under the header, rail and every floating layer. They are rendered outside the route stage, because a transformed ancestor would pin `position: fixed` elements to the stage instead of the viewport.
- **`--edge-top-background`** ([apps/next/src/app/styles.css](../../apps/next/src/app/styles.css)) — one palette for the page edges. Safari tints its status bar from the `html` background (and `theme-color`) and its bottom controls from the `body` background; the strips repaint the same colours over scrolled content.
- **`ALLOWED`** ([apps/next/src/app/floating-layers.test.ts](../../apps/next/src/app/floating-layers.test.ts)) — feature CSS may pin something to the viewport only through an allowlist (`app/shell.css`, `client/auth-card/ring-backdrop.css`, `client/welcome/flights/flights.css`). Everything else floats through a shared primitive (Toast, ToastSlot, Popover, Sheet, Dialog, Menu), so it joins the shell's layer order instead of picking its own z-index. The test enforces this.
- **`.member-header .site-header-inner`** ([apps/next/src/app/shell.css](../../apps/next/src/app/shell.css)) — the member header always takes Overview's wide shell (`--content-width: 2560px` above 700px), so its edges match Overview and stay put across routes. The incoming pathname selects Overview's wide content (`.page-shell[data-wide]`) before its fade, so retained outgoing pages cannot resize the header or the incoming route during a transition. The shell CSS breakpoint matches `styles.css` (700px); it uses tokens only.
- **`.tab-bar`** ([apps/next/src/app/shell.css](../../apps/next/src/app/shell.css)) — mobile stacking while a scrimmed menu is open is the menu, then the rail, then the scrim, then toasts and the import dock. It is implemented with fixed `z-index` values 73 and 74 on `.tab-bar` and `.ui-menu.add-card`; the menu shield is 71 and sheets and dialogs 51.
- **`.mobile-sr-only`** ([apps/next/src/app/shell.css](../../apps/next/src/app/shell.css)) — on phones the member header already names the page, so the page's own heading becomes screen-reader-only (absolute 1px box) and stays `RouteFocus`'s target. Guests have no title in the header and keep it visible.
- **`.ui-menu.account-menu`** ([apps/next/src/app/shell.css](../../apps/next/src/app/shell.css)) — the account menu is a boarding pass: an accent-tinted stub over the menu body, notched (`--notch: 8px`) on both sides at the tear, 300px wide. Each half masks its own semicircles, so the notch follows the stub's height without measuring it. The content element draws the floating shadow as a `filter`, which follows the cut edge.
- **`--pass-ink`** ([apps/next/src/app/styles.css](../../apps/next/src/app/styles.css)) — the Next up boarding pass (DESIGN.md "Journal redesign") is the same night-jade ticket in both themes. Hue 178° sits in the gap between success (150°) and Asagi (206°). The flaps take the accent tuned for ink (`--accent-on-ink`, the dark fill), so every accent clears 3:1 on the paper in light too; dark keeps its own fill (`tokens.test.ts`).
- **`--atlas-visit-1`** ([apps/next/src/app/styles.css](../../apps/next/src/app/styles.css)) — the Passport atlas fill starts at the accent and deepens toward `--heat-4` with visits (1, 2–3, 4–9, 10+). It is derived from the accent and heat tokens, so every theme and accent gets a ramp. The system heat ramp is not used because its first bucket starts too close to the land colour to read.
- **`--atlas-sticker-shadow`** ([apps/next/src/app/styles.css](../../apps/next/src/app/styles.css)) — the sticker's lift shadow is a fixed dark `color-mix` of black in both themes; `--text` is light in dark mode and the shadow read as fog.
- **`--removed-body-scroll-bar-size`** ([apps/next/src/app/styles.css](../../apps/next/src/app/styles.css)) — registered with `@property` as non-inherited. Radix's modal scroll lock writes it on `body` at every sheet and dialog open and close; nothing reads it, and with inheritance each write would restyle every element on the page instead of `body` alone.
- **`.ui-menu-shield`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — sits under the menu (z-index 71) and over toasts, sheets and the page, so a press anywhere else only closes the menu, as the modal menu did. The tinted variant is the scrim behind a card-like menu (mobile Add, account): opacity-only animation, and `touch-action: none` so a drag on it never scrolls the page under the menu. A `mobile` scrim is a plain shield above 700px.
- **`.ui-dialog-overlay`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — shares the sheet layer (z-index 51), so the surface opened last stacks on top: a confirm's scrim dims the sheet that opened it, and a picker sheet opened from a dialog still covers that dialog.
- **`.ui-button:active`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — the press transform (`scale(0.96)`) uses `:where` to stay at the specificity of `.ui-button:active`, so the reduced-motion override below it still wins. Popup trigger buttons (`[aria-haspopup]`, `[data-state]`, `[role='combobox']`) get no press transform: Arc popup triggers keep their anchor rectangle still while the layer measures it.
- **`.ui-panel-body`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — with no footer the body is the panel's last edge, so it matches the header's top padding. Single-class specificity keeps panels that set their own body padding (the fullscreen globe) in charge.
- **`.ui-sheet[data-side]`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — the reduced-motion fade uses `[data-side]` to match the slide rules' specificity, so the fade wins. Elements with `data-instant` (keyboard actions) skip dialog, overlay and sheet animations, so surfaces and selection indicators settle in the committing frame.
- **`.ui-segmented`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — the selected shape is styled before the measured thumb is ready, so server HTML already shows the selection.
- **`.ui-disclosure-panel[data-open='true']`** ([apps/next/src/client/ui/ui.css](../../apps/next/src/client/ui/ui.css)) — the open panel bleeds 4px on every side (`margin: -4px; padding: 4px`) so focus rings at its edges are not clipped by the overflow.
- **`.footer`** ([apps/next/src/client/ui/bottom-sheet.module.css](../../apps/next/src/client/ui/bottom-sheet.module.css)) — the footer is `position: relative` with an opaque floating surface, so actions stay above the viewport edge without resizing the scrolling body per frame. The body reserves `padding-bottom` and `scroll-padding-bottom` for the resting detent's peek, so browser focus and click scrolling still reach content.
- **`.split-flap-cell::after`** ([apps/next/src/client/ui/split-flap.css](../../apps/next/src/client/ui/split-flap.css)) — the seam is a gap to the paper behind with the digit above it, so it never cuts a stroke. Its background transitions with the hover surface, so it never shows as a line of the old colour.
- **`.unified-import-camera`** ([apps/next/src/app/(member)/import/import.css](<../../apps/next/src/app/(member)/import/import.css>)) — the camera source button is hidden on fine-pointer desktops. Desktop browsers ignore the `capture` attribute, so it would only repeat Choose files.
- **`.auth-step`** ([apps/next/src/client/auth-card/auth-card.css](../../apps/next/src/client/auth-card/auth-card.css)) — the Russian welcome heading wraps to two lines (up to 375px wide and from 701px) where the create heading fits one, so the step reserves `min-height: 2lh` in those breakpoints and the centred column does not shift. The Keyline accent icon sets `fill: currentColor` on the path itself, because Keyline puts `fill="none"` on the path and a fill on the `svg` has no effect.
- **`.cs-tilt`** ([apps/next/src/client/stamps/country-stamp.css](../../apps/next/src/client/stamps/country-stamp.css)) — uses the individual `rotate` and `scale` properties with separate transitions, so a press never waits on the hover-straighten delay.
- **Shell offline notice** ([shell-notices.tsx](../../apps/next/src/client/shell-notices.tsx)) — a loaded session keeps working without the network, so the notice says so until it returns. Hard navigations while offline never reach the app, so the notice covers only client-side use.
- **Kuukies notice on card pages** ([kuukies.css](../../apps/next/src/client/kuukies.css), [kuukies-notice.tsx](../../apps/next/src/client/kuukies-notice.tsx)) — on phone card pages the sheet's primary action sits at the bottom, so the notice follows the card in the page flow, with side padding, instead of floating over that action.

### Identity, ownership and sync

- **`resetPrivateState`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — ends with a full document navigation (`window.location.assign`), because a document navigation discards Next's segment cache as well as client stores after an identity change.
- **`IdentityExit.inPlaceOwner`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — a guest becoming a new member on a page that renders no private data (the auth card) publishes the new owner and pushes `targetPath` without a reload, so the card shell stays mounted. It returns the new owner's ID. Any other transition (a departing member, or no owner in the result) still takes the document navigation.
- **`withIdentityMutation`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — for successful cookie-identity mutations. `run` must throw on API failure; only a resolved result broadcasts the identity change and navigates (sign-in passes `/overview`, sign-out `/signin`). The departing cookie owner is resolved while the account lock is held, because a newly mounted tab may not have finished bootstrap and its remembered owner may already be stale after another tab changed the cookie. If that lookup fails the mutation proceeds anyway (`ownerKnown` stays false), so an unavailable lookup never blocks an account action; it only forces the document navigation. The in-place switch happens only when the departing identity is a confirmed guest (`ownerKnown` and `previousOwner` null): there is nothing private to drop that a reload would have to discard, and the card page rendered no owner-scoped payload. For every other change `publishIdentity(null)` is called immediately to hide the previous owner's streamed payload before navigation.
- **`IdentitySnapshot`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — private read islands must wrap their owner-scoped RSC payload in it. The server owner is visible in the initial document; on client navigation a late payload for owner A is suppressed once bootstrap has confirmed owner B.
- **`syncOwnerFlights`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — only a confirmed owner syncs; a guest or a switched identity never writes. API errors during the identity check never imply logout: the check swallows them and leaves the known identity untouched. The BroadcastChannel ping on mount covers a document load that follows an OAuth callback which changed the shared cookie outside this tab's client.
- **`lifecycle-sync`** ([apps/next/src/client/lifecycle-sync.ts](../../apps/next/src/client/lifecycle-sync.ts)) — owner sync trigger (ADR 0001 §2, R1). While the cron is held the Next shell is the only thing that moves a member's flights upcoming, awaiting, logged, so a confirmed owner session calls `POST /api/flights/sync-upcoming` itself: at most once per 10 minutes per owner across every tab (a shared `localStorage` timestamp, written before the request), never for a guest, with at most two follow-up passes while the server says `more`. The caller refreshes the page immediately and announces `kuuki:lifecycle-changed` when flights moved, then refreshes again if pending publication completes. A failed post never implies logout and never retries in a loop: it backdates the throttle so the next try comes after `OWNER_SYNC_RETRY_MS`.
- **`awaitPublication`** ([apps/next/src/client/publication.ts](../../apps/next/src/client/publication.ts)) — a bounded backoff poll for derived publication, kept apart from write-feedback so the owner-sync trigger in `activity.tsx` can use it without an import cycle.
- **`ActivityBridge`** ([apps/next/src/client/activity.tsx](../../apps/next/src/client/activity.tsx)) — on mount it calls `registration.update()` on any root-scope service worker, so a legacy worker still installed in the field fetches its retirement script (see `apps/next/transition`). Failure is ignored: it is best-effort cleanup. Keep it until old root registrations are retired.
- **`remember`** ([apps/next/src/client/lifecycle-sync.ts](../../apps/next/src/client/lifecycle-sync.ts)) — the owner-sync throttle timestamp is written to memory first, then to storage. A storage write that throws (private mode, quota) is ignored because the in-memory guard still holds the throttle for this page.
- **`ReadFreshness`** ([apps/next/src/client/freshness.tsx](../../apps/next/src/client/freshness.tsx)) — publication is pending whenever `derivedState` is not `ready`, even when the revisions are equal: an older build can publish a revision without the evidence projection, and only the owner sync's repair clears that. RSC owns summaries; this bridge is status-only and never fetches a second summary.
- **`AvatarMenu`** ([apps/next/src/client/avatar-menu.tsx](../../apps/next/src/client/avatar-menu.tsx)) — mirrors the `isPublic` prop in state but re-adopts the server value after `router.refresh()` re-renders the shell, so the server wins over an optimistic local value.
- **`announceShellNotice`** ([apps/next/src/client/shell-notices.tsx](../../apps/next/src/client/shell-notices.tsx)) — shows a notice in the owner's member shell, including from an unmount cleanup. - **`keyboardTarget`** ([apps/next/src/client/route-transition-pairs.ts](../../apps/next/src/client/route-transition-pairs.ts)) — records where the last activated link was heading when the keyboard activated it (a click with `detail` 0, as in `ui/button.tsx`). - **`tabFade`** ([apps/next/src/client/route-transitions.tsx](../../apps/next/src/client/route-transitions.tsx)) — fade-in only: the outgoing page hides at once, so the incoming one never waits on it. It uses opacity alone, so reduced motion keeps it, shorter and linear.
- **`transitions`** ([apps/next/src/client/route-transitions.tsx](../../apps/next/src/client/route-transitions.tsx)) — the ssgoi config sets `scrollLock` false: the outgoing page is inert, so there is nothing to protect, and a scroll right after a tap must land. - **`RouteFocus`** ([apps/next/src/client/route-focus.tsx](../../apps/next/src/client/route-focus.tsx)) — `MODE_KEYS` lists, by pathname, the query keys whose change is a real mode or step change that deserves a new heading focus. - **`Nav`** ([apps/next/src/client/nav.tsx](../../apps/next/src/client/nav.tsx)) — measures the sticky `.site-header` height with a ResizeObserver, because the header wraps on narrow desktops and with long labels, and sticky content below reads its real height.

### Concorde and decorative figures

- **`FAST`** ([apps/next/src/client/auth-card/concorde/concorde-field.tsx](../../apps/next/src/client/auth-card/concorde/concorde-field.tsx)) — adaptive half rate (the anatomy kit's lever 5): when a drawn frame costs more than `SLOW` ms (14) of main thread (the runtime's writes plus the style, layout and paint they cause) it draws every other frame; below `FAST` (9 ms) it draws every frame again. The angle stays time-based, so the speed never changes; at 30 fps a step moves the wingtip about 1.3px.
- **`ConcordeField`** ([apps/next/src/client/auth-card/concorde/concorde-field.tsx](../../apps/next/src/client/auth-card/concorde/concorde-field.tsx)) — the brand panel's decoration: the くうき watermark with a 1:200 Concorde display model turning on its stand (an anatomy-kit iso figure in 3D mode, built by `scripts/generate-concorde.mjs`). The figure and its runtime load after hydration so they never hold up the form, then fade in at their rest pose (the frame the generator drew). The turn eases to a stop while the field is off screen, the page is hidden, focus is inside the form (`auth-card.tsx` sets `data-form-focus` on the card) or the user pauses it, and eases back in after the gates clear; under reduced motion the model stands still. Reheat lights as the model first reaches speed, once a lap and on a click (at once with the tail in view, otherwise after a quick spin brings the tail round); pause stays as it was. The tick posts a message so the browser has finished the previous frame and the rendering cost can be timed; at half rate it carries the next drawn frame's writes into the idle frame before it, so neither frame overruns (the writes are about half of a drawn frame's cost, the style, layout and paint they cause the other half).
- **`.auth-concorde`** ([apps/next/src/client/auth-card/concorde/concorde.css](../../apps/next/src/client/auth-card/concorde/concorde.css)) — its own layer, sized by the stage's aspect (set in `concorde.generated.css`) so `contain: strict` size containment holds: a turning frame restyles, lays out and repaints only this box, never the panel or the page. - **`reheat` fragment shader** ([apps/next/src/client/auth-card/concorde/reheat.ts](../../apps/next/src/client/auth-card/concorde/reheat.ts)) — computes each pixel's ray energy from four jet streams in closed form. The aft axis is level and the camera looks down 30°, so every ray crosses a stream at 30° or more and a Gaussian tube integrates to σ·√π / sin θ. Each stream has a short hot core, a thin line and evenly spaced beads stretched along the flow (an elongated Gaussian, so closed-form too), drawn as a graphic rather than as fire, plus a wide glow that only the dark panel shows. Streams are masked by the parts drawn after their nacelle's proxy (bit 1: the first pair, bit 2: the second).
- **`mountReheat`** ([apps/next/src/client/auth-card/concorde/reheat.ts](../../apps/next/src/client/auth-card/concorde/reheat.ts)) — a lost WebGL context (a GPU reset) puts the flame out, nozzle warmth included; once the browser restores the context the layer is rebuilt on the same canvas.
- **`useMotionPause`** ([apps/next/src/client/auth-card/motion-pause.ts](../../apps/next/src/client/auth-card/motion-pause.ts)) — returns `paused = true` as the server snapshot, keeping the decoration stopped until the saved choice is available after hydration, so there is no hydration mismatch.

### UI primitives: Menu, Popover, Tooltip, Dialog and Sheets

- **`Menu`** ([apps/next/src/client/ui/menu.tsx](../../apps/next/src/client/ui/menu.tsx)) — collision-aware: Radix flips and shifts the content to stay inside the viewport (8px padding). It is non-modal, as the menu button pattern is: Radix's modal mode writes `pointer-events` and a scroll-lock custom property on `body`, and both restyle every element on the page at each open and close. `MenuShield` keeps what modal mode gave members: a press outside only closes the menu and never reaches the page or a parent sheet.
- **`MenuShield`** ([apps/next/src/client/ui/menu.tsx](../../apps/next/src/client/ui/menu.tsx)) — a transparent layer under an open menu and over everything else, toasts included. The click is stopped at the shield and closes the menu, and focus returns to the trigger as on Escape. Only a press that starts on the shield (armed flag) closes the menu, because the tap that opened it can end with a click there.
- **`Menu` Escape handling** ([apps/next/src/client/ui/menu.tsx](../../apps/next/src/client/ui/menu.tsx)) — Radix closes on Escape from a document capture listener, so a key is recorded on `window` first: the close renders without motion from the start instead of cancelling a running exit, which would leave the menu mounted. - **`Popover`** ([apps/next/src/client/ui/popover.tsx](../../apps/next/src/client/ui/popover.tsx)) — Menu and Popover content render an invisible, zero-size Radix Arrow as the first child, so Radix puts the transform origin at the trigger (measured after collision shifts) while `:last-child` rules still see the real last item.
- **`Popover` opener focus** ([apps/next/src/client/ui/popover.tsx](../../apps/next/src/client/ui/popover.tsx)) — captures the opener on each fresh Portal mount, before child `autoFocus` or ref callbacks can replace it. `onCloseAutoFocus` restores focus to the opener only if focus is on `body` or inside the closing content, because Radix runs it after unmount and an outside control may already own focus.
- **`Dialog`** ([apps/next/src/client/ui/dialog.tsx](../../apps/next/src/client/ui/dialog.tsx)) — captures the opener element at each Portal mount, before a child `autoFocus` can replace it, so focus returns to the real opener on close.
- **`DestructiveConfirm`** ([apps/next/src/client/ui/destructive-confirm.tsx](../../apps/next/src/client/ui/destructive-confirm.tsx)) — Cancel has initial focus and is the only way out besides Escape (no ×); the danger button never doubles as an icon; closing is blocked while pending.
- **`MenuTray`** ([apps/next/src/client/ui/menu.tsx](../../apps/next/src/client/ui/menu.tsx)) — a value the caller puts back (a failed save) swaps the focused cell for a span; focus moves to the new selected item when it fell to `body`.
- **`ContextMenuItem`** ([apps/next/src/client/ui/context-menu.tsx](../../apps/next/src/client/ui/context-menu.tsx)) — Radix skips disabled items in keyboard navigation, so `disabled` must be paired with the visible `reason`.

When reopened during a drag-dismiss exit, Presence keeps the node, so the dragged offset is dropped before the enter plays.
- **`BottomSheet`** ([apps/next/src/client/ui/bottom-sheet.tsx](../../apps/next/src/client/ui/bottom-sheet.tsx)) — the sheet stays mounted (`AnimatePresence` plus a `forceMount` portal) while it leaves, so a close can be caught and reversed mid-flight. A ref set while it leaves means only the exit may move it and only a reopen clears it, so stray `go()` calls cannot fight the exit. `presenceChange` records when it last started entering or leaving, so a press that began while it was leaving never dismisses it once reopened. `onPointerDownOutside` is prevented when the sheet is leaving or the press predates that change: Radix waits for the click before treating a press as outside, and a press on the trigger while the sheet leaves reopens it first and must not close it again.
- **`BottomSheet` release** ([apps/next/src/client/ui/bottom-sheet.tsx](../../apps/next/src/client/ui/bottom-sheet.tsx)) — a release to closed does not close directly: a controlled owner may veto or defer dismissal, so the sheet recovers to its detent (keeping `dismissVelocity`) while the owner decides.
- **`BottomSheet` header drag** ([apps/next/src/client/ui/bottom-sheet.tsx](../../apps/next/src/client/ui/bottom-sheet.tsx)) — pointer moves arrive once per frame, so a fast flick can leave the header before its first move lands. Until the header captures the pointer, `window` follows it; once captured, the header's own handlers take over. `headerMove` captures only after the pointer has really moved, so a plain click still lands on the grabber button.
- **`criticalSpring`** ([apps/next/src/client/ui/critical-spring.ts](../../apps/next/src/client/ui/critical-spring.ts)) — a critically damped physical spring that settles in about `response` seconds and keeps a handed-over `velocity`. Motion's time-defined springs (`duration` / `bounce`) drop the velocity they are given (motion-dom 14.1 `generators/spring.mjs`), so a release would restart from rest; stiffness and damping keep the finger's speed. `SETTLE` in `swipe-actions.tsx` (stiffness 1000, damping 64) follows the same rule.
- **`useTransitionPresence`** ([apps/next/src/client/ui/use-transition-presence.ts](../../apps/next/src/client/ui/use-transition-presence.ts)) — Radix Presence waits for animations, not CSS transitions, so transition exits retain the portal explicitly. A 350ms timeout fallback keeps a detached document or interrupted browser lifecycle from stranding the layer.
- **`useMobile`** ([apps/next/src/client/ui/use-mobile.ts](../../apps/next/src/client/ui/use-mobile.ts)) — `null` until the media query can be read (server and hydration), then true on phones. Callers that choose a surface must render nothing for `null` instead of guessing desktop, so a phone never sees the desktop dialog swap for the sheet.
- **`SegmentedControl`** ([apps/next/src/client/ui/segmented-control.tsx](../../apps/next/src/client/ui/segmented-control.tsx)) — every option's box is read whenever the control changes size. With equal cells the boxes depend only on that size and the option count, so a new selection reuses them instead of forcing a layout while its commit is applied. Measuring happens in a ResizeObserver with `flushSync`: the first report arrives after layout and before paint, so the thumb lands in the opening frame and reading the boxes costs nothing because layout is already clean.
- **`SplitFlap`** ([apps/next/src/client/ui/split-flap.tsx](../../apps/next/src/client/ui/split-flap.tsx)) — screen readers get `label` (default `value`) once; the tiles are hidden. Tiles are keyed from the aligned end, so 9 → 10 keeps the ones digit instead of re-flipping it.
- **`FeedbackText`** ([apps/next/src/client/ui/feedback-text.tsx](../../apps/next/src/client/ui/feedback-text.tsx)) — React keeps the SSR text stable; Torph owns the node's contents after hydration, so React must not re-render children into it.
- **`FeedbackText` burst mode** ([apps/next/src/client/ui/feedback-text.tsx](../../apps/next/src/client/ui/feedback-text.tsx)) — a numeric update arriving within one `--dur-fast`/`--dur-base` interval of the last one counts as a burst and renders without animation; one quiet interval ends burst mode. This is deliberately simple. Move to stream-level backpressure only if updates become expensive.
- **`MakerSwatch`** ([apps/next/src/client/ui/category-mark.tsx](../../apps/next/src/client/ui/category-mark.tsx)) — Unknown is an outline with a «?», never a fill: it must not pass for a manufacturer colour. Other stays a filled neutral.
- **`Checkbox`** ([apps/next/src/client/ui/checkbox.tsx](../../apps/next/src/client/ui/checkbox.tsx)) — `inner.indeterminate` is set in an effect with no dependency list: a click clears the DOM flag, so it is set again after every render the caller made.
- **`AsyncCombobox`** ([apps/next/src/client/ui/combobox.tsx](../../apps/next/src/client/ui/combobox.tsx)) — the options come from a search request and the typed text is only a query. A place is chosen by Enter on a highlighted option or a click, never by leaving the field, so the only match is not taken for the answer. Loading, no result and failure are separate states; a failure keeps the typed text and the previous choice, and a response for an older query is dropped (see `useAsyncSearch`). The typed text is an unresolved query: it outlives closing the list but not a choice made elsewhere (swap, reset, OCR hand-off), so when the committed label moves on the stale text goes. Enter inside an open search never submits the surrounding form; it picks the highlighted option only. Buttons in the list (Retry) `preventDefault` on `mousedown`, which is what stops the browser moving focus and the blur closing the list.
- **`useAsyncSearch`** ([apps/next/src/client/ui/use-async-search.ts](../../apps/next/src/client/ui/use-async-search.ts)) — a debounced, abortable search whose answer always belongs to the query on screen. A response for an older query (or an older retry) is never shown, even when the search function ignores its signal: the state is keyed by the query it answered, so a stale entry does not match. While a new query loads, the last answer is handed back as `previous` so a list can keep its height; it must never be chosen. `search` is deliberately not an effect dependency: a new closure each render must not restart the request.
- **`SwipeActionsRow`** ([apps/next/src/client/ui/swipe-actions.tsx](../../apps/next/src/client/ui/swipe-actions.tsx)) — a swipe is a shortcut, never the only path. Callers must also give every action a menu path (a row menu, a context menu or the detail sheet), because keyboard, screen-reader and switch users cannot swipe and the revealed buttons are not reachable at rest. Revealed actions are real 44px buttons hidden (`visibility`) until a swipe reveals them. One motion value (`place`) owns both pointer tracking and settling, so grabbing a spring keeps its current position. The drag origin is measured when the axis lock engages, so crossing the slop never jumps the row. A tap on an open row closes it and swallows the click instead of acting on what is underneath.
- **`ContextMenu` anchor** ([context-menu.tsx](../../apps/next/src/client/ui/context-menu.tsx)) — the anchor is `position: fixed`, but a contained ancestor (a ledger row's `content-visibility`) becomes its containing block, so the anchor's real origin is measured at 0,0 before the pointer point is applied. The old inline `left`/`top` are put back afterwards, because React diffs the style prop rather than the DOM and would otherwise skip an unchanged point.
- **`useListClaimsEscape`** ([combobox.tsx](../../apps/next/src/client/ui/combobox.tsx)) — Radix dialogs and sheets close on Escape seen at document capture, before a field inside gets the key. While an inline list is open, Escape is claimed first at window capture (Radix skips a prevented event) and closes only the list; the next Escape closes the panel. Escape during IME composition is left to the input method. A list in its own Sheet is already a Radix layer and needs none of this.
- **`significant` in `searchChoices`** ([combobox.tsx](../../apps/next/src/client/ui/combobox.tsx)) — the airport catalog has no size or traffic data, so "International" (or "международн") in the name stands in for a larger airport when breaking ranking ties, after the member's recents.
- **Flight search inside the add dialog** ([flight-controls.css](../../apps/next/src/client/ui/flight-controls.css)) — the dialog body scrolls and clips overlays, so the result list takes room in the form (as in the bulk dialog). While it is open the dialog may use the viewport height, and the list leaves room for about 400px of header, footer and route summary, so four results show without scrolling the summary away.
- **Dialog footer fill** ([ui.css](../../apps/next/src/client/ui/ui.css)) — the dialog panel stays `overflow: visible` for popovers and focus rings, so the footer paints its own fill following the panel's bottom corners. Sheets sit flush with the screen edge and need none.
- **Airline logo cell** ([ui.css](../../apps/next/src/client/ui/ui.css)) — the logo row is a fixed track: an `auto` row grew to a tall logo's height (KLM) and the clip cut its lower edge.

### Stamp art (build-time library)

- **`stampFiles`** ([apps/next/src/lib/stamp-art/build.ts](../../apps/next/src/lib/stamp-art/build.ts)) — the ring is baked as a file separate from the engraving, so fallback-tier countries have one too and regenerating an engraving never touches the ring file.
- **`frame`** ([apps/next/src/lib/stamp-art/frame.ts](../../apps/next/src/lib/stamp-art/frame.ts)) — the five stamp frames all live in a 200×200 viewBox, so the engraving grid and the frame share one coordinate system. It is the single source for the renderer clip, the linter, the impression nicks and the stamp component.
- **`GRID`** ([apps/next/src/lib/stamp-art/grid.ts](../../apps/next/src/lib/stamp-art/grid.ts)) — everything lives on a 200×200 grid (y down) drawn in one ink (`#000`): the SVG is used as a CSS mask, so there is no second colour and no `<pattern>`. Hatching is emitted as real lines so the mask stays pure geometry. `WEIGHTS` are stroke widths in grid units, tuned to survive a 96px display (2.6 units is about 1.2px).
- **`impression`** ([apps/next/src/lib/stamp-art/impression.ts](../../apps/next/src/lib/stamp-art/impression.ts)) — the wear texture for the owner's impression layer (B1) is one file per frame shape, because the broken edge has to follow that shape's outer rule. The rendered alpha is the mask: opaque keeps ink, transparent removes it (the file is `#fff`, so `mask-mode: luminance` agrees with `alpha`). It is composited over the whole stamp with `mask-composite: intersect`; inside the file the texture is built from an SVG `<mask>` (white keeps, black removes), so holes are real alpha holes. The viewBox is 300×300 centred on the 200×200 stamp (`-50 -50 300 300`), so a 180° rotation and the small offset still cover the stamp. A pressure gradient runs across the shape's width (full ink over the strong 60%, falling toward the weak edge).
- **`impressionGaps`** ([apps/next/src/lib/stamp-art/impression.ts](../../apps/next/src/lib/stamp-art/impression.ts)) — 3–5 dropout blobs. The first sits on the outer rule, pushed half its radius outward and capped at `RULE_GAP_MAX` so it never reaches the ring text; the others stay wholly inside the window, clear of the text. It draws from the same `rand` stream as the rest of the texture, so call order matters for the deterministic baked output.
- **`impressionTransform`** ([apps/next/src/lib/stamp-art/impression.ts](../../apps/next/src/lib/stamp-art/impression.ts)) — per-country placement of the shape's texture. The pressure side is the side pressed down by the rest tilt: the right edge for a clockwise (positive) tilt, the left edge otherwise. The texture is heavy on +x, so it is turned by 0° or 180° only (every frame is point-symmetric about the stamp centre), and the offset is small (±1.5) so the nicks stay on the outer rule.
- **`SURFACE_COLOR`** ([apps/next/src/lib/stamp-art/inks.ts](../../apps/next/src/lib/stamp-art/inks.ts)) — the eight stamp inks have light and dark values; every value is at least 4.5:1 against `--surface` in its theme, because the ring text is small type. `lint.test.ts` checks it.
- **`statue`** ([apps/next/src/lib/stamp-art/kit/object.ts](../../apps/next/src/lib/stamp-art/kit/object.ts)) — object modules draw an abstract monument on a plinth, never a figure.
- **`RASTER_LIMITS`** ([apps/next/src/lib/stamp-art/lint-raster.ts](../../apps/next/src/lib/stamp-art/lint-raster.ts)) — the raster lint is Node-only and kept apart from `lint.ts` so a browser bundle never imports resvg. The engraving is rasterised at 96px with the impression applied and measured inside the frame window. Thresholds were tuned on the six reference countries; measured values live in the `check:stamps` output and the W1b report. Coverage 38–58 (percent of window area): below 38 the window reads empty; above 58 the hatching clogs into grey slabs. Paper regions at least 6: a scene breaks the window into separate paper areas. Solid share at most 15: share of window pixels inside a fully inked 3×3 block; the tone ladder is built from lines, so only T5 roofs and openings reach it. Subject interior at least 50% paper: the subject is the lit shape against the tone, so under half of its silhouette may be ink. Weak quarter to strong quarter retention 0.70–0.92 (measured 0.82–0.84 on the five textures and the six references): the impression keeps that share of the ink on the weak side relative to the strong side, so the art's own distribution does not matter. Below 0.70 the weak side reads as faded ink; above 0.92 the pressure is not visible.
- **`initWasm` loader** ([apps/next/src/lib/stamp-art/lint-raster.ts](../../apps/next/src/lib/stamp-art/lint-raster.ts)) — resolves its directory through `__filename` under tsx (CommonJS) and `import.meta.url` under vitest (ESM), because the same module runs in both loaders.
- **`bakeRing`** ([apps/next/src/lib/stamp-art/ring-bake.ts](../../apps/next/src/lib/stamp-art/ring-bake.ts)) — build-time only (`generate:stamps`, `check:stamps`, tests), Node-only, never imported from client code. It bakes the ring text of a stamp into glyph outlines: the top ring is the country name in its own script, the bottom ring the English name (left empty when both are the same name). harfbuzz shapes the text, the outlines are placed one by one along the frame's ring path, and the result is one SVG path used as a CSS mask, so the browser loads no font and every device draws the same letters.
- **`bakeRing` sizing and fitting** ([apps/next/src/lib/stamp-art/ring-bake.ts](../../apps/next/src/lib/stamp-art/ring-bake.ts)) — Latin, Cyrillic and Greek take the base size (cap height `RING_CAP`). Every other script is sized by a core glyph (the body of a letter, `SIZING`) to a multiple of `RING_CAP`, so a caseless script reads as heavy as the Latin caps next to it; tall marks and stacks may then use the whole band (minus 2 units) and only an overflow shrinks the line. Fitting (plan A5, now with real glyph advances): (1) letter-spacing from the preferred value down to `LS_MIN` at the base size; (2) font size from the base down to the floor at `LS_MIN`; (3) the next candidate (the short form). A name that fits none of them throws: add a short form to `ring-endonyms.overrides.json` instead of cutting it. Scripts that join letters or hang them from a headline (Arabic, Devanagari, Bengali, …) take no letter-spacing and shrink instead. The budget is a share of the ring path length: 82% on the straight rectangle rules and 76% on round rings, where glyphs near the horizon stand sideways and stay readable only while the line is kept off the last stretch of the arc. On the octagon the line never bends round a corner: its budget is the flat edge plus `OCTAGON_OVERHANG` on each end.
- **`FONT_FILES`** ([apps/next/src/lib/stamp-art/ring-bake.ts](../../apps/next/src/lib/stamp-art/ring-bake.ts)) — Commissioner (the UI face) for Latin, Cyrillic and Greek; Noto Sans at weight 600 for every other script. All come from devDependencies except the CJK ones, which are committed subsets (see `ring-fonts/README.md`). Fonts are read as native filesystem inputs, not bundler module imports, so the CLI (repo cwd) and Next (app cwd) use the same files. `harfbuzzjs` initialises its wasm with a top-level await, which a CommonJS script cannot require, so it is loaded lazily through `loadHarfbuzz`, awaited once before `bakeRing`.
- **`SIZING`** ([apps/next/src/lib/stamp-art/ring-bake.ts](../../apps/next/src/lib/stamp-art/ring-bake.ts)) — a script without capitals is sized by measuring the core glyph in the script's own font (`ref`, or the full ink box of the line for `ink`) and scaling it to `mult` times `RING_CAP` times `SIZE_CALIBRATION`. The multiples are the art director's, except where a rendered check found the script still too small (Lao, Thai, Khmer, Sinhala, Thaana) or its core glyph is not what the multiple assumed: Noto Serif Tibetan's ཀ is 1.16 em tall because Tibetan letters hang from the headline, so Tibetan is sized to fill the band instead. Some scripts are also opened up, but only for a short name (`SHORT_CLUSTERS` = 4 or fewer letters) and only lightly (up to `LIGHT_GAP_EM`): their letters carry vowels and marks that must stay with them, so a wide gap reads as separate letters. `SHORT_FILL` (0.4) is the share of the ring arc a tracked short name aims to fill (the Latin names sit at 35–45%). Arabic, Thaana and the headline scripts are never spaced.
- **`stamp-index`** ([apps/next/src/lib/stamp-art/stamp-index.ts](../../apps/next/src/lib/stamp-art/stamp-index.ts)) — build-time only (`generate:stamps`, `check:stamps`, dev sheet server): derives `stamp-index.generated.json`, the one file client code reads. Names come from Node's `Intl.DisplayNames` at generation time, so the browser never formats them and SSR cannot disagree with the client. Territories whose Intl name varies by ICU build or carries a disputed alternate use the catalog's English name instead, so generated names are stable across Node ICU versions.
