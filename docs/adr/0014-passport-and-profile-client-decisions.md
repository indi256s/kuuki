# ADR 0014: Passport and profile client decisions

- **Status:** Accepted, 21 November 2026.
- **Source:** decisions that lived as code comments until the comment ban (`scripts/comments.mjs`); each entry names the symbol it governs.

## Context

The Passport (atlas, sticker, stamps, country sheet), Profile (achievement ladders, figures, badges) and account/settings client code carries many choices that the code alone does not explain: browser and MapLibre quirks, ordering constraints, privacy limits, owner decisions. They used to sit in comments next to the code. A lint rule now bans comments, so each decision is recorded here against the symbol it governs.

Publication boundaries for the passport are decided in [ADR 0007](0007-unified-passport-publication-boundary.md); evidence rules are in [ADR 0001 §4](0001-flight-lifecycle-and-import-drafts.md). Entries below only cover client behaviour.

## Decision

### Passport page, layout and URL state

- **`PassportLayout`** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx)) — one tree serves `/passport`, `/passport?as=visitor` and `/fly/<handle>`. Owner-only controls render only when `owner` is set, and public modes receive no owner data at all. Boundary rationale: ADR 0007.
- **`PassportPage`** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx)) — `visitor` and `preview` modes take only the public payload (permitted country codes, public stats, badges, rankings), so no owner passport data reaches their props or DOM.
- **`PassportLayout` search text** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx)) — the search text is local state so typing is instant; the URL follows it, and on Back the field follows the URL.
- **`PassportLayout` map source** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx), [passport-toolbar.tsx](../../apps/next/src/client/passport/passport-toolbar.tsx)) — on the owner's map a canonical source choice belongs to the map segment, not to Filters, so it adds no badge or Reset. The map scope writes the same `src` the Sources filter writes; any other combination is named instead, and the toolbar's Reset clears it.
- **`quickVisit`** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx)) — stickers are offered only on the owner's own unfiltered map, because under a filter a just-recorded country could vanish at once. Eligibility reads the full collection, so a country hidden or pending elsewhere never lifts.
- **`derivedState`** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx)) — `ready`, `pending` or `error`, so a passport still being derived is never shown as an empty one.
- **`usePassportQuery`** ([use-passport-query.ts](../../apps/next/src/client/passport/use-passport-query.ts)) — query changes go through native `history`, which Next keeps in sync with `useSearchParams` without refetching: `replace` for filters, search, sort and the country sheet, `push` for Cards/Map so Back restores the other view with its filters. Next's own history state is not passed, because that would mark the call router-internal and skip the `useSearchParams` sync.
- **Navigation callback** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx)) — filters and the sheet replace the history entry, a mode change pushes one, and any navigation drops a pending arrival-card intent.
- **`openArrival`** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx)) — a pending slot's arrival card comes from the country's published evidence, not from the queue page's flags. A repeated activation of the same slot is ignored; a newer activation, other navigation or leaving the page supersedes it, so a late read never pulls the member away.
- **Menu to sheet focus** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx)) — a menu action focuses the menu button before opening a sheet, so the sheet returns focus there when dismissed.
- **Stamp hero gate** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx), [collection.tsx](../../apps/next/src/client/passport/collection.tsx)) — the stamp hero runs only on desktop with a pointer. The mobile bottom sheet is driven by JS motion that moves its stamp, and `onOpen`'s `pointer` flag is false for keyboard activation, which never plays the hero.
- **`onHidden`** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx)) — closes only the hidden country's own sheet, because a slow response must not close a sheet the member opened since. The hide toast carries both languages because it outlives the sheet and a locale switch.
- **`useOpener`** ([use-opener.ts](../../apps/next/src/client/passport/use-opener.ts)) — focus returns to the control that opened the sheet, or to the page heading when that control is gone (a removed country, a deep link). Callers pass the element explicitly because Safari does not focus a clicked button; the focused element is only the fallback.
- **`AddCountrySheet`** ([add-country-sheet.tsx](../../apps/next/src/client/passport/add-country-sheet.tsx)) — the sheet has no Radix trigger (the cover and the empty state both open it), so it remembers the focused opener before its own initial focus moves in, and returns there unless a pick handed focus to the country sheet.
- **`unseenCountries` and `markSeen`** ([new-stamps.ts](../../apps/next/src/client/passport/new-stamps.ts), [new-stamps.test.ts](../../apps/next/src/client/passport/new-stamps.test.ts)) — the first visit on a device records only a baseline, so an existing collection never replays; later arrivals are returned once. The seen set only grows (a hidden country keeps its place, so restoring it does not press it again). A tab-local copy stands in when storage is blocked or malformed, and an in-memory copy prevents a remount replay when storage cannot be written. `markSeen` records nothing without a baseline, because the page's first read records the whole collection, that country included.
- **Double effects in development** ([passport-page.tsx](../../apps/next/src/client/passport/passport-page.tsx), [cabinet.tsx](../../apps/next/src/client/profile/ladders/cabinet.tsx)) — effects run twice in development; the in-memory baseline makes the second pass empty, so the first result is kept.
- **`notificationStorage`** ([storage.ts](../../apps/next/src/client/profile/storage.ts)) — wraps `window.localStorage` in try/catch, because browsers can deny storage even when merely reading the property. Callers fall back to a tab-local baseline.
- **Retired `/passport/manage`** ([page.tsx](<../../apps/next/src/app/(member)/passport/manage/page.tsx>)) — bulk aircraft assignment moved to the Journal's Set aircraft action. Old links land on the Passport, and a legacy link with a catalogue code opens that country's sheet.
- **Blank and new passports** ([passport-layout.tsx](../../apps/next/src/client/passport/passport-layout.tsx), [collection.tsx](../../apps/next/src/client/passport/collection.tsx)) — a brand-new owner's passport is the atlas, in either view, so a first country can be stickered at once; a pending-only or blank passport keeps its explanation above the map because there are no cards to choose instead.
- **Passport header and scope on phones** ([passport.css](../../apps/next/src/client/passport/passport.css)) — the owner menu stays beside the name while visibility and Share take the next line, so a long Russian Share label never strands the menu. The scope's three cells share one row and never split a word; they sit beside Filters while labels fit, else on their own row (RU at 320px).

### Passport collection model

- **Pending and suppressed countries** ([model.ts](../../apps/next/src/client/passport/model.ts)) — countries with awaiting flights only appear as unpressed slots and never count as pressed; transit-suppressed hubs have no published row, so they never appear (ADR 0001 §4).
- **`chronology`, `pointKey`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — first and last visit come from dated evidence and land/sea years together, at their real precision. When a dated visit and a year-only visit fall in the same year their order is unknown, so that end shows just the year; a year-only point sorts at the start of its year. Undated evidence (claims, visits without a year) adds nothing.
- **Ground ways** ([model.ts](../../apps/next/src/client/passport/model.ts)) — a country's rail and road ways are its journeys' and its visits' together; a visit without a way stays Manual.
- **`visitorEntries`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — published codes only, so a visitor never sees dates, counts or sources.
- **`filterEntries`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — AND across search, region and sources, OR within sources, so a mixed country matches each of its sources. Visitors have no source evidence, so their sources group is ignored.
- **`searchSuggestion`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — offers "Add {country}" only when the query matches exactly one catalog country and that country is not already in the entries.
- **`suggestCountries`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — suggestions use verified sources only: recently visited countries (published evidence, limit 4) and uncollected catalog neighbours of collected countries (limit 6), ranked by how many collected countries they border. Search over the whole catalog always remains.
- **`arrivalFlightId`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — reads the awaiting flight from `GET /api/passport/countries/:cc/stats`. Only contributing endpoints are listed there; transit-suppressed ones, including the matched outgoing origin of a connection, sit in `suppressed`, so the queue's flags are never reinterpreted here. An arrival is preferred over a departure, then the latest date.
- **`RemovalOutcome` and `removalOutcome`** ([model.ts](../../apps/next/src/client/passport/model.ts)) — only claims and manual visits are removed from the passport directly; flight stamps go through the Journal. `DELETE /api/passport/claims/:cc` deletes the claim and every land/sea visit, never flights, and the outcome counts retained ground visits as deleted even when a linked arrival currently supersedes that evidence. Evidence policy: ADR 0001 §4, C3.
- **`wayOf`** ([visit-ways.ts](../../apps/next/src/client/passport/visit-ways.ts)) — a legacy land visit without a mode reads as `land`, which no tab writes.
- **`TRAVEL_REGIONS`** ([travel-regions.ts](../../apps/next/src/client/passport/atlas/travel-regions.ts), [travel-regions.test.ts](../../apps/next/src/client/passport/atlas/travel-regions.test.ts)) — a display-only grouping for the phone atlas pages (GLOSSARY "Travel region"). A catalog region frames too wide on a portrait phone (Asia runs Türkiye to Japan), so travel regions never feed filters, totals or badges. They are ordered west to east, the order a swipe walks. A test pins that every catalog country has one, since a country without would vanish from every phone page except the world cover.
- **`VisitorSheet`** ([visitor-sheet.tsx](../../apps/next/src/client/passport/visitor-sheet.tsx)) — the read-only sheet for visitors and the owner's visitor preview shows only the large stamp and the name. A catalog country outside the public set shows the name alone, so no stamp claims a visit.
- **Public stamps in the profile** ([profile-page.test.tsx](../../apps/next/src/client/profile/profile-page.test.tsx)) — the public passport shows stamps by name only, ordered by name, never the owner's visit dates (no new disclosure; see ADR 0007).

### Atlas map

- **`AtlasMap` lazy island** ([index.tsx](../../apps/next/src/client/passport/atlas/index.tsx)) — the MapLibre island (about 0.5 MB) is fetched only when the map view shows, and never renders on the server (MapLibre needs the browser). Until it is ready, and whenever WebGL, the worker or the geometry fails, the accessible list stands in.
- **`token`** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — reads the computed style and resolves it through `resolveColor`, because MapLibre needs resolved colours and cannot take `color-mix()` or `var()`.
- **`stateColor`** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — a `match` over ISO2 ids. MapLibre rejects an empty label list, so an empty set contributes no branch. A visited country takes its visit bucket's colour; pending counts only where the code is not visited, because `match` labels must be unique.
- **Countries source** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — `promoteId: 'id'` makes `id` the feature id, so hover is feature state, a paint change rather than a source reload. Pending countries are outlined and dashed, so status never relies on the lighter fill alone.
- **Map setup** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — world copies are disabled, because repeated copies would draw a visited country twice beside its single list entry. Keyboard rotation is disabled (`map.keyboard.disableRotation()`), because Shift plus arrows would rotate a flat reference map.
- **Names as symbols** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — country names are native MapLibre symbol layers, so they are placed in the same frame as the canvas and a drag cannot desync them.
- **`labelPoint`, `FRAME_ANCHORS`** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx), [travel-regions.ts](../../apps/next/src/client/passport/atlas/travel-regions.ts)) — on region pages a huge country frames on its populated part, so its name moves to `FRAME_ANCHORS` when its usual label point lies outside that part (Russia's is in Siberia, off the Europe page).
- **Click and hover picking** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — a marker beats the polygon under it. Where 44px targets overlap (European microstates at world zoom) the marker nearest the pointer wins, not whichever the renderer lists first. Hover is for fine pointers only: at most one query per move, none while the camera moves or a button is held, and label filters change only when the country under the pointer changes.
- **Controls and framing** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — buttons are the keyboard path for zoom and framing. Motion is a jump, so reduced motion needs no branch. The map fits once on the member's countries (the whole world without any), then keeps the member's view: filters, scope and recordings never refit. One button toggles between the two framings.
- **Scroll contract** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx), [pager.tsx](../../apps/next/src/client/passport/atlas/pager.tsx), [atlas.css](../../apps/next/src/client/passport/atlas/atlas.css)) — shared with `client/maps/options.ts`, the map uses cooperative gestures: a plain wheel scrolls the page, Ctrl/Cmd plus wheel zooms, touch needs two fingers. On phones the pager replaces that contract: one finger sideways turns pages, one finger vertically scrolls the page, two fingers pinch (explore), and a swipe moves at most one page. At a page's frame the canvas sets `touch-action: pan-y !important` so the page keeps vertical drags, the pager takes sideways ones and MapLibre keeps the pinch.
- **Pager refit** ([pager.tsx](../../apps/next/src/client/passport/atlas/pager.tsx)) — pages can reorder when a country joins a new region, and the page shown is the one the list names. At rest on its frame, a page refits to new frames on resize; explored or off its frame on the same page, the camera stays put. When the page itself changed under it (a filter removed it, a new country reordered the pages), the camera goes to the page the list names.
- **Pager click suppression** ([pager.tsx](../../apps/next/src/client/passport/atlas/pager.tsx)) — unlike MapLibre's own pan, the pager's page turn does not suppress the browser's compatibility click, so a consumed gesture would lift a country at release. The click is suppressed after such a gesture, and a fresh primary press restores taps. The listener is registered in the capture phase so it runs before MapLibre's canvas listeners can turn the release into a country selection.
- **`mercator`** ([pages.ts](../../apps/next/src/client/passport/atlas/pages.ts)) — Web Mercator in 0..1 units, the space MapLibre interpolates in, so a straight camera move is straight on screen.
- **Strip tab** ([atlas.css](../../apps/next/src/client/passport/atlas/atlas.css)) — the current tab changes colour only, because a heavier weight would widen the tab under the sliding selection.
- **`LABEL_POINTS`, `SMALL_STATE_POINTS`** ([label-points.ts](../../apps/next/src/client/passport/atlas/label-points.ts), [small-states.ts](../../apps/next/src/client/passport/atlas/small-states.ts)) — generated by `scripts/generate-atlas-points.mjs`, never edited by hand, from Natural Earth 10m admin-0 label points pinned at commit `ca96624a56bd078437bca8184e78163e5039ad19` of `nvkelso/natural-earth-vector` (`geojson/ne_10m_admin_0_label_points.geojson`). `LABEL_POINTS` has one `[lon, lat]` per catalog country that the 110m polygons draw (171 placed; EH, PS and SS have no point). `SMALL_STATE_POINTS` covers catalog countries the 110m polygons do not draw (72 placed, 0 unplaced).
- **`EDGE_ZOOM` and `EDGE_LON`** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — without world copies the antimeridian is the canvas edge at world scale, so names centred near it (Fiji, New Zealand) would run off the map. Below zoom 3, names beyond 160° hang inward from their point.
- **World cover taps** ([map.tsx](../../apps/next/src/client/passport/atlas/map.tsx)) — the world cover is read-only when other pages exist: a tap on a marked country turns to its region's page. With nothing marked the cover is the only page, so it takes the first sticker.

### Atlas sticker and quick visit

- **Following the camera** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx), [sticker.css](../../apps/next/src/client/passport/atlas/sticker.css)) — the sticker is drawn in screen pixels at the last React render. The map is flat Mercator with bearing and pitch locked, so a camera move is exactly one translate and scale of that drawing. Each `move` writes it synchronously, never through rAF or React state: MapLibre's own render rAF is already queued ahead of any of ours, and a re-queued one is cancelled before it runs during a drag. `moveend` re-renders once to re-project crisply. The camera moves the two follow wrappers with one transform per `move`, with origin at the overlay's corner.
- **Sticker styling** ([sticker.css](../../apps/next/src/client/passport/atlas/sticker.css)) — the stylesheet only styles; geometry comes inline from the overlay and nothing in it may move a path. The lift uses a CSS transition, not keyframes, so a close during the lift turns back from where it currently is.
- **Lift shadow** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx), [sticker.css](../../apps/next/src/client/passport/atlas/sticker.css)) — the shadow is its own composited layer, blurred once and then only faded, so closing and the crossing do not re-blur; the camera moves its wrapper.
- **Baggage tag** ([sticker.css](../../apps/next/src/client/passport/atlas/sticker.css)) — the tag is split into parts (wrapper in screen space, swinging tag, head with the ISO3 code, tear-off stubs) so a tear can fade the rest while the torn stub falls. It is hidden while the camera moves and returns on `moveend`, because it hangs in screen space. Its mask repeats instead of clipping, so a stub falling below the tag is not cut off (the next notch is 120px lower).
- **`swingTag`** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — animates a full transform string about the eyelet, so WAAPI runs the swing off the main thread.
- **`screenRings`** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — keeps the country's largest polygon and the parts near it, so far-flung islands do not stretch the outline.
- **Unmount mid-crossing** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — a view switch or filter during a crossing announces the pending landing, so the write goes on and its toast and Undo still arrive.
- **Press state** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — cleared when the lifted sticker changes, because its stub may unmount before `pointerup` arrives.
- **Closing a lifted sticker** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — a MapLibre `movestart` carrying an `originalEvent` (the member's pan, wheel or pinch) closes it like a popover. The lift's own flight and the zoom buttons carry none. A crossing in flight is never interrupted; close only acts on a lifted sticker.
- **Sticker animation call** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx), [sticker.test.tsx](../../apps/next/src/client/passport/atlas/sticker.test.tsx)) — motion's `animate` is called with a single start value and keyframes, because an array first argument means a list of subjects and never calls `onUpdate` or `onComplete`. The test's mock handles only that single-value form and forwards other subjects (the toast's motion values) to the real library. jsdom has no `PointerEvent`, so the test installs one; without it `fireEvent` drops `pointerId`, `button` and coordinates.
- **Pull is not a tap** ([sticker.tsx](../../apps/next/src/client/passport/atlas/sticker.tsx)) — `suppressClick` is set for one tick after a pulled stub is released, so a pull never also counts as a tap.
- **`useRecordVisit`** ([quick-visit.ts](../../apps/next/src/client/passport/atlas/quick-visit.ts)) — owner-only, held by the page so it outlives the atlas. It starts the POST at the tear, marks the country seen so the cards never replay it, refreshes the passport on the ack and offers Undo. Undo waits for a POST still in flight (and a year edit after it), then deletes exactly the row it created. A later tear of the same country retires an earlier write's Retry. Try again repeats the write with the same visit id, so a write whose answer was lost is not recorded twice. Year edits run one after another on the created row, so Undo's delete is the last word; a queued edit is dropped when the session is gone (signed out or account switched) so it never writes for a stale session.
- **Recorded toast** ([recorded-toast.tsx](../../apps/next/src/client/passport/atlas/recorded-toast.tsx)) — holds its own close timer while the year wheel is open and releases it on unmount. It relies on the toast keeping `controls` identity stable.
- **Sea remark** ([sea-remark.ts](../../apps/next/src/client/passport/atlas/sea-remark.ts)) — the toast's description under a factual outcome line; it never replaces the outcome. The `LINES` are interchangeable and chosen per country code, so the same country always gets the same line. Russian names stay nominative.

### Year drum and round-up

- **Position model** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx)) — the drum is open state only; the recorded toast's year pill and the round-up rows own the closed state and the commit (spec: stamp-date). Position is a float in rows. Pointer moves write it straight to the list's transform, never through React. A release projects the finger's rest and settles on the nearest row with a critically damped spring handed the release velocity; a grab during that spring continues from where the drum is.
- **`criticalSpring`** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx)) — a physical spring is used because a time-defined one would drop the release velocity.
- **`DECELERATION`** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx)) — Apple's scroll deceleration, 0.998: a release coasts `v · 0.998 / (1 − 0.998)` ahead.
- **Release velocity** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx)) — the release itself is the last sample and only the last 100 ms count, so a drag held still before letting go has no speed left.
- **Commit and dismissal** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx)) — a pointer press outside the drum commits, as does Tab leaving it; blur commits only when focus moves to another control, since a window blur has no destination and keeps the drum. A press on the trigger also closes it, and the click it is about to fire is swallowed at the trigger, so the opener's handler never reopens the drum. The swallowing listener is removed after 600 ms, because a press that never becomes a click (dragged away) must not eat a later one.
- **Wheel, touch, propagation** ([year-drum.tsx](../../apps/next/src/client/passport/year-drum.tsx), [year-drum.css](../../apps/next/src/client/passport/year-drum.css)) — the wheel steps one row per notch (a trackpad's stream is coalesced to one step per `WHEEL_STEP_PX`, 40). A touch on the drum is never an enclosing sheet's drag, which needs non-passive native listeners. The drum stops `pointerdown` propagation so the sheet around it never sees the press, and sets `touch-action: none` so neither the page nor the sheet scrolls under the finger.
- **Undated round-up** ([undated-sheet.tsx](../../apps/next/src/client/passport/undated-sheet.tsx)) — the list is a snapshot taken on open, so a row whose year was just set stays under the finger and shows it; the page refreshes once, when the sheet closes. Per row, writes run one after another and only the latest edit may speak for the row when one fails; an older failure must not overwrite what a newer edit shows. A 409 conflict means the row changed elsewhere, so the list refreshes on close either way. Closing with a year still saving refreshes once every write has settled, not before. Escape closes the open drum first, so the sheet needs a second press.

### Country sheet and revisions

- **Catalog gate and legacy way** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — only catalog countries get a sheet, because its write actions would otherwise press a code with no region or outline. A legacy land visit has no segment of its own; its way stays `land` and the stored way is left out of the PATCH until a way is picked.
- **Draft and selection** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — the `draft` ref holds what the fields hold now, so a save that resolves after the member kept typing clears only fields still equal to the submitted text, on the submitted country (both fields stay editable during the save). A closed sheet keeps its last country, so a save that completes while it is closed still clears the saved draft. Each move to a different country bumps `selection`: an operation, and anything it does on completion, belongs to the selection it started in, so a return to the same country does not hand it newer state. After a save, a draft typed during it keeps the form open.
- **Detail revision refetch** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — a write can read the detail before its publication lands, and the later page refresh only updates the collection. Once the collection's `publishedRevision` is newer than the detail's, the collection states the country's status and the detail reloads once per revision.
- **Failure versus pending** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — C3 keeps failure apart from pending (`last_error`): a failed derivation is an error with a retry, not "preparing".
- **`hide`** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — hiding is presentation only (`PUT /api/passport/hidden/:cc`): records and statistics stay. There is no confirm; Undo is the net.
- **Form lifecycle** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — the projection leaves first/last NULL for land/sea-only countries, so their visit years date the chronology. Adding is the whole job for a country outside the passport; otherwise the record comes first and the form waits. An edit whose visit left the refetched list (deleted elsewhere) is over: the form follows the list. Add visit unmounts as the form opens so focus lands on the form's first choice, and closing from inside hands focus back.
- **Delete dialog** ([country-sheet.tsx](../../apps/next/src/client/passport/country-sheet.tsx)) — cancelling returns focus to Delete visit (the opener); after a delete the form has closed, so Add visit takes focus. `removalCopy` states exactly what `DELETE /api/passport/claims/:cc` does: the claim and every land/sea visit go, flights stay.
- **Four ways control** ([passport.css](../../apps/next/src/client/passport/passport.css)) — the four ways stay one row as a segmented control; cells trim their padding, and at 320px a long label («На машине») wraps inside its own cell instead of pushing a segment to a second row.

### Stamps

- **Stamp cards grid** ([passport.css](../../apps/next/src/client/passport/passport.css)) — columns follow the container: two up from a 288px container, one when narrow or when text is enlarged (the minimum is in `rem`). Space groups the content; cards carry no rules (DESIGN.md).
- **Stamp hero CSS** ([passport.css](../../apps/next/src/client/passport/passport.css)) — while `html[data-stamp-hero]` is set the card's and the sheet's stamps share a per-country view-transition name so the stamp grows into the sheet illustration. The page under it must not crossfade, and the sheet fades in place instead of sliding, because a slide would put the stamp's target off screen when the new state is captured.
- **`waitForSheetStamp`** ([stamp-hero.ts](../../apps/next/src/client/passport/stamp-hero.ts)) — watches mutations, not frames: Chrome runs no `requestAnimationFrame` while a view transition's update callback is pending, so a rAF poll would stall until the browser's ~4 s transition timeout.
- **`openWithStampHero`** ([stamp-hero.ts](../../apps/next/src/client/passport/stamp-hero.ts)) — opens the sheet as a same-document view transition. Both stamps carry one per-country name only while it runs, and the card's name is dropped before the new state is captured (the card stays in the page behind the sheet, and two elements may not share a name). `html[data-stamp-hero]` scopes the transition's CSS so other view transitions never see it. It returns false, having done nothing, when the API is missing, the tab is hidden, a theme switch is running, the user prefers reduced motion or the card has no stamp; the caller then opens the sheet at once.

### Avatar and badges

- **`INKS`, `avatarFace`** ([avatar.tsx](../../apps/next/src/client/profile/avatar.tsx)) — avatar inks are theme-aware passport stamp inks at 4.5:1 on `--surface`, independent of the accent. A member's character is their pick, else one derived from the id, so a rename never changes it. A negative per-id animation delay spreads blinks, so a list of faces never blinks in unison.
- **Founding crew badge** ([founding-crew.tsx](../../apps/next/src/client/profile/founding-crew.tsx), [copy.ts](../../apps/next/src/client/profile/ladders/copy.ts)) — the name stays English in both locales (owner decision, 12 October 2026).
- **Founding crew stub (FC-9)** ([founding-crew.css](../../apps/next/src/client/profile/founding-crew.css)) — the paper stub mask sits on the torn stub and on the trigger's `::before`, so the button's hit area stays unclipped. Mask layers, top first: perforation holes (xor), top notch half, bottom notch half. The house hover fill would show through the holes and notches, so only `::before` tints on hover.
- **Badge toasts** ([badge-notifications.tsx](../../apps/next/src/client/profile/badge-notifications.tsx), [unseen.ts](../../apps/next/src/client/profile/unseen.ts)) — hidden rows (legacy, cities) never toast. `unseenBadges` treats the first successful snapshot on a device as a baseline, and later deltas are one immutable batch. Each scope keeps its own baseline: the toast (`badge-events`) and the profile cabinet's unboxing (`badge-cabinet`) see a badge independently.
- **Cabinet** ([cabinet.tsx](../../apps/next/src/client/profile/ladders/cabinet.tsx)) — earned achievements only: one tile per ladder at its highest rung, plus Founding crew. On the owner's page, tiles whose ladder gained a rung since the last visit press into their slots once, using the cabinet's own per-owner baseline separate from the toast; a first-ever visit only records the baseline. The cabinet keeps the open tile's key, not the tile, so an award that lands while the sheet is open shows the new rung.
- **Ladder model** ([ladders/model.ts](../../apps/next/src/client/profile/ladders/model.ts)) — pure and client-safe. Legacy badge rows 1–18, `cities-*` and unknown codes are hidden at read time (`ladderOf`, `visibleBadges`), not deleted in D1, so this filter must stay in the client.
- **Headline numbers** ([profile.css](../../apps/next/src/client/profile/profile.css)) — Commissioner with tabular figures, because Paper Mono splits numbers like "412,580" at the comma.

### Ladder figures

- **Hero faces** ([ladders.css](../../apps/next/src/client/profile/ladders/ladders.css)) — in the dark theme `.ladder-figure` faces use `--iso-top` and `--iso-front` one step off the sheet's `--surface`, or the hero reads as a wireframe. Ladders only; the overview figures keep theirs.
- **`LadderFigureBuilder` contract** ([figures/types.ts](../../apps/next/src/client/profile/ladders/figures/types.ts)) — draws one ladder's object at one rung at scale `k` (1 iso unit = `k` CSS px) with the app's iso Scene. `figures.test.ts` checks, for every rung and both lods: exactly one group with `part: 'lit'` holding the only accent part (the thing that changed at this rung), drawn with `s.lit` or accent paints, with no accent paint outside it; no text nodes except the Flights top rung's initials (inside the tail, not in `lit`); deterministic output (no `Math.random`, speckle seeded from a fixed hash); geometry in world units, never CSS px, with the caller picking `k` through `fitBox`.
- **Measuring probes** ([parts.ts](../../apps/next/src/client/profile/ladders/figures/parts.ts), [airlines.ts](../../apps/next/src/client/profile/ladders/figures/airlines.ts)) — a Scene measuring for `fitBox` needs only bounds, and every tone layer sits inside a silhouette, so `lathe` and airlines `post` draw only the silhouettes. `Scene.str` returns `''` only while measuring.
- **`lathe`** ([parts.ts](../../apps/next/src/client/profile/ladders/figures/parts.ts)) — the silhouette is each segment's convex hull stroked at twice the width and then filled over as one area, so only the outer half of the stroke shows and internal joins vanish. Tone is drawn as nested regions of equal light, each adding one step of the next tone. The distance figure's chocolate segments use the same hull technique, which also hides the joins along the base web ([distance.ts](../../apps/next/src/client/profile/ladders/figures/distance.ts)).
- **`spline`** ([parts.ts](../../apps/next/src/client/profile/ladders/figures/parts.ts)) — monotone cubic (Fritsch–Carlson) interpolation, so it never overshoots between rows and its slope is continuous, which keeps lathe shading free of steps at the rows. Values clamp to the table's ends.
- **`stamp`** ([parts.ts](../../apps/next/src/client/profile/ladders/figures/parts.ts)) — draws a part once on a scratch Scene at the same scale and replays the recorded `poly`, `poly2`, `area`, `line` and `segs` calls through `s` with every point shifted (the projection is linear), for many identical parts. Bounds, shadows and fit probes work as if each copy were drawn from scratch, at a fraction of the cost. `draw` must not use `glow`, `group` or `text`.
- **Airline `post`** ([airlines.ts](../../apps/next/src/client/profile/ladders/figures/airlines.ts)) — every part of a post is an upright convex turned part, so each is one hull for its silhouette, nested tone bands round the light's azimuth on its walls, and nested crown layers on its domes. This costs a fraction of a general lathe, which matters with twenty-odd posts.
- **Flights `jet`** ([flights.ts](../../apps/next/src/client/profile/ladders/figures/flights.ts)) — the near gear, near engine and both intakes (the lit group) are painted before the fuselage, because the far intake sits behind the nose on screen. Painter's order is load-bearing.

### Account settings and deletion

- **`cell`** ([ground-export.ts](../../apps/next/src/client/account/ground-export.ts)) — the ground-journeys CSV prefixes an apostrophe when a value starts (after whitespace) with `=`, `+`, `@` or `-`, so untrusted notes stay inert in spreadsheet software.
- **`downloadSettingsData`** ([settings-data.ts](../../apps/next/src/client/account/settings-data.ts)) — returns the real downloaded row count, so an empty response never consumes the daily export allowance.
- **Reset token handoff** ([reset-password-form.tsx](../../apps/next/src/client/account/reset-password-form.tsx)) — only the early bootstrap reads and scrubs the URL fragment, handing the one-time token over in `window.__kuukiResetToken`. The form keeps it in a ref in its own mounted memory, so the fragment is never read again. React may replay the effect, and a replay must not discard a captured token: `captured.current` is filled only when undefined. The token must match `/^[A-Za-z0-9_-]{43}$/`.
- **Settings save payload** ([settings-form.tsx](../../apps/next/src/client/account/settings-form.tsx)) — the server is authoritative on save, so an unreachable username availability check counts as ok and must not block the member. Without a chosen address `username` is omitted and the server derives one from the name on the first save. `display_name` is sent only when changed, so a name saved before the 40-character limit cannot block other edits. `passport_publication` is sent only when the member changed it, so a save can never silently widen or narrow publication (ADR 0007).
- **`useSettingsGuard`** ([settings-guard.tsx](../../apps/next/src/client/account/settings-guard.tsx)) — Settings owns this guard. It preserves Next's history payload and restores a traversal before asking, so Back or Forward while dirty or saving does not corrupt the App Router history.
- **Settings dialogs** ([settings-form.tsx](../../apps/next/src/client/account/settings-form.tsx)) — a dialog opened from Settings has its own status line and must not inherit the form's ("Saved.").

## Consequences

- Changing any behaviour listed above means updating this ADR in the same change; the symbol named in each entry is the lookup key.
- Where an entry cites a browser or library quirk (Safari button focus, Chrome rAF during view transitions, MapLibre `match` and `movestart`, jsdom `PointerEvent`), removing the workaround needs a re-check against the current version, not just a passing test.
- Entries that mirror ADR 0001 and ADR 0007 rules are consequences of those ADRs; a change there propagates here.
