# Тестовый пользователь

Созданы два аккаунта: локальный ниже и `atlas-ui-20261004@example.test` в [опубликованном приложении](https://kuuki.marchstudio.uk/?mode=signin). В каждом 69 отобранных рейсов. Пароль опубликованного аккаунта сохранён отдельно от Git в приватном файле доступа. [Проверка опубликованного аккаунта](production-check.json) подтверждает вход из нового браузера и число рейсов.

Файл доступа на этой машине: `~/Library/Application Support/Kuuki/user-journey-atlas/test-user.json`. В нём находятся данные для входа в оба аккаунта. [Проверка восстановления локальной базы](../verification.json) фиксирует создание 69 рейсов и повторный запуск без дублей.

В опубликованной версии обнаружено, что гостевой API возвращает профиль даже при `is_public=false`. У тестового аккаунта убрано публичное имя; прежняя ссылка проверена гостем и возвращает 404. Вход на дашборд работает, участие в рейтингах отключено. Этот обход не исправляет серверную проверку приватности. Добавление нового публичного имени снова создаст ссылку на профиль; нужна отдельная правка опубликованной версии.

Аккаунт существует в изолированной локальной базе по адресу http://localhost:8799. Это временная fixture. После её остановки база удаляется; команды ниже создают аккаунт и данные заново.

| Поле | Значение |
| --- | --- |
| Email | `atlas-user@example.test` |
| Пароль только для локальной fixture | `Atlas-demo-2026!` |
| Username | `test-traveler` |
| Имя | Тестовый путешественник |
| Профиль | `/fly/test-traveler` |
| Исходных записей | 122 |
| Загружено рейсов | 69 |
| Требуют разбора | 27 |
| Исключено | 26 |

Данные взяты из приложенного пользователем текста. [Результат разбора](recognition-result.json) сохраняет каждую исходную запись, решение и причину. Отменённые, неоплаченные, заменённые рейсы и чужие бронирования исключены. Неоднозначный аэропорт, конфликт времени, спорный возврат и неполная запись требуют разбора. Допуск в тестовый набор не доказывает, что рейс был совершён.

[Промпт для распознавания](recognition-prompt.md) можно передать модели вместе с [исходным текстом](input.txt). Этот набор подготовлен локальным разбором текста; ответ Gemini в fixture подменён. Автоматический поиск самолёта отключён для этих 69 записей, потому что источник не указывает модели самолётов. Время нормализовано по справочнику часовых поясов проекта. Координаты ROV взяты из текущего справочника проекта; исторический аэропорт для ранних рейсов отдельно не устанавливался.

Из корня репозитория собери web и API, затем запусти сервер в отдельном терминале:

```sh
pnpm --filter @kuuki/web build
pnpm build:api
python3 docs/user-journeys/tools/run-fixture.py
```

После сообщения `Synthetic fixture ready` во втором терминале:

```sh
python3 docs/user-journeys/tools/seed-test-user.py
```

Скрипт заполняет полный справочник аэропортов проекта в disposable D1. Он замораживает файлы сборки, поэтому параллельная пересборка приложения не ломает обход. Для API используются обычные авторизация, CSRF и ключи идемпотентности. Повторный запуск seed сохраняет те же рейсы без дублей. Другие тестовые аккаунты и страницы остаются доступны. Внешние вызовы серверного провайдера подменены или запрещены, облачные ресурсы не используются.
