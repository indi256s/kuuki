# Промпт для распознавания истории перелётов

Используй этот промпт вместе с [input.txt](input.txt). Он подходит для проверки распознавания текста. Извлечение текста из PDF или изображения выполняется перед этим шагом.

```text
Разбери приложенную историю перелётов. Верни только JSON с массивами flights, review и excluded. Обработай каждую исходную запись и сохрани её номер строки и исходный текст. Заголовки разделов не являются перелётами.

Для каждой записи извлеки date, origin, destination, airline_iata, flight_number, departure_time, arrival_time, arrival_date, aircraft_icao, passenger_scope, booking_status, source_notes, confidence и reasons. Используй null для неизвестных полей. Дата вылета имеет формат YYYY-MM-DD; время HH:MM означает местное время аэропорта. Явную дату прилёта на следующий день сохрани отдельно.

flight_number содержит номер без двухсимвольного кода авиакомпании. Например, S767 означает airline_iata=S7, flight_number=67; PC315 означает PC и 315; 3F584 означает 3F и 584. Не придумывай авиакомпанию или самолёт, если их нет в тексте.

Используй явные IATA-коды. Однозначные названия можно нормализовать: Kaliningrad=KGD, Yerevan=EVN, Tbilisi=TBS, Istanbul Sabiha Gokcen=SAW, Krasnodar=KRR, Rostov-on-Don=ROV. Сохрани исходное название аэропорта и исторические пометки. Moscow не определяет конкретный аэропорт; такую запись помести в review. Не подменяй исторические аэропорты современными без явного указания в источнике.

В flights помести записи основного раздела с полной датой, однозначными аэропортами и без явных пометок об отмене, чужом пассажире или конфликте. Принадлежность основному разделу означает пригодность для тестового набора, а не доказательство совершённого перелёта.

В excluded помести canceled, canceled/refunded, unpaid reservation, superseded и записи раздела Other-passenger bookings or conflicting ownership. Сохрани причину исключения. Замена рейса является отдельной записью; старый superseded рейс не добавляй в flights.

В review помести неполные даты или маршруты, time conflict, conflicting sequence, unresolved, travel mode unconfirmed, possible refund и несовпадение времени в разных документах. Сохрани все варианты и пометки. Не разрешай конфликт догадкой. Schedule updated само по себе не является отменой; используй последнюю явно указанную версию и сохрани пометку об изменении.

Не объединяй разные рейсы в один и не удаляй похожую запись без объяснения. Различай дубль, пересадку и заменённое бронирование. Проверь итог: число записей flights + review + excluded должно совпадать с числом исходных записей.

confidence оценивает точность извлечения полей, а не вероятность того, что пассажир действительно летел. reasons объясняет неоднозначности и решения по включению. Не вычисляй длительность простым вычитанием местных часов в разных часовых поясах.
```

Локальная fixture подменяет ответы провайдера распознавания. [recognition-result.json](recognition-result.json) подготовлен консервативным разбором текста и справочником проекта. Это не результат вызова Gemini. Для проверки настоящего распознавания отправь этот промпт и исходный текст выбранной модели отдельно.
