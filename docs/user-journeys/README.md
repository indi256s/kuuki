## Как агенту найти экран в историческом атласе

1. Определи pathname, состояние авторизации и ширину окна.
2. Найди состояния с этим маршрутом в `manifest.json`. Параметр `?mode=signin` и режимы диалогов важны: одному URL соответствует несколько экранов.
3. Сопоставь `recognition` и текст из файла `snapshot` с видимыми заголовками, кнопками и полями.
4. Открой `screenshot` выбранного состояния. `preconditions` объясняет, какие данные нужны; `actions` описывает доступные переходы.
5. Для последовательности действий открой `flows.md` соответствующего раздела. Проверяй `status` и замечания перед выводами о доступности функции.

6. Проверь поле `audit` выбранного состояния: там известные дефекты экрана со ссылками на [отчёт аудита](2026-10-03/audit/AUDIT.md). Пустое поле не значит, что дефектов нет: системные находки без снимков есть только в отчёте.

`captured` означает, что экран действительно открыт в браузере. `simulated` означает, что условие специально смоделировано; причина должна быть указана. `source-only` означает, что ветка найдена в коде, но снимка нет. Тестовые данные и подменённый ответ распознавания отдельно указаны в описании окружения и состояния.

Скриншот фиксирует состояние на момент съёмки. Карта покрывает различимые состояния и переходы, а не бесконечные комбинации введённых данных, языков, размеров окна и фильтров. Пробелы перечислены в карте. Для проверки опубликованной версии нужны отдельная съёмка и её версия сборки.

## Обновление

Сохрани следующую съёмку в новой датированной папке с теми же полями манифеста. Каждый раздел содержит `manifest.json`, `flows.md` и `images/` с PNG и текстовыми снимками. Стабильный ID состояния должен описывать экран и состояние, а не порядковый номер скриншота.

После правки исторических разделов из корня репозитория:

```sh
python3 docs/user-journeys/tools/build-atlas.py
```

Команда проверяет ссылки, PNG и уникальность ID, затем собирает общую карту, JSON и галерею. Если есть `audit/findings.json`, она проверяет ID состояний в находках, добавляет поле `audit` состояниям, раздел аудита в `MAP.md`, бейджи в галерею, генерирует `audit/AUDIT.md` и блок между `<!-- audit:start -->` и `<!-- audit:end -->` в конце каждого `flows.md`. Правь `findings.json`, а не сгенерированный Markdown; после исправления удали или обнови находку и пересобери атлас. Историческое локальное наполнение описано в инструкциях тестового пользователя, но прежний Vite fixture больше не запускается из этого дерева. Для новой съёмки создай новую датированную папку и проверь маршруты текущего Next приложения.
