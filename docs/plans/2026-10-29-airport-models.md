Goal: Добавить в Kuuki большой интерактивный просмотр реальных аэропортов с входом из Обзора, изучением объектов, точной личной историей и сравнением в одном масштабе. Первая поставка — TBS и BER; добавление следующего поддержанного аэропорта не требует ветки в коде просмотра.

## Принятые решения и проверенные ограничения

### Граница первой поставки

1. Подготовить две принятые модели: TBS/UGTB, boundary `relation/967676`; BER/EDDB, boundary `way/859790021`. Связь IATA/ICAO/OSM проверяется явно, а не определяется первым объектом в ответе.
2. `/airports/TBS` и `/airports/BER` — приватные member routes. Заглавный IATA каноничен; синтаксически допустимый, но неподдержанный код показывает member-only not-found с возвратом. Превью и геометрия не содержат owner ID, рейсов или производных личных фактов.
3. Модель занимает экран. Header содержит возврат, сравнение и историю; у сцены доступны объекты, слои, масштаб и исходный ракурс. Компьютер: одна контекстная панель поверх сцены. Телефон: та же информация в нижней панели/Sheet, без скрытия основных controls. Открытие панелей не меняет камеру или metres-per-pixel.
4. История, список объектов и сведения об объекте используют одну панель. При выборе объекта из истории доступно «К перелётам» с сохранением выборки/прокрутки. Акцент в сцене обозначает выбор, остальные стоянки/контуры нейтральны.
5. Сравнение использует одинаковый горизонтальный масштаб, север сверху, два плоских плана. Для единственного доступного эталона — прямое «Сравнить с BER». При нескольких — picker: сначала доступные модели аэропортов из текущей выборки, по числу рейсов; остальные модели отдельно. Высоты и отношения площадей не сравниваются.
6. В полях модели явно различаются OSM-значение, оценка по этажности и визуальное допущение. Отсутствующие свойства не превращаются в факты. Современная схема не утверждает, какой аэропорт или полоса были на дату старого перелёта.
7. Начальная камера совпадает с подготовленным превью для соответствующей ширины. При загрузке/ошибке/отсутствии WebGL превью остаётся; история и доступные текстовые сведения не блокируются. Автовращения и постоянного render loop в покое нет.

### Production-подход к геометрии и зависимостям

Выбран настоящий 3D renderer, потому что нужны свободный ракурс, корректное перекрытие зданий и выбор объектов на крупных планах. SVG-макет подтверждает композицию, но не заменяет depth/picking/render lifecycle. Three.js подключается из npm как ES modules; без React Three Fiber, legacy CDN globals, textures, shadows и post-processing. Версия и соответствующие types фиксируются в W2-R по проверенному release; конкретный номер не выдумывается из версии r128 референса. [WebGLRenderer использует WebGL2](https://threejs.org/docs/pages/WebGLRenderer.html); [Shape поддерживает holes](https://threejs.org/docs/pages/Shape.html), [ExtrudeGeometry — объём из Shape](https://threejs.org/docs/pages/ExtrudeGeometry.html).

Подготовка использует `proj4` и `polygon-clipping` только как dev dependencies. `polygon-clipping` выполняет boolean difference непокрытого объёма родительского здания и пересекающихся частей; это сохраняет геометрию без двойной экструзии и самописных polygon booleans. Projection: WGS84 → локальная UTM zone, выбираемая по центру аэропорта, затем вычитание общего projected origin. Для первых двух зон — EPSG:32638 и EPSG:32633 соответственно. Хранить CRS/origin; не смешивать градусы, условные SVG-единицы и метры. Новый аэропорт вне поддержанной области/точности отвергается подготовкой с диагностикой. [Proj4js документирует transformations, оси lon/lat и UTM definitions](https://proj4js.org/).

Права на авторский код референса не установлены в сохранённых материалах. По умолчанию пишем собственные normalization/viewer modules по требованиям и OSM; извлечение/исполнение авторского JS в production tooling не используется. Если исполнитель установит право повторного использования, это отдельная запись происхождения, а не предположение. Three.js имеет [MIT license](https://github.com/mrdoob/three.js/blob/dev/LICENSE), что не лицензирует код артефакта. Подготовленные геоданные распространяются отдельно как ODbL derivative data: attribution, ссылка на лицензию и доступные исходные/нормализованные данные; личная история в этот набор не входит. Основание: [OSM copyright](https://www.openstreetmap.org/copyright), [OSMF guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines).

### Модель и доставка

```ts
type Measure = {
  metres: number
  source: 'osm' | 'levels' | 'default' | 'geometry'
  raw?: string
}
type PolygonM = { outer: [number, number][]; holes: [number, number][][] }
type AirportModelV1 = {
  schemaVersion: 1
  iata: string
  icao: string
  revision: string // hash canonical preimage; revision/path-hash fields excluded
  projection: { crs: string; origin: [number, number] }
  boundsM: [number, number, number, number]
  boundary: PolygonM[]
  features: AirportFeature[] // discriminated surface/line/building/point types
  cameras: { desktop: CameraPose; mobile: CameraPose }
  provenance: SourceProvenance
}
```

`AirportFeature` имеет стабильный `osm:type/id` плюс subpart identity, kind, безопасные plain-text labels, геометрию в метрах, только имеющиеся свойства и source-qualified размеры. Parts имеют parent/minHeight; `volumeSlices` сохраняет неперекрывающиеся остатки по minHeightM/heightM при исходном addressable footprint; вычитание parts учитывает вертикальные интервалы, semantic non-part replacement и строгий total order не создают floating caps/cycles, ВПП — physical-runway identity и её направления. `CameraPose` задаёт targetM, azimuth, elevation и verticalSpanM; fit при открытии детерминирован, не зависит от истории пользователя. Масштаб высот по умолчанию 1.

Договорка осей: planar coordinates — `[eastM,northM]`, world Three — `(eastM,heightM,-northM)`, углы camera pose в радианах, `verticalSpanM` — полная видимая высота orthographic frustum. Preview builder использует ту же чистую projection convention из `geometry.ts`; совпадение контрольных projected points проверяется отдельно от внешнего вида.

- `scripts/airport-models/sources/` — небольшие воспроизводимые source extracts TBS/BER из официальных сохранённых OSM bbox, identity/config и provenance. Исходный 27 MB BER bbox не обязан попадать в приложение или Git; extract должен содержать все node/member dependencies для повторной нормализации.
- `apps/next/src/lib/airport-models/{model,geometry,scope}.ts` — чистые контракты/расчёты, пригодные для Node и браузера; без React/server imports. Scope использует единую shared filter schema.
- `apps/next/src/lib/airport-models/catalog.generated.ts` — небольшой каталог принятых моделей и точный allowlist ресурсов, пригодный для Worker. Он не импортирует JSON геометрии или Three.js.
- `apps/next/public/airport-models/<hash>/` — `model.json`, `plan.json`, `preview-desktop-{light,dark}.svg`, `preview-mobile-{light,dark}.svg`, `provenance.json` и attribution/licence metadata. `plan.json` произведён из той же нормализованной геометрии и содержит только необходимые для сравнения плоские объекты.
- Хэш учитывает source, generator/schema version, конфигурацию упрощения, projection, estimates, камеры и canonical output data без самих revision/hash-path fields. Сначала вычисляется hash preimage, затем revision подставляется в JSON/пути: циклического хэширования собственного hash нет. Preview и интерактивная сцена используют одну camera convention и projected extents. Источник данных имеет собственные `fetchedAt`/`osmTimestamp` (неизвестное значение — `null`); момент подготовки extract хранится отдельно и не подменяет время получения/состояния OSM. BER timestamp не копируется в TBS.
- Ресурсы готовятся явной офлайн-командой. Обычные `next:build` и просмотр не обращаются к Overpass, Nominatim или OSM API. Refresh — новый extract и новый hash после проверки, старые immutable outputs не перезаписываются.

### Scope, история и URL

Member page: `/airports/[iata]?scope=<versioned-filter>&back=<return-token>&compare=<iata>`. Только `scope` задаёт наследуемую выборку; `back` — непрозрачный токен локального UI-состояния, не путь редиректа. Query содержит filter values, но не owner ID, flight IDs или flight records. `compare` не изменяет основной аэропорт.

- `scope` — canonical base64url UTF-8 JSON `{v:1, filter: OverviewFilter}`. Использовать ту же strict schema, что prefs, с transport bounds: decoded JSON ≤8 KiB, type/value checks и запрет неизвестных полей. Нельзя молча удалить неподдержанный facet или заменить ошибочный scope всей историей. Некорректный/слишком большой scope — явная ошибка выборки с действием «Вся история»; географический просмотр остаётся доступен. Вход из Обзора предварительно проверяет transport bound и сообщает проблему без потери его состояния.
- Нет `scope` — прямое независимое открытие; история по запросу сразу относится ко всем завершённым рейсам этого аэропорта. Это не чтение текущих persisted Overview prefs.
- Переход «Вся история» убирает все facets/period только локально для истории аэропорта. Вернуться к исходной выборке можно без её повторного получения из Обзора. Сравнение и внешний Обзор не меняются.
- Новая API route: `GET /api/me/airports/[iata]/history?owner=<ownerId>&scope=<codec>&cursor=<opaque>`. Gate по текущей identity и обязательному owner match до DB read; существующий код ошибки `OWNER_CHANGED` для несовпадения. Все ответы приватные/no-store.
- Новый `readAirportHistory`: в одном согласованном DB batch получает raw flights выбранного owner/endpoint, refs, suppression и revision state. Для непустого filter использует вынесенный общий raw-row projection из `overviewData.ts`, затем existing `matches()`, без aggregate rows и без правил фильтрации Journal. Пустой filter использует exact COUNT и SQL keyset LIMIT 51 в том же revision-bearing batch, без чтения refs/suppressions; DTO строится тем же projection.
- Условие: `effectiveTravelScope!=='ground' && (origin===iata || destination===iata) && state!=='upcoming' && matches(rawRow, inheritedFilter, refs)`. Один рейс считается один раз, даже когда оба endpoint совпадают. `awaiting` остаётся явно awaiting, как в Обзоре. В existing `effectiveScope` сохранённый `filter.scope` игнорируется, когда у owner нет ни одного non-cancelled ground journey. Получить эту глобальную presence в том же batch и переиспользовать общий presence-based predicate, выделенный из existing `effectiveScope`; не смотреть только на аэропортовую выборку или выбранный период. Только effective ground даёт пустую flight history. `visits`/legacy counters не превращаются в вымышленные рейсы.
- DTO в `packages/shared/src/airportHistory.ts`: `ownerId`, revision pair, scope fingerprint, `status:'ready'|'scope-updating'`, `total:number|null`, `items[{id,date,origin,destination,airline,flightNumber,state}]`, `nextCursor`, `derivedState`. `ready` имеет точный total; `scope-updating` — `total:null`, не ложный ноль. 50 записей на страницу, date/id descending. Opaque cursor v2 хранит ID anchor; его позиция определяется в том же snapshot без парсинга legacy date labels. Cursor связан с owner, airport, scope fingerprint и revision. Изменение revision — явный stale-cursor ответ и refresh первой страницы, без склеивания разных наборов.
- При pending/error derived state обычная история без evidence-dependent фильтров остаётся читаемой. Если active countries/regions требуют ещё не опубликованных suppressions, ответ сообщает `scope-updating`, а не точный ноль. UI сохраняет предыдущий результат с явным updating/retry состоянием; новая выборка не выдаётся за доказанную до согласованного snapshot.
- History загружается только при открытии панели. Client использует `trackPrivateOperation`, auth generation, AbortController и owner verification; поздний ответ старого аккаунта не публикуется. Отмена пагинации снимает pending flag, сохраняя страницы/cursor; lifecycle invalidation в закрытой панели отмечает snapshot dirty и вызывает refresh при открытии. Отмена/смена scope/identity не очищает модель.

### Возврат и состояние интерфейса

Новая owner-keyed session запись хранит только фильтр и UI snapshot: version, token, source URL из allowlist `/overview`, selected category/airport, mobile chapter, window/sheet scroll, stable opener key. Не сохранять payload, рейсы, DOM refs и arbitrary redirect URL. Хранилище ограничено последними 10 переходами; запись старше 24 часов не используется. Storage exceptions дают безопасный fallback, а не блокируют навигацию.

Перед входом: захватить snapshot → привязать token к **исходной Overview history entry** через namespaced `history.state.kuukiAirportReturn` (version/token/owner, сохраняя все Next fields) → вызвать `flushPrefs()` по существующему паттерну, не полагаясь на успешную запись как на источник filter → обычная Next navigation с каноническим scope. Airport entry получает собственный visit marker: был ли вход из Обзора и какой source entry ему соответствует. Snapshot остаётся источником точного возврата при prefs-save failure. `scope` обеспечивает reload/direct link без session token; отсутствующий/чужой/просроченный `back` даёт `/overview` fallback, без утечки чужой выборки.

При native Back, в том числе после airport reload, Обзор находит snapshot по namespace **своей вернувшейся entry**, а не по исчезнувшему query аэропорта и не по глобальной «последней записи». Явный «Обзор» использует тот же back-переход, если собственный visit marker доказывает источник; иначе выполняет безопасный обычный переход `/overview`. Независимый вход в Обзор без source entry marker snapshot не применяет.

Возврат: восстановить filter/category/reading → дождаться `useMobile()` и relevant chapter/layout → восстановить page/sheet scroll → focus на стабильный opener. Не позволять inactive/adjacent chapter consume snapshot. Один restore attempt имеет cancellation/generation guard; повторная навигация или самостоятельное действие пользователя отменяет его. После успешного restore последующие самостоятельные изменения обновляют/инвалидируют source snapshot, чтобы Forward→Back не откатывал новый выбор к старому; marker остаётся привязан к конкретной history entry до expiry/identity reset. При удалённом аэропорте/изменённой выборке fallback к rankings tile/heading. Session записи очищаются на `kuuki:identity-reset` и после logout; неизвестные поля Next history state сохраняются.

Состояния аэропорта разделяются: `detail(camera,layers,selection,panel,historyScope,scroll)` и `compare(reference)`. Вход в сравнение создаёт ровно один history entry; смена эталона заменяет его. Back сначала выходит из сравнения; прямой URL с `compare` закрывается replace-переходом к detail без выхода с сайта. Возврат восстанавливает detail и focus на compare trigger. Поворот/zoom не создают browser entries.

### W2-R — viewer и сравнение

Owned writes: Область W2-R из execution map; app dependency/lockfile только после W1 transfer. Временная development fixture размещается в `viewer/` и не создаёт публичный user route без gate.

Implementation:

- Обёртка принимает нормализованную модель и controlled camera/layer/selection state; identity, history и маршруты ей не принадлежат. Renderer даёт callbacks ready/error/selection/camera change и освобождает geometries/materials/listeners/context при unmount/retirement.

На телефоне равные ширины, планы друг под другом. Высоты не участвуют, padding не меняет масштаб одного плана отдельно.

Focused proof: Analytic comparison fixtures с разными aspect ratios/размерами доказывают одинаковую длину 1 km на экране и отсутствие independent-fit. Реальные TBS/BER показывают courtyard/parts/depth и корректный picking в compiled browser fixture; JS unit tests не мокают Three так, чтобы мок сам «доказывал» геометрию. Повторные mount/unmount и context-loss проверяют отсутствие активных loops/listeners после disposal.

- Данные/нормализованные sources/licence records должны воспроизводиться без `.scratch` в новом checkout. Макеты/исследование при желании сохраняются как checkout-local input inventory; «файл существует у автора» не считается переносимостью production build.
- Обновить affected docs в том же scoped patch. GLOSSARY/ADR меняются только если появились новые доменные/архитектурные утверждения, а не для отметки просмотра. Handoff отделяет source completion, local checks, release acceptance и deployment.

Focused proof: Полное покрытие success/exclusions, независимый review и final evidence gate ниже. Методом test-audit каждый новый test имеет named contract, credible regression и причину, почему existing coverage его не ловит; без source-string inventories и test-only production seams. OpenClaw-specific команды из общего test-audit skill к Kuuki не относятся: runner берётся из реального package.json.

Accept when: Один immutable scoped candidate проходит все обязательные lanes, review findings закрыты либо явно признаны непокрытыми блокерами, docs/handoff соответствуют кандидату. Ни один gate не означает production deployment.

## Final evidence gate

Identity: Все final lanes проверяют одну immutable scoped patch identity. Чистый owned commit допустим только после отдельного разрешения на коммит. В текущем shared checkout использовать baseline SHA + сохранённый binary-capable owned patch + SHA-256 inventory релевантных новых files/assets; подготовка isolated candidate — по shared-checkout procedure. Нельзя включать чужие hunks или считать branch/status доказательством содержания. Отдельно записать Node/pnpm/Next/Three/proj4 versions, lockfile hash, fixture/browser config, assets/source hashes и имеющиеся waivers. При relevant code change identity и затронутые evidence обновляются.
