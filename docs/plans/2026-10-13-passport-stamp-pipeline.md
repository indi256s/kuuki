# Passport Stamp Pipeline Implementation Plan

Goal: a build-time pipeline that turns per-country JSON recipes into one-ink engraving SVGs (`apps/next/public/stamps/{iso2}.svg`), a `<CountryStamp>` frame component with the Q34 states and motion, a stamp linter in the verify gate, and a dev contact sheet — six reference countries signed off first, then all 246.
Architecture: one engine module in `apps/next/src/lib/stamp-art/` (kit modules, signature parts, frame geometry, inks, renderer, linter) consumed by three callers: the `pnpm generate:stamps` script (writes committed SVGs), the stamp check (lints + drift-checks committed SVGs inside `pnpm verify:cloudflare`), and the dev-only `/dev/stamps` contact sheet (renders recipes live). The frame is inline SVG in `apps/next/src/client/stamps/`; the engraving is a CSS mask whose `background-color` is the country ink.
Success: `pnpm generate:stamps` is deterministic (second run = no diff); the stamp check passes for every committed SVG and fails on a planted out-of-frame, under/over-inked or unknown-module recipe; `/dev/stamps` shows every country in light/dark at 96px and card size with rest, hover, focus, press, pending and new-impression states; owner signs off the six before the rest are generated.
Out of scope: Passport page / country sheet / import integration (the existing `client/signature/stamp.tsx` stays untouched in behaviour), the sheet hero grow (only a stable hook for it), deploy, push, edits to `packages/data/src/countries.json`.
Constraints: AGENTS.md, CODING_STANDARDS.md (Oxfmt single quotes/no semicolons; design tokens only in `apps/next/src/app/styles.css`; `kuuki/design-tokens` lint; RU+EN for every user-visible string), DESIGN.md motion tokens and rules (no ease-in, no `transition: all`, transform/opacity only, reduced motion = opacity only). Motif rules Q38–Q47 (secular, no active religious sites/statues, no active seats of power, no copyrighted modern landmarks, contested territories = neutral nature, no flags/regime/military/food/people). Execution: Opus orchestrator plans, integrates and checks every diff; Sonnet workers (high effort) implement, one at a time; UI/design review by an Opus subagent at high effort; final code review once on GPT-6.1 Sol high via T3 `delegate_task`; subagents stop only servers they started.
Planning basis: spec `/Users/indi256/Documents/kuuki/kuuki/.scratch/passport-profile/spec.md` rounds 6+ (Q29–Q47, motion grammar); `country-semantics/registry.json` (246 rows), `REGISTRY.md`, `SUMMARY.md`, `REVIEW.md`, `BRIEF.md`; motion prototype `stamp-proto/index.html`; Paper p-6-0 "Passport stamps r3 — group A/B" (layout reference only). Repo evidence: `packages/data/src/countries.json` (`stampShape` is only `circle` ×52 / `rectangle` ×194); existing `client/signature/stamp.tsx` (flag-ink `Stamp`, one-shot press memory) and `lib/stamp-ink.ts` + `lib/color.ts` (contrast helpers); `countryNamer` in `client/passport/model.ts` (Intl.DisplayNames RU/EN); dev routes `app/dev/{gallery,overview}/page.tsx` (`notFound()` in production); precedent generator `scripts/generate-concorde.mjs`; `scripts/verify-cloudflare.sh` is the repo's verify gate (there is no `pnpm verify` script); `@resvg/resvg-wasm@2.6.2` is already in `pnpm-lock.yaml` transitively. The worktree has no `node_modules`: run `pnpm install` first.
Owner additions (2026-10-13, round 2): (B1) impression layer — one shared, deterministically generated wear texture (pressure falloff, paper grain, broken edges, ink gaps) applied as a second mask over frame and engraving, offset/rotated per country by hash, pressure side aligned with the rest tilt; press and new impression are opacity crossfades between the worn layer and a full-density layer. Kill test at the W2 sign-off: owner compares impression on/off; it dies if the owner prefers clean or if 96px legibility needs thicker strokes kit-wide. (B2) owner marks on the contact sheet (accept / redo + note), persisted to a committed JSON, so the owner selects per Q35 and notes feed the next W3 batch.
Assumptions (owner can veto): (A1) five frame shapes — `circle`, `oval` (circle family) and `rectangle`, `cut-rect`, `octagon` (rectangle family); the catalog family is kept, the member is picked by a stable hash of the ISO2 and can be overridden in the recipe. (A2) The new component is named `CountryStamp` to avoid colliding with the existing `Stamp`. (A3) Ink palette of 8 named inks with light/dark values, each ≥4.5:1 against `--surface` in its theme (ring text is small type), assigned per recipe; the default is a hash, and countries in one cluster get distinct inks. (A4) `@resvg/resvg-wasm` becomes a direct root devDependency for the linter's 96px raster. (A5) Ring text = `countryNamer(locale)` uppercased + `·` + ISO3, fitted by letter-spacing then font size down to a floor; below the floor the catalog short name is used.
Execution profile: primary=runtime-selected (Opus, medium); workers=sonnet, effort high; reviewers=Opus high (UI/design), gpt-6.1-sol high via codex (final code); exact-profile-attestation=not-requested
Authority update (2026-10-14): owner authorized local main merge while preserving parallel work; delegates use Sol low; full navigation and browser suites are waived. No push or deployment authorized.

Authority evidence: original owner task message of 2026-10-13 (build the pipeline, six first with sign-off, then 246; no integration, deploy, push or landing).

## W1: Engine, starter kit, six recipes, generator, stamp check

Objective: the six reference countries (ME, TH, JP, DE, AM, GE) render from JSON recipes into committed one-ink SVGs, and a check fails on bad output.
Owned writes: `apps/next/src/lib/stamp-art/` (`grid.ts`, `kit/*.ts`, `signatures/*.ts`, `frame.ts`, `inks.ts`, `recipe.ts` (schema + loader), `render.ts`, `impression.ts`, `lint.ts`, `recipes/{iso2}.json`, `registry.json` copied from the root scratch folder), `apps/next/public/stamps/`, `scripts/generate-stamps.ts`, `scripts/check-stamps.ts`, root `package.json` (`generate:stamps`, `check:stamps`, devDep `@resvg/resvg-wasm`), one line in `scripts/verify-cloudflare.sh`.
Implementation:

- Grid 200×200, y down; three stroke weights (`hair`, `line`, `bold`) and up to three solid fills, all one colour (`#000`) because the file is a mask. Modules are pure functions `(box, params) → SvgNode[]` registered by tag; symmetric by default (`mirror: true` draws the left half and reflects it).
- Starter kit = what the six need from the registry, drawn to the base-kit style so W3 extends rather than redraws: `water`, `mountains`, `twin-peak`, `cliff`, `platform`, `steps`, `fortress-wall`, `tower`, `hip`, `gable`, `stilts`, `pagoda-tier`, `curved-eave`, `colonnade`, `pediment`, `triumphal-arch`, `statue`. Signature parts: `kalae-finial` (TH), `kotor-walls` (ME zig-zag wall up the slope), `quadriga` (DE). Verify each silhouette against reference photos before drawing (registry facts are unchecked).
- Recipe JSON: `{ iso2, tier: 'engraved'|'fallback', shape?, ink?, cluster?, layers: [{ module, box:[x,y,w,h], params?, mirror? }], signature?: [{ part, box, params? }] }`, validated with zod (already a dependency); unknown module or part = load error.
- `frame.ts` owns the five shapes (A1): outer path, ring-text path, inner window path and its safe box in grid units — the single source shared by the renderer clip, the linter and the W2 component.
- Renderer clips the engraving to the inner window and writes a minimal, stable SVG (sorted attributes, fixed number precision, no timestamps). Fallback tier writes no file; the component shows frame + ISO3.
- `impression.ts` (B1): generates the shared wear texture deterministically (seeded noise, no `Math.random`) into `apps/next/public/stamps/_impression.svg`, and exposes `impressionTransform(iso2, tilt)` (offset, rotation, pressure side matching the rest tilt) for the component and the linter.
- `lint.ts` (pure, used by the script and a vitest): every node's bbox inside the safe box; module/part tags exist in the kit; raster at 96px via resvg **with the impression applied** → ink coverage within a band (initial 12–45 %, tune on the six and record) and a legibility proxy (at least N connected ink regions larger than 2px², no region of ink fill > X % — tune and record). `check:stamps` = regenerate in memory, byte-compare with committed files (drift), then lint.
  Dependencies: `pnpm install` in the worktree.
  Focused proof: determinism and drift → run `pnpm generate:stamps` twice, `git status` clean after the second; check strength → a vitest in `lib/stamp-art/lint.test.ts` with three planted bad recipes (out of frame, near-empty, unknown module) that must fail, plus the six real recipes that must pass; `pnpm --filter @kuuki/next typecheck`, `pnpm lint`, `pnpm format:check`.
  Accept when: six SVGs committed, check green, planted failures red, and primary has looked at the six SVGs.

## W2: CountryStamp frame, motion, inks, dev contact sheet

Objective: a stamp that behaves per Q34 and a contact sheet the owner can judge.
Owned writes: `apps/next/src/client/stamps/` (`country-stamp.tsx`, `country-stamp.css`, tests), `apps/next/src/app/dev/stamps/` (`page.tsx` with production `notFound()`, `contact-sheet.tsx`, css), the `--stamp-ink-*` light/dark block in `apps/next/src/app/styles.css`.
Implementation:

- Props: `iso2`, `locale`, `status: 'inked'|'pending'`, `size`, `impressionId?` (plays the full impression once per ID), `static?`, `viewTransitionName?` (hook for the later sheet grow). Ring text per A5 on a `<textPath>`; the SVG is `aria-hidden` (name and status live in card text, per spec acceptance).
- Impression (B1): the wrapper carries the `_impression.svg` mask with the per-country transform, so frame and engraving wear together; a full-density duplicate layer is crossfaded in for press (`--dur-press`) and for the new impression (faint → full over `--dur-moment`); reduced motion = static worn stamp; pending = no ink, no texture.
- Engraving: a `<span>` with `mask-image: url(/stamps/{iso2}.svg)` and `background-color: var(--stamp-ink-{ink})`; fallback tier shows ISO3 inside the window.
- Motion (Q34, timings from DESIGN tokens and `stamp-proto/index.html`): deterministic rest tilt from ISO2; fine-pointer hover straightens after 60ms over `--dur-base` `--ease-out`, leave `--dur-fast`; `:focus-visible` straightens instantly; press scale .97 + denser ink over `--dur-press` (touch too); new impression `--dur-moment` once per ID (reuse the one-shot memory approach of `signature/stamp.tsx`, exporting its helpers rather than copying them if needed); pending = dashed outline, no ink, engraving hidden; reduced motion = no tilt/scale, opacity only.
- Contact sheet `/dev/stamps`: every recipe rendered live from the engine (no build step), grouped by tier/cluster; 96px and card size; theme toggle light/dark; RU/EN toggle; state strip per country (rest, hover-pose, focus, pressed, pending, impression replay button); worst-case ring names (longest RU/EN names in the catalog) shown on every shape; lint result badge per country; impression on/off toggle (B1 kill test); owner marks per country (B2): accept / redo + note, saved by a dev-only route handler to `apps/next/src/lib/stamp-art/review.json` (production `notFound()`), with a filter for unmarked and redo.
  Dependencies: W1 frame/inks/render API.
  Focused proof: ink contrast (≥4.5:1 vs surface, both themes) → unit test over the palette; ring fit → unit test on the longest RU/EN catalog names per shape; behaviour → `pnpm --filter @kuuki/next test`, typecheck, lint; visual → agent-browser on `/dev/stamps` (light/dark, 96px, reduced motion emulated) with downscaled screenshots, then an Opus high design review of the sheet against the spec and DESIGN.md.
  Accept when: review findings resolved or reported; **stop and show the owner the contact sheet of the six (screenshots + how to open it), with impression on/off side by side. W3 starts only after the owner signs off and decides B1.**

## W3: Full kit and all 246 recipes

Objective: every catalog country has an engraved recipe or a deliberate fallback, inside the rules.
Owned writes: `apps/next/src/lib/stamp-art/**` and `apps/next/public/stamps/**` (transferred from W1 after W2 accepted).
Implementation:

- Finish the base kit (~46 modules from SUMMARY.md plus `amphitheatre`, `stepped-pyramid`, `stilts`, `waterfall`; lighthouse and volcano variants as params, not new modules), with any style changes the owner asked for in the sign-off.
- Recipes in sequential batches (one Sonnet worker at a time, ~30 countries each, by registry region), high-confidence rows first, then medium, then low. Each worker reads the registry row, checks the silhouette against current sources, applies REVIEW.md collision notes (Maya proportions, volcano profiles, atoll signatures, lighthouse bands) and the cluster rule (shared base + signature part, ≤8 per cluster, distinct inks within a cluster).
- Fallback tier when no readable recipe passes the check; list each fallback with its reason.
- Rule audit per batch: no active religious buildings/statues, seats of power, copyrighted modern landmarks, flags, regime/military, food, people; contested territories (EH, PS, XK, IO, FK, YT) neutral nature only.
  Dependencies: W2 accepted, owner sign-off.
  Focused proof: `pnpm check:stamps` green after each batch; primary reviews each batch on the contact sheet (filtered by batch); the owner marks it (B2) and `redo` notes go into the next worker's prompt.
  Accept when: 246 recipes, check green, fallback list and cluster/ink table recorded in the handoff.
