# Экран импорта: линия досмотра

Goal: пустой экран `/import` заменяет растянутую кнопку изометрической фигурой линии досмотра, каждое движение которой показывает настоящее состояние источника; экран говорит правду о приватности и показывает вход для истории Flighty.
Approach: чистая функция переводит состояния `UnifiedSession` в положения лотков; фигура собирается ядром `Scene` и двигает именованные группы CSS-переменными (как карусель багажа); список файлов с текстовыми статусами остаётся единственным носителем фактов.
Success: при любом наборе источников положение каждого лотка выводится из фазы его источника; монитор светится только пока хотя бы один источник в фазе `online`; без движения (reduced motion) экран сообщает то же самое.
Out of scope: приём файлов на других страницах Kuuki, единое поле ввода вместо кнопок, строка «последний перелёт в журнале», изменения сервера, `UnifiedSession` и `HistorySession`, онбординг (`ImportClient`), плавающая карточка фонового импорта, деплой.
Planning basis: решения владельца от 11.11.2026 в треде Flighty CSV (выбор линии досмотра, четыре UX-решения ниже).
Status: ход работ и проверки в [handoff](2026-11-11-import-security-lane-handoff.md).
Authority: план разрешает локальные коммиты в своей ветке. Push, посадка в `main`, PR и деплой требуют отдельного согласия владельца.

## Принятые решения

1. **Срок жизни.** Пока источников нет, фигура крупная (бокс 560×216, на ≤700px 328×168). С первым принятым источником она один раз становится полосой (бокс 560×120, на ≤700px 328×96) и до конца импорта высоту не меняет. Смена размера происходит только в ответ на действие человека, никогда на событие сервера.
2. **Два предмета по поведению.** Документ (любой PDF, фото, текст) едет в туннель. Бортжурнал Flighty лежит на столе ручного досмотра. Формат файла предмет не меняет.
3. **Монитор без текста.** Единственная светящаяся часть фигуры (`lit`) — экран монитора оператора с силуэтом. Маршруты и счётчики только в HTML-списке.
4. **Шутки.** Одна в тексте (файл больше 10 МБ), одна в движении (неподдерживаемый тип упирается в шторки). Других нет.

## Обязательные ограничения

- `DESIGN.md`, раздел Illustration: одна светящаяся часть; фигура `aria-hidden` и не принимает указатель; не несёт сведений, которых нет в тексте; штрихи 1px, CSS фигуру не масштабирует (размер запекается через `fitBox`).
- `DESIGN.md`, раздел Motion: только `transform` и `opacity`; без ease-in; без `transition: all`; содержимое первого рендера не анимируется; `--dur-moment` (450ms) и `--ease-out` для переездов лотка.
- Правило «фигуры не зациклены и не анимируются при загрузке» сохраняется по смыслу: в покое ничего не движется. Ролики крутятся только пока файл над страницей или пока лоток переезжает. Это исключение записывается в `DESIGN.md` в Task 6.
- Перед работой с движением прочитать `~/.claude/docs/motion-durations.md`.
- Нет линий-разделителей между строками и цветных полос с одной стороны (`apps/next/src/app/side-stripes.test.ts`).
- Каждая строка есть в EN и RU, в объекте `C` файла `unified-import.tsx` или в `history-copy.ts`; без подписей-пояснений сверх перечисленных здесь.
- Содержимое файлов и текста не попадает в логи и хранилище браузера; фигура получает только фазы и счётчики.
- Команды запускать из корня рабочей копии. Playwright один раз в конце. Скриншоты разрешены только в Task 2 для самопроверки рисунка, уменьшенные `sips -Z 1200`; оценку ощущения делает владелец.
- Коммиты без упоминаний ИИ.

## Соответствие состояний

Источник истины: `SessionEntry.phase` и `problem` (`apps/next/src/client/import/unified-session.ts:29-47`).

| Состояние                                            | Место лотка (`slot`)                                  | Содержимое                          |
| ---------------------------------------------------- | ----------------------------------------------------- | ----------------------------------- |
| Источников нет                                       | один пустой лоток в `mouth`                           | пусто                               |
| Файл над страницей                                   | то же, шторки подняты, ролики крутятся                | пусто                               |
| `queued`                                             | `queue` с номером 0..2; четвёртый и далее не рисуются | документ                            |
| `local`                                              | `frame` (рамка штрихкода перед туннелем)              | документ                            |
| `online`                                             | `tunnel`, лоток скрыт клипом; монитор светится        | документ                            |
| `ready`                                              | `exit`; предыдущие готовые уходят в `stack`           | корешки, `min(число черновиков, 4)` |
| `empty`                                              | `exit`                                                | тот же документ                     |
| `failed` + `read`/`recognition`/`partial`/`reselect` | `side` (боковая линия)                                | документ                            |
| `failed` + `size`                                    | `mouth`, лоток отодвинут назад                        | документ и бутылка рядом            |
| `failed` + `type`                                    | `mouth`, одно движение «упёрся и вернулся»            | документ                            |
| Всё сохранено                                        | все лотки в `stack`                                   | пусто                               |
| История Flighty читается или отправляется            | `table` (стол ручного досмотра)                       | бортжурнал                          |

В каждом месте кроме `queue` и `stack` рисуется не больше одного лотка: самый поздний источник в этом состоянии. Список файлов показывает все.

### Task 1: Модель линии

- [x] Готово

Файлы: новый `apps/next/src/client/import/lane/lane-model.ts` и `lane-model.test.ts`.

Интерфейс:

```ts
export type LaneSlot = 'mouth' | 'queue' | 'frame' | 'tunnel' | 'exit' | 'side' | 'stack' | 'table'
export type LaneCargo = 'none' | 'document' | 'stubs' | 'logbook'
export interface LaneTray {
  id: string // id источника; 'idle' для пустого лотка
  slot: LaneSlot
  index: number // место в queue или stack, иначе 0
  cargo: LaneCargo
  stubs: number // 0..4
  rejected: 'size' | 'type' | null
}
export interface LaneModel {
  trays: LaneTray[]
  monitor: boolean
  rollers: boolean
  flaps: boolean
  size: 'hero' | 'band'
}
export interface LaneInput {
  entries: readonly {
    id: string
    phase: SessionEntry['phase']
    problem?: SessionEntry['problem']
    drafts: number
  }[]
  dragging: boolean
  history: 'idle' | 'reading' | 'done'
  saved: boolean
}
export function laneModel(input: LaneInput): LaneModel
```

Правила: таблица выше; `monitor` равен «есть источник в `online`»; `flaps` равен `dragging`; `rollers` равен `dragging`; `size` равен `'hero'`, только когда `entries` пуст и `history === 'idle'`. Функция чистая и детерминированная.

Тесты (по одному на правило): пустой ввод; очередь из пяти даёт три лотка в `queue`; `online` включает монитор, `local` нет; два `ready` дают один `exit` и один `stack`; `size` и `type` дают `rejected`; `partial` идёт в `side`; `saved` складывает всё в `stack`; `history: 'reading'` даёт лоток `table` с `logbook` и размер `band`.

Проверка: `pnpm --filter @kuuki/next exec vitest run src/client/import/lane/lane-model.test.ts`.

### Task 2: Рисунок линии

- [x] Готово

Файлы: новый `apps/next/src/client/import/lane/lane-figure.ts` (построитель), `lane-figure.test.ts`. Использует `Scene`, `fitBox` (`apps/next/src/client/overview/iso/scene.ts`), `solids.ts` и детали из `apps/next/src/client/profile/ladders/figures/parts.ts`. Образец движущейся части: `apps/next/src/client/overview/iso/carousel.ts` и `carousel.css`.

Интерфейс: `export function buildLane(box: { w: number; h: number }, model: LaneModel): IsoFigureData`.

Состав сцены слева направо: стопка возврата лотков, роликовый стол с очередью, рамка штрихкода, туннель рентгена со шторками и монитором оператора на стойке, выходной роликовый стол, боковая линия от туннеля к зрителю, стол ручного досмотра за линией. Уровень проработки как у фигур достижений: мелкие точные детали, четыре тона граней. Перед рисованием загрузить навык `anatomy-asset`.

Требования:

- Каждый лоток это `group('tray:<id>', …, { vars })`. Геометрия лотка рисуется в начале координат линии, а место задаётся переменными `--tray-x`, `--tray-y` из `s.vector(...)`. Так элемент переживает перестроение и CSS-переход работает.
- Порядок отрисовки фиксирован: дальние части, лотки до туннеля, корпус туннеля, лотки после туннеля, шторки последними. Лоток в `tunnel` скрыт клипом корпуса (приём карусели). `s.include(...)` покрывает весь путь лотков, чтобы `viewBox` не менялся между состояниями.
- Ровно одна группа `lit`: экран монитора. При `monitor: false` экран рисуется краской `iso-ghost` без свечения.
- Текста в фигуре нет.
- Роликов нет в общих деталях: построить локальную функцию в этом файле, не выносить в `parts.ts`.

Тесты: `viewBox` одинаков для всех состояний одного бокса; не больше одной группы `lit`, и она есть только при `monitor: true`; нет узлов `text`; одинаковый ввод даёт одинаковый результат; набор `data-part` лотков совпадает с `model.trays`.

Самопроверка рисунка: временная страница или скрипт рендерит состояния из таблицы в PNG; после проверки временный код удалить.

Проверка: `pnpm --filter @kuuki/next exec vitest run src/client/import/lane`.

### Task 3: Компонент и движение

- [x] Готово

Файлы: новый `apps/next/src/client/import/lane/security-lane.tsx`, `security-lane.css`, `security-lane.test.tsx`.

Интерфейс: `export function SecurityLane(props: { model: LaneModel }): JSX.Element`. Рендерит `IsoFigure` (`apps/next/src/client/overview/iso/iso-figure.tsx`) в контейнере `div.security-lane[data-size]`, `aria-hidden`, `pointer-events: none`.

Поведение:

- Бокс берётся из `model.size` и `useMobile()` (`apps/next/src/client/ui/use-mobile.ts`); пока `useMobile()` возвращает `null`, используется настольный бокс.
- Переезд лотка: `transition: transform var(--dur-moment) var(--ease-out)` на группе лотка. Первый рендер без перехода. Прерванный переезд продолжается из текущего положения (свойство CSS-перехода, отдельный код не нужен).
- Смена `hero` → `band`: высота контейнера меняется за `--dur-base`, фигура перестраивается сразу в новом боксе без масштабирования.
- Шторки поднимаются на `flaps`, ролики вращаются на `rollers` и пока идёт переход лотка (класс снимается по `transitionend`). В покое анимаций нет.
- `rejected: 'type'`: одна анимация 450ms «вперёд до шторок и назад», запускается один раз на появление источника.
- Скрытая вкладка и фигура вне экрана: вращение роликов ставится на паузу. Взять тройку `IntersectionObserver` + `visibilitychange` + `matchMedia` из `apps/next/src/client/loading/windsock.tsx`.
- Reduced motion: переходов и вращения нет, лотки сразу на местах, монитор горит ровно.

Тесты: `aria-hidden` и отсутствие фокусируемых элементов; `data-size` следует модели; при reduced motion контейнер несёт признак, отключающий переходы.

Проверка: `pnpm --filter @kuuki/next exec vitest run src/client/import/lane`.
