# WebMCP: отдельная работа после спеки путешествий

Область согласована 13 октября 2026. Это предварительный план, реализация
не начата и сейчас не поручена. Полная декомпозиция задач появится после
проверки фактических возможностей браузера и существующих операций приложения.

## Цель и границы

Дать собственному агенту владельца инструменты открытой страницы Kuuki для
чтения и изменения журнала, паспорта, настроек, приватности и экспорта.
Выполняются поручения по сообщениям. WebMCP не обещает работу при закрытой
странице. Удалённый MCP, OAuth для внешних агентов, плагины и периодическая
автономная работа отложены. Совместимость Hermes и Dots через удалённый MCP
не является приёмкой этого этапа.

Требования к правам и поведению — в
[спеке агентского доступа](../../.scratch/personal-agents/spec.md).
Поезда и роуд-трипы подключаются к инструментам после появления реальных
операций, а не через заглушки. Их выпуск имеет
[самостоятельную спеку](../../.scratch/ground-travel/spec.md).

## Последовательность реализации

1. **Сверить актуальный API и выбрать проверяемый клиент.** Исследование на
   13 октября указывает на `document.modelContext`; перепроверить редакцию
   и фактическую поддержку браузера перед кодом. Выбрать один клиент для
   полного пользовательского прогона; не переносить вывод на непроверенных.
2. **Составить перечень реальных действий.** Сопоставить чтение, поиск,
   создание, редактирование, импорт, подтверждение, удаление, статистику,
   настройки, приватность и экспорт с действующими UI/API. Выделять общую
   логику только там, где нужна: одинаковые права владельца и валидация.
   Смену пароля и удаление аккаунта завершает человек в Kuuki.
3. **Подключить браузерный реестр.** Только авторизованная страница, feature
   detection, без ущерба обычному UI при отсутствии WebMCP. Регистрация
   привязана к документу и аккаунту; очистка при выходе, смене владельца
   и завершении жизненного цикла. Аннотации не заменяют авторизацию;
   аргумент ownerId не является источником прав.
4. **Закрыть контракты изменения.** Явное поручение владельца может разрешить
   сохранение и подтверждение поездки/стран; вывод агента этого не делает.
   Изменения видны человеку, его страница и позиция сохраняются без команды
   на переход. Конкурирующее изменение возвращает конфликт с актуальными
   данными. Повтор запроса не создаёт дубликаты, частичный успех сохраняется.
   При остановке новые операции не стартуют; уже отправленные запросы
   сверяются, отмена браузерного вызова не считается откатом серверной записи.
5. **Проверить и документировать.** API/реестр: авторизация, очистка аккаунта,
   конфликт, повтор, частичный успех, неизвестный результат и остановка.
   Один полный клиентский сценарий: чтение → изменение → видимый результат
   → подтверждение → экспорт, плюс работа UI без WebMCP. Использовать
   существующие seams и проверки репозитория; добавить тесты только для
   отсутствующих наблюдаемых гарантий. Обновить документацию реальных
   возможностей и проверенных браузеров/клиентов.

## Открытые решения до выполнения

- Конкретный браузер/клиент и доступная ему редакция API.
- Имена, схемы и результаты инструментов на основе инвентаризации действий.
- Доступные гарантии версий, безопасного повтора и проверки неизвестного
  результата в текущих API; какие изменения общих операций необходимы.
- Как передавать требование подтверждения владельцем без подмены его
  свободным утверждением агента; как отдать экспорт выбранному клиенту.
