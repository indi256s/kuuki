# Mobile dock Implementation Plan

Goal: the phone rail returns to Overview · Journal · Passport · [+]; Journal and Ground travel become one Journal section with a Flights · Ground switch; one grouped Add list serves the mobile + card and the desktop "Add" menu.
Architecture: navigation-only merge. `/journal` and `/ground-travel` keep their routes, read models, URL codecs and return contexts. The shared pieces are a section-switch component rendered by both list pages, a single `AddActions` list, and a transition rule that makes Journal ↔ Ground an instant swap. No shared Next layout, no data merge.
Success: every acceptance check in `.scratch/mobile-dock/spec.md` ("Acceptance checks") holds in the built app at 320×568 and 390×844 (EN and RU) and on desktop; `pnpm typecheck`, `pnpm lint`, `pnpm --filter @kuuki/next test`, `pnpm next:build` and the full `pnpm test:next:navigation` pass.
Out of scope: a merged flights + journeys chronology; Leaderboard in the rail or a Passport rank tile; account-menu changes; route renames or redirects; deploys, pushes, PRs and remote D1 writes.
Constraints: follow `AGENTS.md`, `CODING_STANDARDS.md`, `DESIGN.md` and `docs/agents/shared-checkout.md`. No divider lines inside the Add card (space groups the two pairs). Reuse `Menu`/`MenuGroup`/`MenuItem` (`client/ui/menu.tsx`), `ChipGroup`/`FacetChip` (`client/ui/chip-group.tsx`), Keyline icons and existing tokens; the `kuuki/design-tokens` lint rule applies. Reuse ground copy keys in `ground/copy.ts`. Read `~/.claude/docs/motion-durations.md` before touching the + rotation. Run builds and Playwright serially in the checkout; Playwright once at feature end, not per wave. One subagent at a time; Sonnet for well-specified mechanical subtasks; no per-wave reviews. Commits are local on the task branch only; landing on `main` follows the shared-checkout procedure and needs the owner's go-ahead.
Planning basis: spec `.scratch/mobile-dock/spec.md` (owner-approved 2026-10-15, questions Q1–Q4 resolved). Repository evidence: `client/nav.tsx` (`TABS`, `TabBar`, `PrimaryNav`, `MobilePageTitle`, `isActive`); the removed + key and Add card in `git show 8441ef07:apps/next/src/client/nav.tsx` (and its `shell.css` at that commit); `client/add-actions.tsx`, `client/add-menu.tsx`, `client/queue-summary.tsx`; `client/journal/header.tsx:73` (`journal-add-mobile`) and `header.css:103`; `client/ground/ground-page.tsx` (`SegmentedControl` in `FilterToolbar`, `AddChooser`, `EmptyGround action`), `ground/add-chooser.tsx`, `ground/url.ts` (`withReturn`), `ground/form/return-context.ts`; `client/route-transition-pairs.ts` (`TAB_ROUTES`, `isTabSwitch`, `useTransitionKey` keeps the key for unapproved pairs, so the swap is instant); `client/route-focus.tsx` (heading focus on pathname change); `client/journal/toolbar.tsx:518` (chip pattern); `apps/next/tests/navigation.test.ts:48,206,225`; `scripts/smoke-next-runtime.ts:193` (visits `/ground-travel`, no tab assertions). Assumption: `sessionStorage` is read after mount only, so SSR and first client render link to `/journal`.
Execution profile: primary=claude-opus-5-5; workers=runtime-selected (prefer Sonnet 5.5 for mechanical subtasks); reviewers=codex gpt-6.1-sol reasoningEffort=high, once at feature end via T3 delegate_task (omit runtimeMode; read-only limits in the prompt); exact-profile-attestation=required for primary only
Authority evidence: owner, 2026-10-15, in the planning thread: "Пиши спеку", then answers to Q1–Q4, then `/writing-wave-plans` with "как закончишь запускай новый тред с opus на имплементацию". Implementation on a task branch is authorized; landing on `main`, push and deploy are not.

## W1: Rail and one Add list

Objective: the phone rail shows Overview · Journal · Passport and the + key; every member screen can open the Add card; desktop shows one "Add" / «Добавить» menu with the same rows.
Owned writes: see execution map, W1 row.
Implementation:

- `TABS` drops the Ground entry and its `name` override. `NAV_ITEMS` drops `/ground-travel`. Add a helper, e.g. `isJournalSection(pathname)`, true for `/journal` and `/ground-travel` subtrees; the Journal tab and the desktop Journal link use it for `aria-current`. `MobilePageTitle` shows "Journal" / «Журнал» on `/ground-travel`.
- Restore the + key from `8441ef07` (`tab-add-slot`, `Menu` side top, align end, rail-width card 8px above the rail, `scrim`, `tab-add-icon` rotation 45°, accessible name "Add" / «Добавить», "Close" / «Закрыть» while open, keyboard-open closes the card). Port its CSS from `shell.css` at that commit; check widths at 320px with three tabs.
- `AddActions` renders two `MenuGroup`s separated by space (no `MenuSeparator`): flights (`/import` "Flights from files" / «Перелёты из файлов», `/add` "Flight by hand" / «Перелёт вручную»), ground (`/ground-travel/new?mode=rail` train, `?mode=road` road trip; icons `Train`, `Car` as in `add-chooser.tsx`), then `QueueMenuItem` last. Ground rows use `withReturn(path, parseGroundUrl(location.search))` when the current pathname is `/ground-travel`, otherwise the bare path. Keep `data-add-action` ids, adding `rail` and `road`.
- `AddMenu` trigger label becomes "Add" / «Добавить».
  Dependencies: existing `Menu`, `QueueMenuItem`, `ground/url.ts`.
  Focused proof: `pnpm --filter @kuuki/next exec vitest run nav add-menu` (vitest file filter) passes with updated tests asserting three tabs, Journal `aria-current` on `/ground-travel?mode=road`, row order/hrefs, return param on `/ground-travel`, Escape returns focus to the key.
  Accept when: unit tests pass, `pnpm typecheck` and `pnpm lint` pass, primary has read the W1 diff.

## W2: Journal section

Objective: both list pages read as one Journal with a Flights · Ground switch that swaps instantly, remembers the last section per browser tab, and the ground filter uses chips.
Owned writes: see execution map, W2 row; `client/nav.tsx` transfers from W1.
Implementation:

- `JournalSections` (client): `<nav aria-label="Journal sections" / «Разделы журнала»>` with two `NavigationLink`s (`/journal`, `/ground-travel`), `aria-current="page"` on the current one, segmented visual from existing tokens, ≥ 44px tall under `pointer: coarse`. On mount it writes `sessionStorage['kuuki:journal-section'] = 'flights' | 'ground'` (guard storage errors).
- Both pages: visible `h1` "Journal" / «Журнал» with a visually hidden " · Flights" / " · Перелёты" or " · Ground" / " · По земле" (existing `.sr-only` utility, `app/styles.css:977`); `JournalSections` directly under it, always shown (also with zero ground journeys). Forms do not render it.
- Journal header: remove `journal-add-mobile` markup and CSS and the now-unused `AddMenu` import.
- Ground page: remove the header `AddChooser`; `EmptyGround` still receives an action offering train and road (keep `AddChooser` for that, or reduce it to two links; executor's choice, one implementation). Replace the All/Rail/Road `SegmentedControl` with a single-select `ChipGroup` of Rail and Road `FacetChip`s; no chip = all; `?mode=` and `GroundTotals` unchanged.
- `route-transition-pairs.ts`: `isTabSwitch` returns false when both ends are in {`/journal`, `/ground-travel`}; both stay in `TAB_ROUTES`. Update `route-transition-pairs.test.ts` (`['/journal', '/ground-travel', true]` → false; Overview ↔ either stays true).
- `nav.tsx`: the Journal tab and desktop Journal link read the stored section after mount (`useEffect` → state) and link to `/ground-travel` when it is `ground`; SSR/first render link to `/journal`.
- `ground-travel/page.tsx` metadata: "Journal · Ground" / «Журнал · По земле».
- `ground.css` has a foreign uncommitted hunk in the root checkout (`.flight-full-sheet .ui-panel-footer .gt-list-actions`); it is not in the worktree's base. Keep edits to this file minimal and separate so the landing patch merges around it.
  Dependencies: W1 accepted.
  Focused proof: `pnpm --filter @kuuki/next exec vitest run route-transition-pairs header ground-page nav` passes: pair is not a tab switch; both pages render the switch with correct `aria-current` and hidden section text; chip toggles write and read `?mode=`; empty ground state shows train/road actions; first render of the Journal tab links `/journal`, and after a stored `ground` it links `/ground-travel`.
  Accept when: those tests, `pnpm typecheck` and `pnpm lint` pass and primary has read the W2 diff.
