# Flighty CSV: состояние реализации

10 ноября 2026 года. Worktree `feat/flighty-csv-import`, база `08fb0705`. Задачи 1–10
[плана](2026-11-10-flighty-csv-import.md) реализованы; решение — [ADR 0008](../adr/0008-flighty-history-import.md).

## Что сделано

- **Разбор.** `packages/shared/src/flighty.ts` и `flighty-time.ts`: детерминированный CSV без AI, все записи и
  ячейки сохраняются, неизвестные колонки сохраняются и показываются владельцу. Локальное время аэропорта
  переводится в UTC по историческому IANA-поясу; fold и gap становятся вопросами. Профиль
  `flighty-observed-33/v1` описывает наблюдаемые файлы, а не опубликованную спецификацию Flighty.
- **Хранение.** Миграция `0020_history_import.sql`: `history_import_runs`, `history_import_rows`,
  `flights.utc_explicit`. Миграция аддитивна. Committed-строка — одновременно квитанция и tombstone.
- **Сервер.** `functions/api/_services/historyImport*.ts`, маршруты `functions/api/import/history/**`. Приём
  чанками с проверкой digest, поиск повторов, групповые и построчные ответы, подтверждение через общую
  цепочку `flightCreate`, удаление и истечение.
- **Клиент.** `apps/next/src/client/import/history-*.ts(x)`; CSV из выбора файла, drag-and-drop и вставки
  уходит в history import. В браузере хранятся только id run, operation id и digest манифеста.

## Независимое ревью

GPT-6.1 Sol high, два прохода. Первый нашёл 9 проблем (2×P1, 7×P2): кратность повторов, обход
duplicate guard у `new_since_import`, зависший seal, лимит 100 чанков, потерянный ответ создания run,
удалённая цель link, нет построчных ответов, нет исключения готовой записи, не показаны неизвестные
колонки. Все исправлены с регрессионными тестами. Повторная проверка подтвердила 9/9 и нашла 2 новых P2
(tombstone link-квитанции терялся при поиске; Save мог обогнать Skip) — исправлены, тесты падают без фикса.

## /simplify

Применено: общие `isRecord`/`canonicalTimeZone`, один `runStatusStatement`, единый список открытых
состояний, `sealRun` на Map вместо квадратичных поисков, `stored_bytes` инкрементом, группы только для
review-страниц, заголовки парсятся один раз на запрос, мёртвый код удалён, таблицы копирайта вместо
вложенных тернарников, `HistorySession.forOwner`.

Пропущено сознательно: trigger на `DELETE flights` (меняет явный дизайн ADR, три пути удаления покрыты
тестами); стратегия guard в `flightCreate` (выходит за diff, задевает конверсию черновиков); облегчённый
listing только id для Save; мемоизация смещений пояса; слияние `batch`/`history` в URL.

## Ограничения

- Свежего оригинального экспорта владельца нет: совместимость заявлена только для наблюдаемого профиля
  на синтетических fixtures; редкие случаи проверены синтетически и не названы проверенными на Flighty.
- Визуальная проверка UI не выполнялась (не запрошена).
- Просмотр источника на карточке отдельного рейса не сделан; владелец получает данные через JSON-архив.
